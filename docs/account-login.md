# 로그인과 내 여행 운영 문서

최종 수정: 2026-08-24

## 사용자에게 제공하는 것

- 항공권 목록과 상세 보기는 계속 로그인 없이 사용할 수 있다.
- 찜은 로그인한 사용자만 새로 저장할 수 있고 여러 기기에서 이어 볼 수 있다.
- 로그인 전 찜을 허용하던 이전 버전에서 브라우저에 남은 찜은 첫 로그인 때 한 번 계정으로 옮겨 데이터가 사라지지 않게 한다.
- 로그인 뒤 연 항공권 상세는 최근 본 표로 최대 30건까지 남는다.
- 찜한 뒤 가격이 바뀌면 현재 가격과 저장 당시 대비 오른 금액·내린 금액을 보여준다.
- 현재 검색어, 출발지, 도착 지역, 날짜, 여행사, 항공사, 정렬 조건에 이름을 붙여 최대 10개까지 저장할 수 있다.
- 현재 목록에서 내려간 찜·최근 본 항공권은 저장 당시 정보만 보여주고 예약 상세를 열지 않는다.
- 사용자는 내 여행 화면에서 저장 검색을 지우거나 계정과 개인 저장 데이터를 모두 삭제할 수 있다.
- 내 여행에서 찜을 바로 해제하고 최근 본 표 기록을 한 번에 비울 수 있다.

## 로그인 방식

비밀번호를 받지 않는 이메일 일회용 인증번호 방식이다.

1. `/api/auth/request-code`가 6자리 번호를 만들고 Gmail로 전송한다.
2. 데이터베이스에는 번호 원문 대신 HMAC-SHA256 변환값만 저장한다.
3. 번호는 10분 동안 유효하고 5회 틀리면 새 번호를 받아야 한다.
4. 이메일 기준 15분 3회·하루 10회, 접속 주소 변환값 기준 15분 10회로 발급을 제한한다.
5. 인증에 성공하면 256비트 임의 세션 토큰을 만들고, 데이터베이스에는 토큰 원문 대신 변환값만 저장한다.
6. 브라우저에는 `HttpOnly`, `Secure`, `SameSite=Lax`, `Path=/` 속성을 가진 `__Host-tikitikit_session` 쿠키만 둔다.
7. 로그인은 30일 유지된다. 사용자가 로그아웃하면 현재 세션을 즉시 삭제한다.
8. 한 계정에는 최근 5개 기기의 로그인만 유지해 오래된 세션이 계속 늘어나지 않게 한다.

`AUTH_SECRET`은 Vercel의 Production·Preview 환경에 Sensitive 값으로 설정돼 있다. 코드나 `.env*`에 넣지 않는다. 비상 폴백은 서버에만 있는 `SUPABASE_SERVICE_ROLE_KEY`지만, 운영에서는 별도 `AUTH_SECRET`이 우선 사용된다.

## 데이터베이스

마이그레이션: `supabase/migrations/20260824_create_tikitikit_accounts.sql`

| 표 | 내용 | 기본 보유 기준 |
|---|---|---|
| `tikitikit_users` | 이메일 계정 | 계정 삭제 시까지 |
| `tikitikit_auth_codes` | 인증번호·요청 주소의 변환값 | 10분 유효, 만료 24시간 뒤 자동 정리 |
| `tikitikit_auth_sessions` | 세션 토큰의 변환값 | 30일 만료, 만료 기록 자동 정리 |
| `tikitikit_user_favorites` | 찜과 저장 당시 항공권 정보 | 직접 해제 또는 계정 삭제 시까지 |
| `tikitikit_user_recent_flights` | 최근 본 항공권 | 사용자당 최근 30건 |
| `tikitikit_user_saved_searches` | 저장 검색 조건 | 사용자당 최대 10건 |

모든 표는 RLS를 켰고 `anon`, `authenticated` 역할의 모든 권한을 회수했다. 브라우저가 Supabase를 직접 호출하지 않으며 Vercel 서버가 세션을 확인한 뒤 service role로 필요한 행만 읽고 쓴다. 만료 기록은 API 요청 때와 매일 03:15 KST에 한 번씩 정리한다. 마이그레이션은 2026-08-24 운영 Supabase에 적용했다.

## API

- `POST /api/auth/request-code`: 인증번호 발급과 메일 전송
- `POST /api/auth/verify-code`: 인증번호 확인과 세션 쿠키 발급
- `POST /api/auth/logout`: 현재 세션 삭제와 쿠키 제거
- `GET /api/account`: 로그인 상태와 찜·최근 본 표·저장 검색 조회
- `POST /api/account`: 찜 합치기/변경, 최근 본 표 기록, 검색 저장/삭제, 계정 삭제

상태를 바꾸는 모든 요청은 같은 출처에서 온 요청인지 확인한다. 이메일, 인증번호, 세션 토큰은 서버 로그와 GA4 이벤트에 넣지 않는다.

## 통계에서 볼 항목

GA4 어드민의 행동 목록에서 다음 이벤트를 확인할 수 있다.

- `account_open`: 내 여행 화면 열기
- `login_code_requested`: 인증번호 요청 성공
- `account_login`: 로그인 성공
- `saved_search_create`: 검색 조건 저장 성공
- `saved_search_apply`: 저장 검색 다시 적용
- `account_logout`: 로그아웃
- `account_delete`: 계정 삭제 확인

초기 판단은 `내 여행 열기 → 인증번호 요청 → 로그인 완료` 이탈과 `로그인 완료 사용자 중 검색 저장·다시 보기`를 본다. 이메일 주소 같은 개인 식별값은 보내지 않는다.

어드민의 **사용자 현황 — 계정과 가격 알림**에서는 이메일을 표시하지 않고 전체 계정, 최근 7일 새 계정, 만료되지 않은 로그인 세션, 계정에 저장된 찜·최근 본 표·검색 조건 수를 볼 수 있다.

## 배포 뒤 점검

1. 비로그인 상태에서 메인 화면과 항공권 상세가 그대로 열리고, 찜을 누르면 로그인 화면이 열리는지 확인한다.
2. 로그인 버튼에서 이메일을 넣고 10분 안에 인증번호가 오는지 확인한다.
3. 이전 버전에서 브라우저에 남은 찜이 있다면 로그인 후 내 여행의 찜과 한 번 합쳐지는지 확인한다.
4. 다른 기기에서 같은 이메일로 로그인해 찜이 보이는지 확인한다.
5. 항공권 상세을 연 뒤 최근 본 표에 표시되는지 확인한다.
6. 필터를 바꾸고 검색 조건을 저장한 뒤 다시 적용되는지 확인한다.
7. 로그아웃 후 개인 목록이 API에서 노출되지 않는지 확인한다.
8. 테스트 계정은 내 여행의 계정 삭제로 정리한다.
