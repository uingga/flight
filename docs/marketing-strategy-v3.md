# 티키티킷 마케팅 전략 — Version 3

> 2026-08-24 전면 재작성.
> 이 문서는 채널별 홍보 계획이 아니라, 항공권의 발견·변화·종료가 스스로 콘텐츠가 되어 사람을 데려오고 다시 돌아오게 만드는 구조를 설계한다.
> 브랜드의 정의와 표현 원칙은 [브랜드 가이드 Version 3](branding-guide-v3.md)를 따른다.

---

## 1. 전략의 결론

티키티킷은 광고비로 대형 항공권 서비스와 싸우지 않는다. 검색 기능의 수, 페이백, 인플루언서 물량, SEO 문서 개수로도 경쟁하지 않는다.

티키티킷이 차지할 자리는 다음과 같다.

> **이상할 만큼 싸진 항공권이 나타나는 순간을 발견하고, 왜 눈여겨볼 만한지 한눈에 보여주는 곳.**

사용자가 티키티킷을 떠올리는 상황도 바뀌어야 한다.

```text
“항공권이 필요하니 검색해야지”
                ↓
“오늘은 뭐가 떨어졌지?”
```

목표는 항공권 검색 수요의 일부를 빼앗는 것이 아니다. **아직 여행 계획이 없는 순간에도 열어보는 새로운 습관을 만드는 것**이다.

---

## 2. 우리가 만드는 성장 장치

기존 마케팅은 서비스를 만든 뒤 홍보할 소재를 찾는다.

```text
서비스
  → 오늘 올릴 콘텐츠 고민
  → 별도 이미지와 글 제작
  → 발행 후 소멸
```

티키티킷은 항공권 데이터 자체가 콘텐츠를 발생시키게 한다.

```text
항공권 발견
  → 변화 확인
  → DROP 생성
  → 사이트의 사건 카드
  → 공유 카드
  → 커뮤니티·SNS 속보
  → 블로그 맥락 글
  → 종료 기록
  → 지난 DROP 아카이브
  → 월간·연간 데이터 콘텐츠
```

항공권 하나가 한 번의 게시물로 끝나지 않는다. 살아 있는 동안 변화를 만들고, 사라진 뒤 기록이 되고, 기록이 쌓이면 분석이 된다.

이 구조가 티키티킷의 마케팅 엔진이다.

---

## 3. 마케팅이 아니라 제품으로 퍼진다

티키티킷의 가장 중요한 마케팅 채널은 광고 계정이 아니라 제품 화면이다.

사람들이 캡처하고 보내고 다시 들어올 장면을 제품 안에서 먼저 만든다.

### 장면 1. 가격 붕괴

```text
오늘 가격이 크게 떨어졌어요
인천 → 오사카
171,000원 → 129,000원
오늘 42,000원 하락
```

단순 최저가가 아니라 변화의 크기를 보여준다.

### 장면 2. 오늘의 DROP

```text
DROP #042
부산 → 후쿠오카
왕복 79,000원
오전 10시 20분 처음 확인
```

하루에 1개가 없을 수도 있다. 발행량을 채우기 위해 평범한 표를 DROP으로 만들지 않는다.

### 장면 3. 끝난 뒤의 기록

```text
DROP #042 종료
최저 관측가 79,000원
처음 확인 10:20
마지막 확인 16:10
```

종료된 항공권을 지우지 않고 티키티킷이 실제로 발견했다는 증거로 남긴다.

### 장면 4. 여행 가능성의 번역

```text
0연차 탈출 가능
금요일 20:40 출발
일요일 22:10 도착
왕복 89,000원
```

가격만으로는 공유되지 않는 표에 “우리 둘이 실제로 갈 수 있다”는 이유를 붙인다. 실제 항공 시간이 조건을 충족할 때만 사용한다.

### 장면 5. 예산으로 여는 발견

```text
10만원이면 오늘 어디까지?
후쿠오카 79,000원
칭다오 84,000원
오사카 99,000원
```

목적지 검색을 예산 놀이로 바꾼다.

## 4. DROP을 선정하는 법

DROP은 운영자가 마음에 드는 표가 아니라, 설명 가능한 사건이어야 한다.

### 지금부터 사용할 수 있는 근거

- 같은 항공권의 직전 관측가보다 얼마나 내려갔는가
- 오늘 또는 최근 수집에서 처음 나타났는가
- 좌석 수가 실제로 변했는가
- 출발일까지 얼마나 남았는가
- 날짜와 시간이 실제 여행에 쓸 만한가
- 수수료를 포함하거나 고지했을 때도 가격이 매력적인가

### 기록이 쌓인 뒤 사용할 근거

- 같은 노선·비슷한 시기의 관측 가격 중 어느 위치인가
- 최근 30일·60일의 같은 조건과 비교해 얼마나 낮은가
- 티키티킷 관측 역사상 몇 번째로 낮은가
- 비슷한 가격대의 표가 얼마나 오래 남았는가
- 좌석이 특정 수 이하가 된 뒤 얼마나 빨리 사라졌는가

### DROP에서 제외할 것

- 수집 실패로 가격이나 항공권 수가 급변한 회차
- 예약 페이지에서 같은 항공권을 찾기 어려운 표
- 숨은 수수료를 반영하면 매력이 사라지는 표
- 비교 조건이 다른 항공권을 섞어 만든 과장된 할인율
- 가격은 싸지만 사용하기 어려운 일정을 숨겨야만 매력적으로 보이는 표
- 제휴 수익 때문에 선택된 표

### 자동화와 사람의 역할

시스템은 후보를 찾고 숫자를 정리한다. 사람은 공개할 만한 사건인지 확인한다.

초기에는 자동 게시하지 않는다. 잘못된 DROP 하나가 평범한 글 열 개보다 신뢰를 더 크게 해친다.

## 5. 한 DROP이 여러 콘텐츠가 되는 구조

예를 들어 오사카 항공권이 171,000원에서 129,000원으로 내려갔다고 하자.

### 사이트

> 오늘 가격이 크게 떨어졌어요<br>
> 오사카 · 171,000원 → 129,000원

### 공유 카드

> 오사카 왕복 129,000원<br>
> 오늘 42,000원 내려감<br>
> “이거 같이 갈래?”

### 커뮤니티·SNS

> 오늘 확인한 오사카 왕복이 17만1천원에서 12만9천원으로 내려왔네요. 날짜는 9월 19~22일이고, 귀국편은 오후 6시입니다.

서비스 설명보다 가격과 일정이 먼저 보이게 한다.

### 네이버 블로그

가격만 반복하지 않는다. 이 표가 실제로 쓸 만한 일정인지, 수수료와 항공 시간이 어떤지, 어떤 사람에게 맞는지를 검토한다.

### 종료 후

> 이 DROP은 여기까지였어요.<br>
> 최저 관측가 129,000원 · 약 2일간 확인

### 데이터가 쌓인 뒤

> 올해 10만원대 오사카 왕복은 몇 번 나타났을까?

한 사건을 채널별로 복사해 붙이는 것이 아니다. 같은 사실을 각 채널의 사용 이유에 맞게 다시 표현한다.

## 6. 대표 제품·콘텐츠 체계

### A. 오늘의 DROP

지금 살아 있는 사건이다.

- 하루 0~3개
- 실제 변화나 희소성을 한 문장으로 설명
- 현재 항공권 상세와 바로 연결
- 가격과 좌석이 바뀌면 같은 DROP 안에서 갱신

### B. 지난 DROP

끝난 사건의 기록이다.

- 최저 관측가
- 처음·마지막 확인 시점
- 가격과 좌석의 주요 변화
- 현재 비슷한 표

### C. 전설의 DROP

오랜 기록 속에서도 드문 사례다.

- 충분한 관측 기간과 표본이 생긴 뒤 시작
- 운영자의 감탄이 아니라 실제 순위와 희소성으로 선정
- 매년 `DROP AWARDS`의 근거가 됨

### D. 가격 붕괴 카드

캡처와 공유를 위해 만들어지는 단일 화면이다.

- 이전 가격과 현재 가격
- 차액과 변화율
- 노선·날짜·출발지
- 처음 확인한 시각
- 티키티킷 로고는 정보 뒤에 작게

### E. CATCH CARD

실제 구매자가 자신의 득템을 공유하는 카드다.

- 구매 인증 방식이 생긴 뒤에만 도입
- 예약 클릭을 구매로 간주하지 않음
- 브랜드 홍보보다 사용자의 전리품이 주인공

### F. 항공권 시장

노선별 가격 변화를 하나의 판으로 보여주는 장기 기능이다.

```text
오늘 일본 표는 전반적으로 내려갔어요
후쿠오카 ▼
오사카 ▼
도쿄 ─
삿포로 ▲
```

여행 시기와 조건이 다른 가격을 무작정 평균 내지 않는다. 충분한 표본과 비교 모델이 생기기 전에는 만들지 않는다.

### G. 기다릴까, 살까

장기적으로 가장 강한 판단 기능 후보다.

- 같은 노선과 비슷한 조건의 과거 생애를 비교
- 가격, 잔여좌석, 출발 D-day를 함께 사용
- 근거가 부족한 노선에는 판단을 제공하지 않음
- 확률을 확신처럼 말하지 않음

## 7. 인사이트바의 새 역할

인사이트바는 목록 사이를 꾸미는 배너가 아니다. **지금 데이터에서 벌어진 사건을 발견하게 하는 편집 카드**다.

### 우선 사용하는 세 가지

1. **가격이 크게 내려간 표**
   - `오사카 · 171,000원 → 129,000원`
2. **오늘 처음 나타난 가격**
   - `마츠야마 왕복 109,000원 · 오후 2시 17분 처음 확인`
3. **일정이 특별한 표**
   - `금요일 퇴근 후 출발 · 연차 없이 후쿠오카`

### 데이터가 쌓인 뒤 추가할 것

- 최근 60일 중 가장 낮은 가격
- 같은 노선의 역대 순위
- 종료됐다 다시 나타난 표
- 좌석이 빠르게 줄어든 표
- 지난 DROP의 결과

### 표현 규칙

- `오늘의 변화`처럼 범주만 말하지 않는다.
- 제목에 사건을, 다음 줄에 노선과 숫자를 쓴다.
- 한 카드에 여러 주장과 버튼을 넣지 않는다.
- 모든 인사이트를 같은 색과 크기로 만들지 않는다. 중요한 사건만 강하게 보인다.
- 사용자가 항공권 카드를 보던 흐름을 끊지 않게 한다.

## 8. 유입 전략: 돈보다 사건을 배포한다

티키티킷은 사이트 자체를 설명하는 홍보글보다 실제 DROP을 배포한다.

### 1순위. 공유와 메신저

가장 자연스러운 문장은 광고 문구가 아니다.

> “야, 우리 이거 가능함?”

- 항공권 상세 공유에 가격 변화와 일정을 포함
- 공유받은 사람은 같은 항공권을 바로 봄
- 항공권이 끝났다면 지난 기록과 현재 대안을 봄
- 공유 링크 유입과 이후 예약 클릭을 측정

### 2순위. 여행·특가 커뮤니티

- 서비스 소개글을 반복하지 않음
- 정말 이상한 가격이나 일정이 나왔을 때 한 건씩 공유
- 커뮤니티의 언어로 사실을 먼저 설명
- 가입 유도보다 항공권 상세 확인을 우선
- 실제 문구와 결과는 [커뮤니티 홍보 실험 기록](community-marketing-experiments.md)에 남김

개발자 커뮤니티나 창업 서비스 소개 게시판은 초기 핵심 채널로 삼지 않는다. 서비스 구조를 자세히 노출하는 데 비해 실제 여행 수요가 약하고 복제 위험이 크다.

### 3순위. DROP 속보 계정

여행 팁과 밈을 억지로 섞지 않는다. 계정의 사용 이유는 하나다.

> **이상한 가격이 나타났을 때 알려주는 계정.**

- Threads 또는 한 개의 짧은 채널부터 시작
- 같은 형식으로 매일 채우지 않음
- DROP이 없으면 올리지 않음
- 사이트 데이터에서 이미지와 문구 초안을 자동 생성
- 댓글 운영이 감당되지 않으면 새 채널을 늘리지 않음

### 4순위. 네이버 블로그

블로그는 단순 속보보다 검색 가능한 맥락을 맡는다.

- 지금 나온 DROP의 일정과 조건 분석
- `10만원으로 갈 수 있는 실제 항공권`
- `0연차로 가능한 표`
- 지방공항에서 나타난 드문 가격
- 새로운 목적지와 항공권을 연결한 글

날짜와 가격만 바꾼 대량 글은 만들지 않는다.

### 5순위. 자체 `/tips`

시간이 쌓일수록 강해지는 데이터 콘텐츠다.

- 후쿠오카 항공권은 얼마면 눈여겨볼 만한가
- 출발 며칠 전에 가격이 가장 많이 움직였는가
- 올해 10만원 이하 도쿄 항공권은 몇 번 나타났는가
- 2026년 가장 큰 가격 하락 TOP 20
- 좌석이 줄어든 뒤 판매 종료까지 얼마나 걸렸는가

관측 기간과 표본을 제목이나 본문에 명확히 밝힌다.

### 6순위. 알림

알림은 유입 채널이자 재방문 제품이다.

- 조건형 알림보다 사건형 문장으로 보냄
- 동일한 가격과 노선을 반복하지 않음
- 사용자가 정한 출발지·지역·예산을 존중
- 예약이 어려운 표와 불확실한 가격은 제외

## 9. 공개할 것과 숨길 것

티키티킷은 발견한 결과를 널리 보여주되, 복제하기 쉬운 운영 설계까지 홍보하지 않는다.

### 공개할 것

- 노선, 가격, 날짜, 시간
- 가격이 어떻게 변했는지
- 티키티킷이 언제 처음과 마지막으로 확인했는지
- 지나간 DROP의 기록
- 충분한 표본에서 나온 집계 결과

### 공개하지 않을 것

- 여행사별 수집 방식과 취약 지점
- 크롤링 횟수와 세부 자동화 구조
- 내부 필터와 후보 점수의 전체 계산식
- 외부 비교 서비스의 수집 결과 원본
- 관리자용 오류·복구 정보

브랜드의 해자는 비밀스러운 크롤러 하나가 아니라 오랫동안 축적한 생애 기록이지만, 그렇다고 운영 설명서를 마케팅 콘텐츠로 만들 이유는 없다.

---

## 10. 사용자가 참여하는 방식

초기에는 빈 커뮤니티를 먼저 만들지 않는다. 사용자가 이미 하고 싶은 행동을 가볍게 기록하는 것부터 시작한다.

### 지금 가능한 참여

- 가격이 달라요
- 예약이 안 돼요
- 친구에게 공유
- 원하는 조건의 DROP 알림

### 다음 단계

- “이 가격이면 간다 / 더 기다린다” 투표
- 더 싼 가격 제보
- 실제 구매 인증
- 잡은 DROP을 개인 기록에 저장

### 나중에 가능한 문화

- 잡은 도시가 쌓이는 여권
- 과거 DROP 수집 기록
- 구매 인증 기반 CATCH CARD
- 연말 DROP AWARDS
- 사용자가 붙인 별명과 이야기

포인트, 등급, 헌터 호칭은 행동이 생긴 뒤 붙인다. 사람이 없는 곳에 게임 규칙부터 세우지 않는다.

---

## 11. 가장 중요한 지표

### 중심 지표: 주간 DROP 행동 사용자

한 주 동안 DROP 또는 항공권을 본 뒤 다음 행동 가운데 하나 이상을 한 순사용자 수다.

- 상세 열람
- 여행사 예약 페이지 이동
- 공유
- 가격·예약 문제 신고
- 개별 또는 조건형 알림 등록
- 지난 DROP 열람 후 현재 항공권으로 이동

단순 방문자 수만으로 성공을 판단하지 않는다.

### 반드시 함께 볼 지표

| 질문 | 지표 |
|---|---|
| 사건이 눈에 띄었나? | 인사이트·DROP 노출 대비 상세 열람률 |
| 친구에게 보여줄 만했나? | 공유율, 공유 링크 신규 유입 |
| 실제 구매 관심이 있었나? | 상세 대비 여행사 예약 클릭률 |
| 다시 올 이유가 생겼나? | 7일·30일 재방문률, 직접 유입 |
| 다음 사건을 기다리나? | 알림 등록률과 실제 알림 클릭률 |
| 신뢰할 수 있었나? | 가격 차이·예약 불가 신고율 |
| 콘텐츠가 사람을 데려왔나? | 게시물별 유입 후 상세·예약 행동 |

### 숫자를 해석하는 원칙

- 조회수가 높아도 상세와 예약 클릭이 없으면 구경거리였을 뿐이다.
- 공유 수가 적어도 공유받은 사람이 예약 페이지까지 이동하면 강한 콘텐츠다.
- 방문자는 늘었지만 신고가 급증하면 성공이 아니다.
- 트래픽이 적을 때 작은 비율 차이를 승리로 단정하지 않는다.
- A/B 테스트는 충분한 표본이 생긴 뒤 사용한다. 초기에는 서로 다른 강한 시안을 순차적으로 내고 실제 행동과 반응을 함께 본다.

---

## 12. 실행 단계

### 단계 1. 직접 확인한 변화만 말한다 — 지금부터 2주

- 가격·좌석·사라짐·재등장 기록이 정상적으로 쌓이는지 확인
- 수집 실패 회차가 판매 종료 기록에 섞이지 않는지 확인
- 인사이트바를 사건형 문장으로 전환
- `이전 가격 → 현재 가격`, `처음 확인 시각`을 사용
- DROP 후보를 자동 추출하되 공개 여부는 사람이 확인
- 공유 카드가 현재 항공권 상세로 정확히 연결되는지 확인

이 시기에는 역대 순위, 생존 확률, 시장 평균을 말하지 않는다.

### 단계 2. 사건이 사라져도 남게 한다 — 3~6주

- 지난 DROP 페이지 제작
- 종료·재등장 흐름 표시
- 가격 붕괴 공유 카드 제작
- DROP별 유입과 행동 측정
- 커뮤니티와 한 개의 짧은 채널에서 실제 사건을 소량 배포

### 단계 3. 기록을 비교 가능한 정보로 만든다 — 2~3개월

- 노선·여행 시기·체류 기간별 비교 기준 설계
- 최근 30일·60일 가격 범위 제공
- 같은 노선의 드문 가격 후보 추출
- `10만원이면 어디까지?`, `0연차 탈출` 같은 반복 가능한 제품 화면 검증
- 첫 데이터 기반 `/tips` 글 발행

### 단계 4. 티키티킷만 말할 수 있는 이야기를 만든다 — 3~6개월

- 노선별 역대 순위
- 월간 가격 붕괴 기록
- 올해 10만원 이하 항공권 출현 횟수
- DROP 생존시간의 실제 분포
- 가격과 좌석이 함께 움직인 사례 분석
- 연말 DROP AWARDS

### 단계 5. 판단을 돕는다 — 충분한 표본 이후

- `기다릴까, 살까`
- 좌석 수와 판매 종료 가능성의 관계
- 출발 D-day별 가격 변화
- 노선별 관측 기반 구매 판단

날짜를 채우기 위해 다음 단계로 넘어가지 않는다. 필요한 데이터가 쌓였을 때 넘어간다.

## 13. 운영 리듬

| 주기 | 자동으로 할 일 | 사람이 할 일 |
|---|---|---|
| 크롤링 후 | 가격·좌석 변화 기록, DROP 후보 추출 | 수집 실패와 예약 가능성 확인 |
| 좋은 사건 발생 시 | 사이트 카드·공유 이미지·문구 초안 생성 | DROP 공개와 외부 발행 결정 |
| 종료 확인 시 | 생애 요약과 지난 DROP 초안 생성 | 종료가 실제인지 검수 |
| 주 1회 | 유입·상세·예약·공유 통계 정리 | 다음 주에 밀 한 장면 선택 |
| 월 1회 | 노선·가격·좌석 변화 집계 | 공개할 만한 데이터 이야기 선정 |

콘텐츠 달력을 채우는 것이 목표가 아니다. **사건이 생겼을 때 놓치지 않고 여러 형태로 활용하는 것**이 목표다.

## 14. 지금 하지 않을 것

- 캐치프로그의 페이백·추천인 구조를 그대로 따라 하기
- 서비스명과 로고만 바꾸고 제품은 그대로 두는 리브랜딩
- 모든 항공권에 DROP 번호 붙이기
- 근거 없는 `역대급`, `곧 품절`, `오류 가격` 선언
- 구매 여부를 모른 채 `잡은 사람 수` 표시
- 충분한 기록 없이 가격 지수와 생존 확률 공개
- 매일 같은 형식의 TOP 3 자동 발행
- 여러 SNS 계정을 동시에 운영
- 여행과 관계없는 개발자·창업 커뮤니티에 구조를 자세히 공개
- 방문자를 남겨둘 제품 없이 유료 광고 집행
- 일반 여행 정보를 대량 생산하는 SEO 전략

## 15. 브랜드명 변경과 마케팅

새 이름은 이 전략을 압축해야지 대신해서는 안 된다.

이름 후보를 평가할 때 다음을 함께 만든다.

- 이름과 한 문장 설명
- `오늘의 DROP`이 들어간 첫 화면
- 공유 카드 한 장
- 종료된 DROP 기록 화면
- “야, ○○에 이 표 떴어”라는 실제 대화

세 가지 이상 서로 다른 브랜드 세계를 시안으로 비교한 뒤 도메인·상표·SNS 사용 가능성을 확인한다.

이름을 바꾸기로 하면 다음을 한 번에 준비한다.

- 기존 도메인의 장기 리디렉션
- 검색 노출과 분석 도구의 연속성
- 기존 알림 구독과 공유 링크 유지
- 여행사 제휴 링크와 이메일 발신자 변경
- “이름만 바뀐 것이 아니라 무엇이 달라지는가”를 보여주는 첫 DROP

리브랜딩 발표의 주인공도 로고가 아니라 새 제품 경험이어야 한다.

## 16. 매주 던질 질문

1. 이번 주 가장 이상했던 가격은 무엇이었나?
2. 그 가격이 정말 이상하다는 근거를 보여줄 수 있었나?
3. 어떤 장면을 사람들이 가장 많이 열고 공유했나?
4. 공유받은 사람은 상세와 예약까지 이동했나?
5. 사라진 DROP이 현재 항공권으로 다시 연결됐나?
6. 가격이나 예약 문제 신고가 반복된 여행사는 어디인가?
7. 이번 주 데이터에서만 만들 수 있는 이야기는 무엇인가?
8. 우리가 만든 표현이 사실보다 앞서가지는 않았나?
9. 다음 주에는 어떤 한 장면을 더 강하게 만들 것인가?

## 17. 전략이 제대로 작동하는 신호

- 사용자가 서비스 설명 대신 특정 DROP을 친구에게 보냄
- 검색 없이 직접 들어와 오늘의 변화를 확인함
- 끝난 항공권 페이지도 계속 열림
- `티키티킷에서 봤다`가 가격의 출처처럼 쓰임
- 블로그와 커뮤니티 글이 단순 조회가 아니라 항공권 상세 행동을 만듦
- 시간이 갈수록 과거 기록을 활용한 콘텐츠가 늘어남
- 외부 채널을 늘리지 않아도 같은 DROP이 여러 접점을 만듦

반대로 게시물 수와 방문자만 늘고 공유, 예약 클릭, 재방문, 기록 열람이 늘지 않으면 이 전략은 작동하지 않는 것이다.
