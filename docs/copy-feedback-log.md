# 원고 피드백 로그 — 사용 종료

> **상태: 2026-08-26 운영 종료.** 과거 원고 피드백 기록만 보존한다.
> 새 원고를 쓸 때 이 파일을 기준으로 읽지 않고, 새 피드백도 여기에 추가하지 않는다.
> 현재 작업은 사용자의 최신 지시를 따르고, Threads 문구가 필요할 때만 `docs/threads-copy-candidates.md`를 참고한다.

## 증류된 규칙 (최신)

| 퇴짜 유형 | 예 (실제 퇴짜) | 대신 이렇게 |
|---|---|---|
| 정보 없는 티저 | "세 장을 골랐습니다. 한 장은…" | 첫 문장부터 구체 사실(노선·가격·시각) |
| 근거 없는 일반화 | "아직 아무도 모르는 노선의 좌석은 이렇게 나옵니다" | 검증된 사실만 나열하고 해석은 독자에게 |
| 확인 안 된 단정 | "두 달 뒤에도 이 가격일 리는 없습니다" | 데이터로 확인된 차이만 쓴다 |
| 독자 상황 단정 | "첫 끼는 호치민에서 쌀국수입니다" | 권유체로: "아침은 쌀국수로 시작하세요" |
| 잘난 척 어미 | "다시 나오지 않습니다", "나오는 날이 드롭 날입니다" | 사실 서술로 낮춰 쓰기 |
| 홈쇼핑 필러 | "놓치는 게 싫으면 방법이 하나 있습니다" | 삭제하거나 CTA로 직행 |
| 당연한 말 | "자고 일어나면 사흘의 낮이 통째로 남습니다" | 삭제 |
| 병렬 공식 제목 | "밤 비행기를 타면, 낮이 사흘 남습니다"식 반복 | 꼭지마다 다른 각도의 소제목 |
| 한 문장에 정보 과적ㅊ | "새벽부터 문 여는 국숫집에서 3천 원쯤이고, 에그커피도 여기서 시작됐습니다" | 문장을 쪼개 정보 하나씩 |
| 독자 소외 | "청주 사는 사람만 해당됩니다" 뉘앙스 | 포함 범위를 넓혀 쓰기 (대전·세종…) |
| 자존심 상하는 표현 | "돈이 없어서" | 독자를 깎아내리지 않는 이유로 교체 |
| 딱딱한 정의문 | "하노이는 쌀국수의 원조 도시입니다" | 리듬 있는 사실 선언: "쌀국수도 에그커피도 하노이가 원조입니다" |
| 뜬금없는 배치 | 일정 설명 끝에 갑자기 음식 문단 | 꼭지 안 순서: 왜 이 표 → 도시 → 일정 → 링크 |
| 중복 시각 정보 | 티키티킷 항공권 캡처 바로 아래 같은 내용의 링크 카드 | 캡처 카드는 빼고 클릭 가능한 링크 카드만 사용 |
| 빽빽한 본문 | 문단이 빈 줄 없이 연달아 붙음 | 일반 본문 문단 사이에 빈 줄을 정확히 하나 둔다 |
| 맥락 없이 바로 시작 | 대표 이미지 다음에 첫 항공권 설명이 곧바로 나옴 | 이번 드롭의 흐름을 여는 짧은 도입부 2~3문장 |
| 잘못 붙인 조건 | "평일 사흘을 비울 수 있다면 도착한 날을 거의 온전히…" | 서로 무관한 사실은 조건문으로 묶지 않고 각각 설명 |
| 당연한 접근 설명 | "대구공항으로 바로 갈 수 있다면", "부산·경남에서 공항으로 갈 수 있고" | 출발 공항만 밝히고, 실제 판단에 필요한 시각·연차 조건만 설명 |
| 억지 접속어 | "마지막 날은 짧습니다. 대신 비행시간이 길지 않고…" | `대신·하지만·그래서` 앞뒤에 실제 인과나 대비가 있을 때만 사용 |

**잘 읽힌 것**: 짧은 문장 / 권유체("배를 타세요", "시키세요") / 사실 선언으로 열고 디테일로 잇기 /
실측 숫자(좌석 수·시각) / 중요하지 않은 내용은 제목에서 빼기 / 꼭지 간 구조 반복 피하기.

## 로그

### 2026-08 DROP 02 (호치민→하노이 교체 포함)

- ❌ "세 장을 골랐습니다. 한 장은…" → 매력도, 정보도 없음 → 구체 사실로 시작
- ❌ 소제목 "오전 10시 30분에 내리면, 첫날 점심이 남습니다 / 청주에서 밤 비행기를 타면, 낮이 사흘 남습니다" → AI가 쓴 병렬 공식 느낌, 공감 안 됨
- ❌ "공항이 멀어서", "돈이 없어서" → 사실과 다르고 / 자존심 상함
- ❌ "아직 아무도 모르는 노선의 좌석은 이렇게 나옵니다. 두 달 뒤에도 이 가격일 리는 없습니다." → AI 문장 + 미확인 단정 (실제로 넉 달 뒤도 같은 가격이었음)
- ❌ "하나는 청주 사는 사람만 해당됩니다" → 청주 아닌 독자 소외
- ❌ 귀국편 조건 설명 문단 → 내용이 복잡함 → 단순화
- ❌ "셋 다 아니면 / 그럴 수 있습니다…" → 매력 없음
- ❌ "다음 드롭 날짜는 저희도 모릅니다… 놓치는 게 싫으면 방법이 하나 있습니다" → 홈쇼핑 필러
- ❌ "한정판 스니커에만 드롭이 있는 게 아닙니다" → 재작성 지시
- ❌ "다시 나오지 않습니다" → 재수없어 보임
- ❌ "첫 끼는 호치민에서 쌀국수입니다" → 단언이 별로 → 권유체로
- ❌ "9월 17일 목요일 08:45 출발…" 식 나열 → 잘 안 읽힘
- ❌ "자고 일어나면 금·토·일, 사흘의 낮이 통째로 남습니다" → 당연한 말
- ✅ "고르면 → 골라도" 같은 어미 완화가 좋음
- ❌ "좋은 표는 저희가 정한 요일에 맞춰 나와주지 않습니다. 나오는 날이 드롭 날입니다" → 안 읽히고 재수없음
- ❌ "출발지, 지역, 예산 — 세 가지면 됩니다" → 없어도 됨
- ✅ 모든 항공권에 몇 박 며칠 명시 요구
- ❌ 소제목 "재입고 없음" → 어떤 항공권이 얼마인지 안 보여 후킹 안 됨 → 소제목에 도시·가격
- ❌ "그래서 드롭도 요일을 정해두지 않았습니다" → 굳이
- ✅ "~올립니다" 대신 다른 표현 ("소개할 만한 표가 모이면 그때 드롭합니다")
- ❌ 예상 결제금액 문장 두 개 연달아 → 헷갈림 → 하나로 정리
- ✅ 제목은 단순하게: "호치민, 다카마쓰, 나트랑 — TIKITIKIT DROP 02" 계열
- ❌ (하노이 교체 후) 음식 문단이 일정 뒤에 갑자기 등장 → 뜬금없음 → 도시 얘기는 꼭지 중간으로
- ❌ "하노이는 쌀국수의 원조 도시입니다" → 너무 딱딱함
- ❌ "새벽부터 문 여는 국숫집에서 한 그릇에 우리 돈 3천 원쯤이고, 커피에 달걀노른자를 올린 에그커피도 여기서 시작됐습니다" → 안 읽힘 (정보 과적) → 문장 쪼개기
- ✅ 최종 채택 (권유체가 승리, 섞은 절충안보다 원래 권유체 버전 선호): "아침은 쌀국수로 시작하세요. 원조 동네라 골목 국숫집 어디를 들어가도 기본은 하고, 한 그릇에 우리 돈 3천 원쯤입니다. 커피가 당기면 에그커피를 시키세요. 커피에 달걀노른자를 얹어 마시는, 하노이에서 태어난 메뉴입니다."
- ❌ 티키티킷 항공권 캡처 이미지 + 네이버 링크 카드 연속 배치 → 내용 중복, 세로 길이만 늘어남 → 다음 회차부터 캡처 이미지는 제외하고 링크 카드만 사용
- ✅ 일반 본문 문단 사이에는 엔터 한 번에 해당하는 빈 줄을 둔다. 사후 키보드 입력이 아니라 입력용 HTML에서 먼저 만든다.
- ✅ 세로로 긴 목적지 사진은 원본 비율 그대로 길게 쓰지 않고, 주요 피사체를 확인해 최대 4:5 비율로 크롭한다.
- ✅ 대표 썸네일 다음에는 짧은 도입부를 두고, 각 목적지 사진 다음에는 노선·항공사·날짜·기간·왕복 가격을 3줄로 먼저 요약한다.
- ✅ 내부 작업명은 DROP 02였지만 첫 공개 글이므로 발행 번호는 DROP 01로 확정. 제목은 발행일과 핵심 두 목적지의 가격대를 먼저 보여주고 시리즈명은 뒤에 둔다.

### 2026-08-19 첫 공개 DROP 전면 재선정 원고 (내부 작업명 DROP 02)

- ❌ "평일 사흘을 비울 수 있다면 도착한 날을 거의 온전히 쓸 수 있습니다" → 평일 휴가 여부와 도착 당일 체류시간은 무관함. 평일 출발이라는 부담과 오전 도착이라는 장점을 각각 설명한다.
- ❌ "마지막 날은 짧습니다. 대신 비행시간이 길지 않고…" → 마지막 날의 길이와 비행시간은 서로 대비되는 내용이 아님. 마지막 날이 짧은 이유와 실제로 쓸 수 있는 날짜만 설명한다.
- ❌ "대구공항으로 바로 갈 수 있다면", "부산·경남에서 공항으로 갈 수 있고" → 해당 지역 출발 표라는 사실만으로 충분히 짐작할 수 있는 당연한 설명. 실제로 의미 있는 출발 시각과 퇴근 조건만 남긴다.
- ❌ "이번에는 출발 공항부터 골라보세요" → 대부분 가까운 공항을 이용하므로 특별한 제안이 되지 않음. 세 표를 함께 보여주는 이유가 일정 차이라면 그 차이를 바로 도입부에 쓴다.
- ✅ 접속어는 문장을 부드럽게 보이게 하려고 넣지 않는다. 앞뒤에 실제 인과·대조·보완 관계가 있을 때만 쓴다.
- ❌ "도착한 날부터 시작하는 칭다오, 금·토·일을 보내는 타이베이, 주말을 괌에서 보내는 일정" → 서로 다른 세 항공권이라는 표시 없이 도시와 일정을 이어 써서 하나의 여행처럼 읽힘. 여러 표를 함께 소개할 때는 `세 표에는`, `각각`처럼 대상이 서로 다르다는 점을 분명히 하거나 문장을 나눈다.
- ❌ 귀국 시간을 설명한 뒤 맥주박물관·구도심 이야기로 갑자기 돌아감 → 일정과 목적지 정보의 순서를 고정할 필요는 없지만, 이미 마친 주제로 설명 없이 되돌아가지 않는다. 관련된 내용끼리 묶고 주제가 바뀔 때는 흐름이 자연스러운지 확인한다.
- ✅ 금요일 저녁 출발·월요일 아침 도착 표는 단순히 `주말 여행`이라고만 쓰지 않고, 조기 퇴근과 오전 반차 등 연차를 얼마나 줄일 수 있는지 구체적으로 알려준다.
- ✅ 독자의 흔한 경험을 꺼내는 도입은 딱딱한 사실 선언보다 대화하듯 쓴다: "가격만 보고 표를 골랐다가 막상 출발·귀국 시간을 확인하면 마음이 바뀌는 경우가 있죠."
- ❌ "아침에 도착해 첫날부터 쓰는 칭다오" → 무엇을 `쓴다`는지 모호하고 제목의 힘이 약함. 가격과 도착 후의 느낌을 함께 보여주는 "칭다오 17만원대, 도착해도 아직 아침입니다"로 교체.
- ❌ "대구에서 목요일 밤에 떠나는 타이베이" → 시간표를 문장으로 옮긴 수준. 일정이 주는 이득을 말하는 "주말을 하루 일찍 시작하는 대구발 타이베이"로 교체.
- ❌ "조금 일찍 퇴근할 수 있다면, 부산에서 괌" → 조건과 노선명이 문법적으로 이어지지 않음. 연차 절약이라는 이득을 바로 보여주는 "연차 없이 떠나는 부산발 괌 21만원대"로 교체.
- ✅ 각 목적지 소제목 위에는 일반 문단 사이보다 엔터를 한 번 더 넣는다. 입력용 HTML에서 소제목 직전에 빈 문단을 두 개 두어 꼭지의 시작이 충분히 구분되게 한다.
- ✅ 각 목적지 소제목 아래에는 엔터를 넣지 않고 목적지 이미지를 바로 붙인다. 꼭지의 위쪽 여백은 소제목 위에서만 확보한다.
- ❌ `원하는 특가 알림 받기` → 이동 목적지가 보이지 않아 광고·스팸 링크처럼 느껴짐.
- ✅ 블로그 알림 CTA는 `티키티킷에서 특가 알림 설정하기 →`로 쓰고, 바로 아래에 작은 글씨로 `tikitikit.kr의 알림 설정 화면으로 이동합니다.`를 밝혀 링크의 목적지를 안심시킨다.
- ✅ 마지막 알림 설명은 한 덩어리로 쓰지 않는다. `다음 드롭은 예고 없이 옵니다.` 뒤를 한 번 띄우고, 출발지·지역·예산 / 선별 기준 / 드롭 밖의 표도 알린다는 내용을 문장별로 나눈다.

### 2026-08-19 사이트 UI 문구 (날짜 필터 안내)

- ❌ "고른 날짜는 가는 편이 출발하는 날 기준이에요. 돌아오는 날은 이 기간 밖일 수 있어요." → 무슨 말인지 모르겠음, 두 문장이나 됨
- ✅ 채택: "출발일 기준으로 검색됩니다." → UI 안내 문구는 설명하려 들지 말고 짧은 사실 한 문장 (사용자가 예시를 직접 제시)
- ❌ (사이트) 땡처리 상세 시트의 🔎 안내(특가 목록 설명+찾을 항목+1인 기준, 3문장) → 너무 복잡, 통째로 제거 ("알아서 찾겠지") → 자동 하이라이트 기능만 남기고 설명은 생략
