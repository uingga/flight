## 2. 브랜드 코어: 땡처리 항공권에서 여행 기회를 찾아주는 서비스

### 한 줄 정의

> **티키티킷은 여러 여행사에서 저렴하게 나온 땡처리 항공권을 먼저 보여준다. 추천 순서는 가격을 우선하되 날짜와 시간, 체류 기간, 수수료도 함께 본다.**

대형 항공권 서비스가 `목적지·날짜 결정 → 검색 → 가격 비교`를 돕는다면, 티키티킷은 `저렴한 표 확인 → 갈 곳 발견 → 날짜와 시간 확인 → 예약·공유`의 순서를 만든다. 검색 기능을 많이 넣는 것보다 사용자가 직접 찾지 않은 저렴한 표를 먼저 보여주는 데 집중한다.

### 새 기능의 첫 번째 판단 질문

> **“항공권 검색을 더 편하게 하는가?”보다 “새로운 여행 기회를 더 잘 발견하게 하는가?”를 먼저 묻는다.**

검색 편의 기능이 불필요하다는 뜻은 아니다. 다만 개발 우선순위를 정할 때는 아래 순서로 판단한다.

1. 사용자가 몰랐던 저렴한 표를 보여주는가?
2. 날짜와 시간까지 보고 고를 수 있게 하는가?
3. 마음에 드는 표를 바로 예약하거나 공유할 수 있는가?
4. 지금 맞는 표가 없다면 조건형 알림이 새 표를 대신 찾아주는가?
5. 위 네 가지와 관계가 약할 때만 일반적인 검색 편의성 개선으로 평가한다.

따라서 필터를 하나 더 추가하는 기능보다 `저렴한 땡처리 항공권`, `날짜와 시간이 괜찮은 표`, `생소하지만 조건이 좋은 목적지`, `내 조건에 맞는 새 표 알림`을 더 잘 보여주는 기능을 우선한다.

### 핵심 고객 상황

티키티킷의 핵심 고객은 목적지와 날짜를 이미 확정한 사람보다 다음과 같이 아직 여행을 결정하지 않은 사람이다.

- “9월에 어디 좀 가고 싶은데 아직 정하지 못했다.”
- “20만원이면 일본 어디까지 갈 수 있지?”
- “이번 주말에 갑자기 싸게 나온 곳이 없을까?”
- “부산에서 지금 싸게 갈 수 있는 곳이 어디지?”

정확한 노선을 찾는 사람도 서비스할 수 있지만, 티키티킷만의 강점은 **계획이 없던 사람에게 여행을 결심할 이유를 만들어주는 것**이다.

### 메시지 체계

- **브랜드 정의**: 저렴한 땡처리 항공권을 먼저 보여주는 서비스
- **헤더**: 오늘은 어디가 싸게 나왔을까요?
- **검색·공유 설명**: 여행사마다 따로 올라오는 저렴한 표를 한곳에서 확인하세요.
- **푸터**: 좋은 표 하나가, 없던 여행 계획을 만듭니다.
- **콘텐츠 질문**: 이번 주에 새로 싸게 나온 표 중 날짜와 시간도 괜찮은 것은 무엇인가?
- **내부 판단 원칙**: 저렴한 표를 먼저 보되, 가격만으로 순서를 정하지 않는다.
- **알림 진입**: 지금 떠날 만한 표가 없나요?

위 문구를 한 화면에 모두 나열하지 않는다. 메인·콘텐츠·알림처럼 사용 맥락에 맞는 문구 하나를 골라 반복해, 브랜드 인상을 분산시키지 않는다.

### 브랜드가 지켜야 할 원칙

1. **검색보다 발견을 먼저 설계한다.** 목적지와 날짜를 모두 입력하기 전에 지금 나온 저렴한 표를 보여준다.
2. **저렴한 표를 먼저 보되, 가격만으로 순서를 정하지 않는다.** 가격을 첫 기준으로 삼고 날짜와 시간·체류 기간·경유 여부·정보 확인 시점·수수료도 함께 본다. 점수는 추천 순서를 정하는 데만 쓴다.
3. **선택에 필요한 항공권 조건을 함께 보여준다.** 가격 옆에 날짜, 출·도착 시각, 체류 시간, 출발 공항, 추가 비용을 빠뜨리지 않는다.
4. **생소하다는 이유로 목록에서 빼지 않는다.** 저렴하고 일정이 괜찮다면 보여준다. 판단하기 어려운 곳만 위치와 공항 이동 시간을 짧게 덧붙인다.
5. **검증 가능한 사실만 말한다.** 확인되지 않은 `무조건 최저가`, 과장된 긴급성, 다녀온 것처럼 꾸민 경험담을 쓰지 않는다. 외부 가격 비교는 내부 판단 근거로 활용하되 공개 문구에서 특정 비교 서비스나 크롤링을 언급하지 않는다.
6. **지금 나온 표와 앞으로 나올 표를 함께 다룬다.** 지금 마음에 드는 표는 상세 확인·예약·공유로 이어지게 하고, 지금 맞는 표가 없다면 조건형 알림이 새 표를 대신 찾게 한다.
7. **혼자 운영 가능한 구조를 우선한다.** 항공권 데이터 하나가 사이트·드롭·블로그·공유 카드·알림의 원재료가 되게 하고, 지속적인 수작업 관리가 필요한 채널은 뒤로 미룬다.

### 브랜드 톤

티키티킷은 좋은 점만 늘어놓지 않는다. 가격, 날짜, 시간, 체류 기간, 수수료처럼 항공권을 고르는 데 필요한 사실부터 말한다.

- 구체적으로 쓴다: 노선·가격·날짜·체류 시간과 목적지 고유 정보를 먼저 제시한다.
- 장점과 제약을 함께 쓴다: 싼 이유, 불편한 시간대, 짧은 체류처럼 판단에 필요한 단서도 숨기지 않는다.
- 호기심은 만들되 낚시하지 않는다: 생소한 목적지는 위치와 이동 시간 같은 사실로 설명한다.
- 전형적인 AI 문장을 피한다: `가볼 만할까?`, `완벽 가이드`, `놓치면 후회`, `가격 실화?` 같은 반복 문구를 쓰지 않는다.

## 3. 목표와 퍼널

솔로 운영이므로 목표는 3개만 잡는다 (분기 단위 갱신).

```
인지 (블로그·검색·커뮤니티·공유)
  → 여행 기회 발견 (드롭·카드·공유 링크)
  → 검토 (가격·날짜·시간·체류·수수료 확인)
  → 현재 기회 행동 (예약 클릭·공유)
  → 확산 (공유 링크 → 단톡방/커뮤니티)

지금 맞는 표가 없음
  → 조건형 알림 등록
  → 새로운 여행 기회 도착
  → 다시 발견·검토
```

### 북극성 지표

**주간 예약 클릭 수** (`booking_click`) — 매출 대리 지표이자 발견한 여행 기회가 실제 행동으로 이어졌는지를 보여주는 최종 성과.

브랜드가 제대로 작동하는지 보는 핵심 선행 지표는 **항공권 상세 확인률**이다. 방문자가 단순히 목록을 스쳐 지나가지 않고 “이 여행은 가능하겠다”고 판단하기 위해 상세를 열었는지를 본다.

### 보조 KPI (주간 체크)

| 지표 | 소스 | 이유 |
|------|------|------|
| 신규 방문자 | GA4 | 인지 채널 효과 |
| 항공권 상세 확인률 | GA4 | 여행 기회 발견 품질 |
| 가격·조건형 알림 구독 수 | Supabase / GA4 | 미래의 여행 기회를 다시 열 수 있는 관계 축적 |
| 공유 클릭 수 | GA4 `share` 이벤트 | 확산 루프 작동 여부 |
| 7일·30일 재방문율 | GA4 | “다시 발견하러 오는 서비스”가 되었는지 확인 |
| 네이버 검색 유입 키워드 | 네이버 서치어드바이저 | SEO 방향 보정 |

## 4. 채널 전략: 우선순위와 역할

원칙: **자동화 가능한 것 → 복리가 쌓이는 것 → 일회성 노출** 순으로 투자한다.

각 채널은 따로 운영하지 않고 다음 하나의 브랜드 시스템으로 연결한다.

```
티키티킷 항공권 데이터
  ├─ 지금 생긴 여행 기회 → 티키티킷 드롭 → 사이트·네이버·공유
  └─ 축적된 가격 기록   → /tips 데이터 콘텐츠 → 검색 유입
                                  ↓
                           항공권 상세 확인
                                  ↓
                           예약·공유 또는
                          조건형 알림 등록
                                  ↓
                   새로운 여행 기회 → 다시 발견
```

### Tier 1 — 검색 (네이버 + 구글): 복리 엔진

- **네이버 발견형 특가 시리즈**: 매일 같은 TOP 3를 반복하지 않고 항공권 데이터를 서로 다른 여행 욕구로 재구성한다.
  - 월요일: `20만원으로 갈 수 있는 여행`
  - 화요일: `지방공항에서 출발하는 특가`
  - 수요일: `연차 없이 가능한 일정` 후보가 실제로 있을 때만 발행. 후보가 부족하면 `연차 하루면 가능한 2~4일 짧은 일정`으로 대체하며 억지로 만들지 않는다.
  - 목요일: `처음 보는 목적지` — 생소함을 감점하지 않고, 어디에 있는지·공항에서 시내까지 얼마나 걸리는지·짧은 일정이 가능한지를 설명한다.
  - 금요일: `티키티킷 드롭` — 가격·날짜·시간·희소성을 함께 본 한 주의 대표 항공권 3개.
  - 주말: `다음 주 바로 떠나는 항공권` 또는 `이번 주 새로 등장한 목적지`.
- 제목은 날짜와 TOP 3를 반복하지 않는다. 다만 `가볼 만할까?`, `어떤 곳일까?`, `실제로 갈 만할까?` 같은 질문형 제목도 AI 양산 글과 구별되지 않으므로 사용하지 않는다.
- 제목에는 확인 가능한 항공권 사실과 그 목적지만의 구체적인 단서를 바로 쓴다. 예: `인천→웨이하이 173,630원 | 산둥반도에서 보내는 2박 3일`, `부산→구마모토 191,000원 | 이번 주 낯선 표`, `인천→요나고 160,500원 | 돗토리 서쪽으로 들어가는 항공권`.
- 생소한 목적지 콘텐츠의 시리즈명은 우선 `이번 주 낯선 표`로 사용한다. 시리즈명은 썸네일이나 제목 뒤에 짧게 붙이고, 매번 같은 질문형 문장을 반복하지 않는다.
- 본문은 무조건 추천으로 끝내지 않는다. `이 표가 잘 맞는 사람`과 `추천하기 어려운 사람`을 함께 적고, 개인적으로 다녀온 것처럼 꾸며 쓰지 않는다.
- `총정리`, `완벽 가이드`, `놓치면 후회`, `가격 실화?`, `요즘 뜨는`, `알아보겠습니다`처럼 근거가 약하거나 흔한 AI·홍보 문구는 사용하지 않는다.
- **정보성 콘텐츠**: 과거 캘린더를 기계적으로 소진하지 않고 현재 검색 수요와 티키티킷 데이터가 만나는 주제를 우선한다. 일반 여행 정보만 반복하지 않는다.
- **사이트 자체 SEO**: `/tips`는 네이버 글을 복사하는 공간이 아니다. 축적된 티키티킷 가격 데이터를 활용해 `일본 항공권은 출발 며칠 전에 싸질까?`, `2026년 후쿠오카 항공권 가격 기록`처럼 다른 곳이 쉽게 복제할 수 없는 장기 검색 자산을 만든다.
- 가격 기록이 충분히 쌓이기 전에는 성급한 통계를 만들지 않고 데이터를 계속 축적한다.
- **검색 색인 운영**: 네이버 서치어드바이저와 구글 서치콘솔 등록은 완료된 상태로 보고, 색인 제외 사유·사이트맵·대표 URL 문제를 정기적으로 점검한다.

네이버는 오늘의 여행 기회를 발견시키는 채널이고, `/tips`는 시간이 지나도 검색되는 가격 데이터 자산이다. 같은 글을 복사하지 않고 서로 다른 역할로 사이트에 방문자를 데려온다.

### Tier 2 — 커뮤니티 시딩: 초기 점화

가이드에 없는 영역이지만 초기 트래픽에는 가장 효과적.

- **어디에**: 뽐뿌 항공정보, 네이버 여행 카페, 클리앙 알뜰구매 등 특가 공유 문화가 있는 곳.
- **어떻게**: 서비스 자체를 홍보하기보다 **실제로 소개할 가치가 있는 특가를 발견했을 때만** 판단에 필요한 정보와 공유 링크를 올린다.
- **빈도**: 주 1~2회, 정말 좋은 딜이 있을 때만. 커뮤니티별 홍보 규정 사전 확인 필수 — 강퇴당하면 채널 하나가 영구 소멸.

### Tier 3 — 카카오톡 채널: 사용자가 늘어난 뒤의 리텐션 채널

- 카카오 오픈채팅은 초기에는 운영 부담이 크므로 보류한다. 대화 관리·광고 삭제·분위기 유지가 필요한 커뮤니티보다 자동으로 굴러가는 유입 자산을 먼저 만든다.
- 자체 조건형 알림의 이용자와 발송 성과가 쌓인 뒤 카카오톡 채널을 검토한다.
- 장기적으로는 `인천 출발 · 일본 · 20만원 이하` 같은 조건형 특가를 카카오톡으로 전달하는 채널로 연결한다.

### 보류

- **유료 광고**: 오가닉 퍼널이 검증되기 전에는 집행하지 않는다 (3개월 후 재검토).

## 5. 제품 주도 성장 (사이트 안에서 할 일)

마케팅으로 데려온 방문자를 자산으로 바꾸는 장치. 유입보다 이쪽 개선이 ROI가 높을 수 있다.

1. **조건형 특가 알림을 새로운 발견 방식으로 운영**: `출발지 + 지역 + 예산`만 받고 날짜와 정확한 목적지는 요구하지 않는다. 지금 원하는 표를 놓치지 않게 하는 기능이 아니라, 나중에 사용자가 찾지 않았던 새로운 여행 기회를 티키티킷이 먼저 열어주는 기능이다. 조건에 맞는 모든 항공권이 아니라 가격·일정·희소성이 충분한 기회만 알려준다. 기존 개별 항공권 가격 알림은 이미 원하는 표가 있는 사람을 위해 함께 유지한다.
2. **공유 카드 품질**: 단톡방에 던져진 링크의 OG 미리보기가 가격·노선을 한눈에 보여주는지 확인 — 이게 사실상 광고 소재다.
3. **재방문 이유 만들기**: 가격 히스토리(`price-history.json`) 기반 "어제보다 내린 노선" 같은 데일리 변화 요소.
4. **발견 영역 강화**: 생소한 목적지를 무조건 제외하지 않는다. 일반 특가 목록과 별도로 `처음 보는 여행지`로 소개하고, 위치·이동 난이도·추천 일정·가격 매력을 함께 설명한다.
5. **티키티킷 드롭 통합**: 단순 최저가 TOP 3가 아니라 가격·날짜·시간·희소성을 함께 본 대표 항공권 3개를 고른다. 현재는 금요일 대표 콘텐츠로 검증하고, 운영 부담과 반응을 확인한 뒤 빈도를 늘린다. 같은 선정 결과를 사이트·네이버 블로그·공유 카드가 재사용하도록 한다.
6. **알림을 큐레이션으로 유지**: 예산 이하라는 이유만으로 모두 발송하지 않는다. 최근 같은 지역을 반복했는지, 일정이 실제로 쓸 만한지, 가격이 충분히 눈에 띄는지를 판단해 알림 피로를 막는다.

## 7. 발행·기능 검수 기준

콘텐츠나 기능을 공개하기 전에 아래 질문으로 브랜드 일관성을 확인한다.

- 사용자가 목적지를 정하지 않았어도 새로운 여행 기회를 발견할 수 있는가?
- 단순히 싸다는 말 외에 날짜·일정·희소성 등 갈 만한 이유가 있는가?
- 이 항공권으로 가능한 여행을 구체적으로 상상할 수 있는가?
- 불편한 조건과 추천하기 어려운 사람도 정직하게 설명했는가?
- 전형적인 AI 문구나 검증되지 않은 최저가·긴급성 표현이 없는가?
- 상세 확인, 예약, 공유, 알림 중 다음 행동이 명확한가?
- 같은 데이터와 결과물을 다른 채널에서도 무리 없이 재사용할 수 있는가?
