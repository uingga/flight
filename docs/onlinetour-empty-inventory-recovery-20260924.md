# 온라인투어 빈 목록 복구 — 2026-09-24

## 확인한 상태

- 운영 데이터의 온라인투어 항공권은 0건이고 마지막 정상 갱신은 2026-09-07이다.
- B PC 정규 시도(09-12·09-15·09-21)는 첫 문서 1회와 상품 목록 1회 뒤 `invalid_first_page`로 실패했다. 저장된 증거에는 명시적 접근 제한이 없으며, 응답 본문은 보존되지 않아 빈 목록인지 응답 형식 변경인지 아직 구분되지 않는다.
- 09-23 기존 1회 진단도 문서 1회·상품 목록 1회 뒤 같은 이유로 실패했다. 운영 데이터는 반영하지 않았다.
- 09-24 13:23 회차의 B PC 정규 시도도 `invalid_first_page`, 접근 제한 없음, 브라우저 정리 성공으로 끝났다.
- 정규 작업이 끝난 뒤 승인된 1회 진단에서 문서 1회·상품 목록 1회만 전송했다. 응답은 HTTP 200, 정상 JSONP, `data.list` 1건, `data.count=1`, `data.paging=null`이었다. 외부 광고 문서 1건은 요청 전에 차단됐고 작업 탭 정리도 확인됐다. 첫 진단 프로세스는 모듈 로드 오류로 Chrome 연결 전 종료되어 사이트 요청이 없었으며, 이력 표식을 보존했다. 응답 본문·상품 행·인증 정보는 저장하지 않았다.
- 실제 실패 원인은 상품이 없거나 차단된 것이 아니라 첫 페이지 파서가 `paging.curPage`와 `paging.totalLastPage`를 필수로 요구한 점이다. 후속 페이지 파서에도 같은 조건이 있었다.

## 코드 변경 후보

- 첫 지역의 도시 목록이 없고 문서의 빈 재고가 검증되었으면 뒤의 월과 지역을 계속 확인한다.
- 첫 도시의 페이지가 `totalCount=0`, 빈 목록, 마지막 페이지, 화면의 더보기 없음으로 확인되면 정상 빈 범위로 취급하고 다른 도시·월을 계속 확인한다.
- 전 지역·도시·월에서 실제로 빈 페이지가 모두 검증되었을 때만 운영 전체 0건을 인정한다. 미방문 범위, 누락된 페이지, 형식 오류는 실패로 남긴다.
- 빈 목록 및 불완전한 페이지는 접근 제한 24시간 회로를 열지 않는다. HTTP/API 401·403·429와 명시적 제한 화면은 계속 차단으로 분류한다.
- 사이트가 실제로 보낸 `data.count`만 있는 응답에서는 검증된 `pageSize=20`으로 마지막 페이지 수를 계산한다. `count`가 누락되거나 목록 길이보다 작으면 실패하며, 최종 화면의 페이지·더보기 상태와 계획 범위 완료 검사는 그대로 요구한다. 기존 `paging` 형식도 계속 받는다.
- 수동 첫 페이지·범위 진단도 검증된 빈 결과와 접근 제한을 별도로 기록한다. 기존 요청 상한·재시도 금지·운영 게시 경로는 변경하지 않는다.

## 남은 확인

- 승인된 첫 응답 구조 확인과 두 파서의 범위 제한 수정은 완료했다. 오프라인 회귀와 타입 검사에서 `count`만 있는 상품 1건·빈 목록 0건, 기존 `paging` 응답, 잘못된 형식 거부를 확인했다. 추가 사이트 요청은 하지 않는다.
- 최종 후보는 `docs/DEPLOY.md`의 별도 운영 코드 배포 승인을 받은 뒤 A 저장소와 B 설치본을 함께 적용한다. 다음 정규 회차에서 실제 수집 및 게시를 확인한다.
