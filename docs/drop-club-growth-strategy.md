# DROP·클럽 성장 전략 연구

> 상태: 연구 가설. 공개 표기에는 `오늘의 DROP #037`과 `티키티킷`을 함께 쓰는 방향을 반영하되, 구현·출시·명칭·유료화는 확정하지 않는다.
> 아래에서 참조한 마케팅 전략과 DROP 실행 가이드는 2026-08-26부로 사용 보류됐다. 이 문서 역시 새 DROP의 기준으로 자동 사용하지 않는다.

## 1. 문서 목적

티키티킷의 강점은 여러 여행사의 땡처리 항공권을 모으는 데서 끝나지 않는다. 가격, 일정, 항공 시간, 수수료를 함께 보고 지금 소개할 가치가 있는 표를 골라내는 판단이 반복될수록 그 판단 자체가 브랜드 자산이 될 수 있다.

이 문서는 다음 장기 성장 가능성을 연구한다.

1. `DROP`을 일회성 블로그 콘텐츠가 아니라 반복해서 찾고 공유하는 브랜드·팬덤 자산으로 확장할 수 있는가.
2. 무료 조건형 알림 사용자가 큐레이션과 조기 접근을 반복해서 이용한 뒤 유료 멤버십으로 전환할 이유가 생기는가.
3. 사용자 제보, 수요 집계, 여행사 제휴를 연결해 티키티킷만의 딜 공급 구조를 만들 수 있는가.
4. 항공권에 소비자 마진을 붙이지 않고도 여행 전체 여정에서 지속 가능한 수익을 만들 수 있는가.

현재 실행 기준인 `좋은 표를 보여줌 → 상세 확인 → 예약 클릭·공유·알림 등록 → 재방문` 흐름은 유지한다. 이 문서의 아이디어는 그 흐름을 강화할 때만 다음 단계로 진행한다.

## 2. 공통 원칙

### 2-1. 신뢰가 성장보다 먼저다

- 낮은 가격만으로 좋은 딜이라고 단정하지 않는다. 날짜, 항공 시간, 체류 기간, 수수료, 좌석 생존 가능성을 함께 본다.
- 협찬 여부, 제휴 수익 여부, 특정 판매처의 이해관계가 좋은 딜 판정을 바꾸지 않게 한다.
- 외부 가격 자료는 내부 검증에 사용하되, 사용자에게 특정 비교처나 수집 방식을 직접 드러내는 홍보 소재로 쓰지 않는다.
- 검증되지 않은 희소성, 최저가, 긴급성을 만들지 않는다.

### 2-2. 기능보다 반복 행동을 먼저 검증한다

클럽, 랭킹, 역공동구매, 유료 멤버십을 먼저 만들지 않는다. 현재 있는 상세 확인, 예약 클릭, 공유, 조건형 알림의 반복 사용이 확인된 뒤 가장 작은 실험부터 진행한다.

### 2-3. 한 사람이 운영할 수 있어야 한다

새 아이디어는 운영 채널과 수작업을 계속 늘리는 방식이 아니라, 같은 항공권 데이터와 검수 과정을 사이트, DROP, 공유, 알림에 다시 쓰는 방식이어야 한다. 주간 운영 시간을 측정하고 감당할 수 없는 실험은 중단한다.

## 3. DROP을 브랜드·팬덤 자산으로 확장하는 가설

### 3-1. 가설

`DROP`을 단순히 항공권 세 건을 묶은 콘텐츠 이름으로 쓰는 데서 나아가, 티키티킷이 직접 고른 한정적이고 신뢰할 만한 딜이라는 표식으로 발전시킬 수 있다.

사용자가 `이번 글을 읽었다`보다 `오늘 몇 번째 DROP이 나왔는지 확인했다`, `이 DROP을 친구에게 보냈다`, `다음 DROP을 기다린다`고 느끼면 DROP은 다음 자산을 만든다.

- 반복 방문을 만드는 시리즈 기억
- 공유할 때 통하는 짧은 고유명
- 과거 딜과 현재 딜을 잇는 기록
- 어떤 가격대·일정·목적지가 반응을 얻었는지 쌓이는 편집 데이터
- 장기적으로 공동·독점 딜을 제안할 때 보여줄 수 있는 브랜드 실적

### 3-2. 일련번호형 포맷 방향

향후 공개 표기는 `오늘의 DROP #037`처럼 짧은 이름과 일련번호를 결합하고, 앞이나 뒤에 발행 주체인 `티키티킷`을 함께 넣는 방향으로 간다. 현재 우선안은 `오늘의 DROP #037 | 티키티킷`이다. 번호는 사용자가 시리즈의 축적을 직관적으로 느끼고 특정 딜을 다시 언급하기 쉽게 한다.

시리즈명과 브랜드명의 앞뒤 순서는 제목·썸네일·공유 카드에서의 가독성을 본 뒤 확정한다. `오늘의 DROP #037`이라는 일련번호형 구조와 `티키티킷`을 함께 표기한다는 원칙은 유지한다.

다만 현재 번호 체계와의 충돌을 먼저 해결해야 한다.

- 현재 DROP 실행 가이드는 실제 발행한 공개 글만 회차로 세며, 첫 공개 회차를 `DROP 01`로 기록한다.
- 현재 `current-drop.json`에는 `issue: 2`, `campaign: tikitikit_drop_002`가 있어 내부 작업·데이터 번호와 공개 회차가 이미 다르게 쓰인 사례가 있다.
- `오늘의 DROP #037`이 개별 항공권 번호인지, 세 항공권을 묶은 편집 회차인지, 발행일별 번호인지 정해져 있지 않다.
- 만료된 딜의 번호를 보존할지, 교체된 딜과 폐기된 초안이 번호를 소비할지도 정해져 있지 않다.

따라서 기존 번호를 소급 변경하거나 새 번호를 바로 노출하지 않는다. 먼저 아래 운영 대안을 비교한다.

| 운영 대안 | 번호의 단위 | 장점 | 위험 |
|---|---|---|---|
| 편집 회차 번호 | 한 번에 공개하는 DROP 묶음 | 현재 블로그 운영과 가깝다 | 묶음 안의 개별 딜을 지칭하기 어렵다 |
| 개별 딜 번호 | 선정된 항공권 한 건 | 공유·기록·랭킹과 연결하기 쉽다 | 현재 회차 번호와 혼동될 수 있다 |
| 날짜+순번 | 발행일 안의 딜 | 운영과 추적이 명확하다 | 브랜드 축적감이 약할 수 있다 |
| 공개 번호와 내부 ID 분리 | `오늘의 DROP #037`과 데이터 식별자를 별도 운영 | 사용자 경험과 내부 운영을 분리할 수 있다 | 체계가 복잡해질 수 있다 |

결정 전에는 `공개 회차`, `내부 작업 번호`, `캠페인 ID`, `개별 딜 ID`를 구분해 기록하고, 어느 하나를 새 표준으로 확정하지 않는다.

### 3-3. 검증할 행동

- DROP 유입자의 항공권 상세 확인률과 예약 클릭률
- 개별 DROP 공유율과 공유 링크를 통한 신규 방문
- 같은 사용자의 7일·30일 내 재방문
- DROP을 본 뒤 조건형 알림을 등록한 비율
- 목적지, 가격대, 일정 유형별 반응 차이
- 발행 한 회차를 만드는 데 드는 운영 시간

단순 조회수나 번호가 커지는 것만으로 팬덤이 생겼다고 판단하지 않는다.

## 4. 티키티킷 클럽 가설

`티키티킷 클럽`은 구현이 확정된 제품이나 유료 멤버십 이름이 아니다. 무료 조건형 알림 사용자가 반복 사용자가 되는 과정을 설명하기 위한 연구 가설이다.

### 4-1. 단계 가설

```text
무료 조건형 알림 집단
    ↓
좋은 딜만 골라 보내는 큐레이션 경험
    ↓
새 DROP 조기 접근 또는 우선 알림 실험
    ↓
알림 클릭·재방문·예약 클릭의 반복 검증
    ↓
반복 가치가 충분할 때만 유료 멤버십 가능성 연구
```

#### 1단계: 무료 조건형 알림 집단

- 출발지, 지역 또는 아무데나, 예산을 기준으로 신청을 받는다.
- 조건 이하의 모든 항공권을 보내지 않고, 내부 검증을 통과한 표만 보낸다.
- 신청자 수보다 실제 발송률, 클릭률, 재방문, 해지·차단을 먼저 본다.
- 이 단계의 사용자를 임의로 `회원`이나 `클럽 멤버`라고 부르지 않는다.

#### 2단계: 큐레이션과 조기 접근

- 반응이 좋은 조건과 DROP을 바탕으로 소수에게 선별 큐레이션을 제공하는 실험을 할 수 있다.
- `조기 접근`은 실제로 예약 가능성을 높일 만큼 시간 차이가 있고 운영상 공정할 때만 검토한다.
- 무료 사용자의 기본 접근을 고의로 늦춰 유료 가치를 만드는 방식은 피한다.

#### 3단계: 반복 사용 검증

유료화 논의 전에 다음이 반복되는지 본다.

- 같은 사용자가 여러 차례 알림을 열고 사이트로 돌아오는가.
- 알림을 받은 사용자의 상세 확인과 예약 클릭이 일반 방문자보다 높은가.
- 큐레이션이 단순 가격 알림과 구별되는 가치를 주는가.
- 발송 빈도가 늘어도 해지·차단과 신뢰 저하가 커지지 않는가.
- 운영자가 품질을 유지하면서 감당할 수 있는가.

#### 4단계: 유료 멤버십 가능성 연구

유료화는 반복 가치가 증명된 뒤 별도 연구한다. 가격, 혜택, 무료·유료 경계, 환불, 접근 공정성, 유료 회원 수용 규모는 모두 미결정이다.

## 5. Deal Hunter 사용자 참여 가설

`Deal Hunter`는 사용자가 발견한 특가를 제보하고, 검증에 기여한 사람의 활동을 닉네임과 기록으로 보여주는 아이디어다. 명칭과 공개 방식은 확정하지 않는다.

### 5-1. 기대 효과

- 티키티킷이 아직 수집하지 못한 판매처·노선·기간의 특가 발견
- 사용자에게 단순 소비자가 아닌 발견자라는 정체성 제공
- 좋은 딜의 기준을 커뮤니티와 함께 학습
- 반복 제보와 검증 참여를 통한 팬덤 형성

### 5-2. 최소 실험

처음부터 공개 게시판이나 자동 랭킹을 만들지 않는다. 제한된 제보 폼과 수동 검수로 다음을 확인한다.

- 링크, 가격, 출발지·목적지, 날짜, 발견 시각
- 수수료를 포함한 실결제가와 실제 예약 가능 여부
- 기존 데이터와 중복인지, 티키티킷의 좋은 딜 기준을 통과하는지
- 제보자가 닉네임 공개와 기록 축적을 원하는지

### 5-3. 닉네임·랭킹 연구 원칙

- 제보 수가 아니라 검증을 통과하고 사용자 행동을 만든 제보를 중요하게 본다.
- 랭킹 때문에 허위·중복·과장 제보가 늘지 않도록 한다.
- 예약 클릭이나 매출만으로 순위를 정해 협찬·제휴 딜이 유리해지지 않게 한다.
- 개인정보, 명예훼손, 판매처와의 분쟁, 제보 삭제 요청에 대한 운영 규칙이 먼저 필요하다.
- 금전, 포인트, 배지, 조기 접근 등 보상 방식은 모두 미결정이다.

## 6. `15만원이면 간다` 역공동구매 가설

일반적인 공동구매가 먼저 공급을 확보한 뒤 구매자를 모은다면, 이 모델은 사용자의 구체적인 수요를 먼저 모아 여행사에 제시한다.

```text
사용자: 출발지·목적지/지역·희망 시기·상한 가격 제시
    ↓
티키티킷: 중복 수요 집계와 실제 구매 의향 확인
    ↓
여행사: 좌석·가격·조건 제안
    ↓
티키티킷: 일반 딜과 같은 기준으로 검증
    ↓
공동 또는 독점 DROP 공개
```

예시는 `15만원이면 간다`이지만, 가격만 받으면 실제 구매 의향을 과대평가할 수 있다. 출발 공항, 가능 날짜 범위, 체류 기간, 인원, 결제 의향 확인 시점이 함께 필요하다.

### 6-1. 장기적 가치

- 검색과 크롤링만으로 얻기 어려운 사용자 수요 데이터 축적
- 여행사에 막연한 트래픽이 아니라 구체적인 대기 수요 제시
- 공동 DROP 또는 티키티킷 전용 DROP 협상 가능성
- 사용자가 원하는 가격과 실제 공급 가능한 가격 사이의 학습

### 6-2. 선행 조건

- 조건형 알림에서 유효한 수요가 반복해서 모여야 한다.
- 단순 관심 표현과 실제 결제 의향을 구분할 방법이 있어야 한다.
- 여행사와 재고, 판매 책임, 취소·환불, 가격 변경, 개인정보 전달 범위를 합의해야 한다.
- 목표 가격을 달성하지 못했을 때의 안내와 데이터 보관 기준이 필요하다.
- 티키티킷이 판매 주체인지 중개·소개자인지 법률·결제 구조를 별도로 검토해야 한다.

수요가 있다는 이유만으로 공급을 약속하거나 선결제를 받지 않는다. 역공동구매의 구현, 참여 조건, 여행사 협상 방식은 미결정이다.

## 7. 스폰서 DROP과 편집 독립성

스폰서 DROP은 장기 수익 모델 후보지만, 좋은 딜 판정과 수익화를 분리해야 한다.

### 7-1. 분리 원칙

- 먼저 일반 DROP과 같은 가격·일정·수수료·예약 가능성 검증을 통과해야 한다.
- 협찬비나 높은 수수료가 추천순, DROP 선정, 표현 강도에 영향을 주지 않게 한다.
- 스폰서 여부를 사용자가 알아볼 수 있게 표시한다.
- 장점뿐 아니라 시간, 수하물, 환불, 추가 수수료 등 판단에 필요한 불편도 동일하게 공개한다.
- 좋은 딜 기준을 통과하지 못하면 비용을 받아도 DROP으로 발행하지 않는다.
- 편집 판단 담당과 영업·정산 기록을 가능한 범위에서 분리한다.

### 7-2. 사전에 정할 규칙

- 스폰서 표시 문구와 위치
- 선정 기준과 거절 기준
- 가격이 바뀌거나 재고가 사라졌을 때 수정·중단 절차
- 독점의 의미와 기간
- 성과 보고 범위와 사용자 데이터 보호
- CPA/CPS와 고정 협찬비가 함께 있을 때의 공개·정산 방식

이 규칙은 아직 확정하지 않는다. 첫 스폰서 제안을 받기 전에 별도 정책으로 승인해야 한다.

## 8. 여행 전체 수익화 가설

### 8-1. 항공권 원칙

항공권 가격에 티키티킷의 소비자 마진을 붙이지 않는다. 사용자가 보는 가격과 결제 단계의 실결제가 차이를 최소화하고, 여행사와의 CPA·CPS·어필리에이트 수익을 우선한다.

- 제휴 수익이 있는 항공권이라는 이유로 추천 순위를 올리지 않는다.
- 제휴가 없는 여행사의 더 좋은 표도 같은 기준으로 보여준다.
- 제휴 링크와 수익 가능성은 알아볼 수 있게 고지한다.
- 예약 클릭, 실제 구매, 정산 데이터를 구분해 본다.

### 8-2. 항공권 이후의 여정

현재 연결된 Trip.com 숙소 제휴와 마이리얼트립 어필리에이트를 항공권 선택 이후의 자연스러운 여행 준비로 연결할 가능성을 연구한다.

```text
좋은 항공권 발견
    ↓
여행사 예약 이동
    ↓
목적지·날짜에 맞는 숙소 탐색
    ↓
현지 투어·액티비티 등 여행 준비
```

연결 원칙은 다음과 같다.

- 항공권 판단을 방해하지 않는 상세 화면 이후에 둔다.
- 사용자가 이미 선택한 목적지와 일정에 맞는 맥락에서만 제안한다.
- 제휴 수익이 있다는 이유로 불필요한 상품을 끼워 넣지 않는다.
- 항공권 클릭, 숙소 클릭, 액티비티 클릭, 실제 정산을 나눠 측정한다.
- 특정 제휴처가 여행 전체 추천을 독점하지 않게 한다.

## 9. 외부 가격비교 데이터의 역할

외부 가격비교 데이터는 사용자에게 특정 비교처를 직접 드러내기 위한 콘텐츠가 아니라, 티키티킷의 내부 판단 품질을 높이는 자료로 사용한다.

### 사용 범위

- 내부 추천순 보정
- 특가 여부 판별
- DROP 후보 선정과 발행 전 교차 검증
- 조건형 알림 후보 필터링
- 가격이 평소 범위에서 얼마나 벗어났는지 내부 판단

### 사용자에게 보여줄 결과

사용자에게는 특정 비교 서비스의 이름이나 수집 과정을 앞세우기보다, 티키티킷이 확인한 현재 가격, 일정, 수수료, 확인 시점과 판단에 필요한 조건을 보여준다. `외부보다 무조건 싸다`처럼 검증 범위를 넘는 표현은 사용하지 않는다.

외부 데이터의 이용 조건, 갱신 주기, 오류 가능성, 내부 보관 기간은 별도로 관리한다.

## 10. 6개월 단계별 액션 플랜

이 계획은 구현 일정이 아니라 무엇을 어떤 순서로 검증할지 정한 연구 순서다. 각 단계는 이전 단계의 품질과 행동 지표가 확인될 때만 진행한다.

### 1개월차: 기준선과 용어 정리

- 현재 DROP 공개 회차, 내부 이슈, 캠페인 ID, 개별 항공권 ID의 사용 현황을 정리한다.
- `오늘의 DROP #037 | 티키티킷`을 우선안으로 두고 브랜드명 위치와 번호 운영 규칙을 비교하되, 공개 번호는 아직 바꾸지 않는다.
- 주간 행동 사용자 수, 상세 확인, 예약 클릭, 공유, 조건형 알림 등록·발송·클릭의 기준선을 저장한다.
- 항공권, Trip.com 숙소, 마이리얼트립 제휴 클릭과 정산을 구분해 볼 수 있는지 점검한다.
- 좋은 딜 판정 기준과 수익 정보가 섞이는 지점을 문서로 찾는다.

**진행 판단:** 핵심 행동 흐름과 제휴별 측정이 끊기지 않고, 번호 충돌 지점이 목록화되어야 한다.

### 2개월차: 무료 조건형 알림 품질 검증

- 조건형 알림 후보를 수동 검수하고 실제 발송률을 기록한다.
- 같은 지역 반복, 애매한 가격, 불편한 일정, 이미 만료된 표를 걸러낸다.
- 알림 클릭, 상세 확인, 예약 클릭, 7일·30일 재방문, 해지·차단을 함께 본다.
- 신청자가 적더라도 발송량을 늘려 숫자를 만들지 않는다.

**진행 판단:** 신청자 수가 아니라 좋은 후보가 실제 발송되고 반복 방문으로 이어지는 사례가 쌓여야 한다.

### 3개월차: DROP 브랜드 형식 실험

- 기존 공개 회차를 유지한 채 제목·썸네일·상세 표기에서 시리즈 인지가 생기는지 작은 실험을 한다.
- 한 번에 한 요소만 바꾸고 최소 2주 관찰한다.
- 조회수보다 공유, 공유 유입, 상세 확인, 예약 클릭, 알림 등록을 비교한다.
- 회차 제작 시간과 발행 후 딜 생존 시간을 기록한다.
- 번호 체계는 결과와 운영 복잡도를 본 뒤 결정 후보만 좁힌다.

**진행 판단:** DROP 유입이 일반 유입보다 의미 있는 행동과 재방문을 만들거나, 사용자가 시리즈를 구분해 기억하는 증거가 있어야 한다.

### 4개월차: Deal Hunter 제한 실험

- 소수 사용자를 대상으로 링크 기반 특가 제보를 수동으로 받는다.
- 중복, 허위, 수수료 누락, 예약 불가를 검수하는 데 드는 시간을 기록한다.
- 공개 랭킹 없이 검증 통과율과 실제 상세·예약 행동을 본다.
- 닉네임 공개 의사와 원하는 보상을 인터뷰 또는 간단한 설문으로 확인한다.

**진행 판단:** 자동화나 보상 없이도 반복 제보자가 생기고, 운영 비용보다 발견 가치가 커야 한다.

### 5개월차: 수요 집계와 파트너 모델 탐색

- 조건형 알림 데이터에서 반복되는 출발지·지역·예산 조합을 익명·집계 수준으로 분석한다.
- `15만원이면 간다` 형태의 의향 조사에서 가격 외에 날짜 범위, 인원, 출발 공항을 함께 받는다.
- 여행사에 판매 약속이 아닌 익명 수요 요약을 제시할 수 있는지 검토한다.
- CPA/CPS, 공동 DROP, 독점 DROP, 스폰서 DROP의 조건을 각각 분리해 대화한다.
- 취소·환불, 개인정보, 판매 주체, 광고 표시와 관련한 법률·운영 검토 항목을 정리한다.

**진행 판단:** 실제로 대응 가능한 여행사와 반복 수요가 모두 확인될 때만 소규모 파일럿을 설계한다.

### 6개월차: 계속할 한 가지 선택

아래 후보를 같은 기준으로 비교해 다음 6개월의 중심 하나만 선택한다.

- DROP 시리즈 강화
- 무료 조건형 알림과 조기 접근 실험
- Deal Hunter 제보 구조
- 역공동구매 파일럿 준비
- 여행 전체 어필리에이트 연결 개선

비교 기준은 주간 행동 사용자, 30일 재방문, 예약 클릭, 신뢰 지표, 수익 가능성, 주간 운영 시간이다. 성과가 약한 아이디어는 기능을 더 만들어 살리지 않고 보류한다. 유료 멤버십은 이 시점에도 반복 가치가 충분히 증명되지 않았다면 시작하지 않는다.

## 11. 하지 말아야 할 것

- 기존 DROP 번호를 합의 없이 소급 변경하거나 내부 번호를 그대로 공개 번호로 사용하지 않는다.
- 소개할 만한 표가 없는데 일련번호를 채우기 위해 DROP을 발행하지 않는다.
- 클럽 이름부터 정하고 유료 회원 기능을 먼저 만들지 않는다.
- 조건형 알림의 기본 품질이 검증되기 전에 무료 사용자의 접근을 늦추거나 핵심 정보를 유료로 막지 않는다.
- 조회수, 신청자 수, 제보 수만으로 성공을 선언하지 않는다.
- Deal Hunter 랭킹과 보상을 먼저 열어 허위·중복 제보 경쟁을 만들지 않는다.
- 사용자 의향만으로 여행사 좌석이나 목표 가격을 약속하지 않는다.
- 판매·환불·개인정보 책임이 정리되기 전에 역공동구매 결제나 예약금을 받지 않는다.
- 협찬비, CPA, CPS, 어필리에이트 수익이 좋은 딜 판정이나 추천순을 바꾸게 하지 않는다.
- 항공권 가격에 티키티킷 소비자 마진을 더하지 않는다.
- 숙소·액티비티 제휴를 항공권 판단보다 앞세우거나 관계없는 상품을 끼워 넣지 않는다.
- 외부 가격비교 서비스 이름, 크롤링 방식, 비교 데이터를 마케팅의 신뢰 근거처럼 직접 노출하지 않는다.
- 모든 아이디어와 채널을 동시에 실행해 한 사람이 품질을 검수할 수 없는 상태를 만들지 않는다.

## 13. 최종 판단 기준

이 전략의 성공은 클럽 회원 수나 DROP 번호의 크기가 아니라 다음 질문으로 판단한다.

1. 사용자가 티키티킷이 고른 표를 믿고 상세를 확인하는가.
2. 예약 클릭, 공유, 조건형 알림 등록 같은 다음 행동으로 이어지는가.
3. 같은 사용자가 새 DROP이나 알림 때문에 다시 돌아오는가.
4. 제보와 수요 데이터가 기존 수집만으로 찾기 어려운 좋은 딜을 만드는가.
5. 제휴·스폰서 수익이 생겨도 추천과 편집 판단이 독립적으로 유지되는가.
6. 한 사람이 반복해서 운영할 수 있는 구조인가.

이 질문에 대한 증거가 쌓이지 않으면 명칭, 기능, 유료화, 파트너십을 확대하지 않는다.
