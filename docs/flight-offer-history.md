# 전체 여행사 항공권 재등장 이력

모두투어에만 적용하던 보존 처리를 노랑풍선·하나투어·온라인투어·땡처리닷컴·마이리얼트립까지 공통 적용한다. 정상 수집에서 사라지거나 가격 비교 필터에서 제외된 표도 출발일까지 최초 발견과 관측 가격 이력을 `flightOfferHistory`에 보존한다. 숨겨진 표를 판매 목록에 다시 추가하지는 않는다.

- 같은 판매 항공권이 같은 가격으로 돌아오면 최초 발견 시각을 유지한다.
- 새로 관측한 최저가가 기존 하락 조건(1만 원 이상, 5% 이상)을 충족하면 가격 하락 이벤트를 기록한다. 올렸다가 과거 최저가로 돌아온 경우에는 새 이벤트를 만들지 않는다.
- 여행사·왕복 날짜·노선·항공사·편명이 다르면 별도 항공권이다. 편명이 없으면 확인 가능한 시각을 보조로 사용한다. 식별 정보가 부족하면 근거 없이 다른 표와 합치지 않는다.
- 모두투어·온라인투어·땡처리닷컴의 안정적인 상품 ID는 유지한다. 가격이나 검색 결과에 따라 ID가 달라지는 노랑풍선·하나투어·마이리얼트립은 일정 식별자를 사용한다.
- 땡처리닷컴 가격 이력은 기존 실질 가격 기준에 맞춰 발권수수료 2만 원을 포함한다. 표시 가격이나 예약 링크 자체를 바꾸지 않는다.
- 과거 모두투어 검증 이력과 기존 필드는 호환 유지한다. 다른 여행사의 미수집 과거 이력은 추정하지 않고 이후 관측부터 축적한다.

일반 수집·MRT 별도 수집·네이버 필터·소스별 공통 게시 병합에서 이력을 전달하며, API와 정적 첫 화면도 동일한 복원 함수를 사용한다. 부분 게시가 다른 여행사의 이력을 덮어쓰지 않도록 소스 범위를 제한한다.

검증: `scripts/test-flight-offer-history.ts`, `scripts/test-modetour-offer-history.ts`, `scripts/test-recommendation-news.ts`, `scripts/test-modetour-manual.ts`, `tsconfig.news.json`, `npm run build`.

배포 시 웹사이트 코드뿐 아니라 실제 A/C 공통 writer·네이버 필터, 일반 소스 수집 런타임 및 MRT 수집 런타임의 의존 모듈도 함께 반영해야 한다. `scripts/lib/naver-admission.mjs`의 새 파일 두 개는 당시 실제 설치된 RUNNER_FILES에 추가한다. 저장소의 목록 전체로 교체하여 이미 설치된 병렬 예약·소유권 복구·전용 프로필 등의 운영 변경을 지우면 안 된다. 실행 중인 수집에는 덮어쓰지 않고 종료 후 정식 유지보수 절차와 digest 검증을 사용한다. 추가 크롤링·운영 캐시 수동 수정은 필요 없다.
