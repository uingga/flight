# 가격 알림 구독 CTA 개선안

> 작성: 2026-08-14. [marketing-strategy.md](marketing-strategy.md) §4-1 "알림 구독 CTA 강화"의 실행 문서.
> 코드 기준: `src/components/Dashboard.tsx`, `src/app/api/alerts/route.ts`

---

## 1. 현재 흐름 진단

### 진입 경로 (현재 1개)

```
카드 목록 → [예약하기 →] 클릭 → 상세 모달(전체 여행사 공용)
  → 스크롤 → 총 예상금액 아래 [🔔 이 노선 가격 알림 받기] (Dashboard.tsx:3102)
```

### 문제점

| # | 문제 | 근거 |
|---|------|------|
| 1 | **진입점이 상세 모달 하단 1곳뿐** | 카드를 클릭한 사용자만, 그중에서도 모달을 아래까지 스크롤한 사용자만 CTA를 본다 |
| 2 | **필터링 사용자가 CTA를 못 봄** | 도시/노선 필터를 쓰는 사용자 = 특정 노선에 관심 있는 사용자인데, 필터 UI 어디에도 알림 제안이 없다. 전략 문서에서 "최적 타이밍"으로 본 시점 |
| 3 | **검색 결과 0건일 때 이탈** | 원하는 노선의 특가가 지금 없는 사용자야말로 알림의 최적 타깃인데, 빈 결과에서 아무 제안 없이 이탈 |
| 4 | **등록 수를 측정 못 함** | `trackAlertSetup`이 `analytics.ts:118`에 정의만 되어 있고 호출부가 없음 → GA4에서 알림 구독 KPI 추적 불가 |
| 5 | "🔔 내 알림" 버튼은 관리 전용 | 미등록 사용자에게는 빈 상태 안내만 보여줌 — 등록 유도로 연결 안 됨 |

### 제약 조건 (설계 시 반드시 고려)

- **API 등록 한도**: IP당 신규 알림 하루 3건, 브라우저(endpoint)당 10건 (`route.ts:13-14`) → CTA를 늘려도 남발형 UI는 불필요. "한 번의 정확한 제안"이 목표.
- **푸시 권한 프롬프트**: 브라우저 알림 권한은 사용자가 CTA를 명시적으로 클릭한 후에만 요청. 배너 노출만으로 권한 프롬프트를 띄우면 차단률만 올라간다.
- **브랜드 보이스**: 카피는 branding-guide 준수 — "알려드릴까요"처럼 차분하고 명확하게 제안. "놓치지 마세요!" 같은 과장된 긴급성 표현은 사용하지 않는다.

## 1-1. 🔴 발견한 버그 — 등록/발송 도시 정규화 불일치 (수정 완료)

CTA 개선 작업 중 발견. **등록된 알림의 상당수가 조용히 발송되지 않고 있었다.**

- 등록: `Dashboard.tsx` → `normalizeCity()` (표기 통일: `서울(ICN)`→`인천`, `쿠마모토`→`구마모토`)
- 발송: `scripts/send-alerts.ts` → 자체 `normalizeCity()` (괄호·공백 제거만: `서울(ICN)`→`서울`)

두 함수가 달라, 저장된 `인천`과 캐시의 `서울(인천)`이 다른 노선으로 취급됐다.

**실측** (`data/all-flights-cache.json` 785건 = 도시 필드 1,570개 기준):

| | 매칭 실패 |
|---|---|
| 수정 전 | **341개 (21.7%)** |
| 수정 후 | 0개 |

주요 사례: `서울`/`서울(인천)`/`서울(ICN)` 241건, `쿠마모토`↔`구마모토`, `다카마츠`↔`다카마쓰`, `타이페이`↔`타이베이`, `비엔티엔`↔`비엔티안`.

**수정**: `send-alerts.ts`에 `cityKey()` 추가 — 대시보드의 `normalizeCity`를 먼저 적용한 뒤 괄호·공백을 제거해 양쪽을 같은 키로 맞췄다. 매칭 비교에만 적용했고 알림 문구·공유 URL 생성은 기존 함수를 그대로 써서 표시 동작은 바뀌지 않는다.

**하위 호환**: 이미 저장된 알림(`인천`, `오사카(간사이)`, `구마모토` 등)도 새 키로 정상 매칭됨을 확인 — 기존 구독자 마이그레이션 불필요.

## 2. 개선안 (우선순위순)

### P0. 상세 모달 CTA 위치 이동 ✅ 완료

기존 위치(총 예상금액 ↔ 예약 버튼 사이)는 모달에서 가장 복잡한 구간이었고, 전면 버튼이 주 전환 동선(가격 확인 → 예약)을 끊었다.

**검토한 후보**

| 후보 | 판단 |
|------|------|
| 액션 바에 세 번째 버튼 추가 | ❌ 375px에서 예약 버튼 폭이 152px로 줄어 문구가 깨짐 |
| 예약 버튼 위 sticky 한 줄 | ❌ 주 CTA 바로 위라 매출 동선과 경쟁, sticky 높이도 증가 |
| 총액 블록 안 인라인 링크 | ❌ 사용자가 지적한 혼잡 구간 그대로 |
| **상단 요약 바 우측 칩** | ✅ 채택 |

**채택 이유**: `mdtSummaryBar`가 이미 `justify-content: space-between` + 닫기 버튼용 우측 여백(56px)을 갖고 있어 두 번째 자식을 받도록 설계돼 있었다. 스크롤 없이 보이고, 가격→예약 흐름을 전혀 건드리지 않는다.

- 트리거: 요약 바 우측 칩 `🔔 가격 알림` (`priceAlertOpenBtn`을 전면 버튼 → 알약형 칩으로 변경)
- 패널: 요약 바 바로 아래에서 펼쳐짐 — 본문 하단과 무관
- 겹침 방지: 칩에 `margin-right: 8px`, 요약 바에 `flex-wrap` — 긴 항공사명(투르크메니스탄항공)에서는 칩이 아랫줄로 흘러가고 닫기 버튼과 겹치지 않음 (실측 확인)

### P1. 측정 — `trackAlertSetup` 호출 연결 ✅ 완료

- `savePriceAlert` 성공 직후 호출. `analytics.ts`의 `trackAlertSetup`에 `entry` 파라미터를 추가해 GA4에 `entry_point`로 기록 — 진입점별 전환 비교가 가능해졌다.

### P2. 노선 검색 반응형 CTA 배너 ✅ 완료

- **트리거**: 검색으로 도착 도시가 **하나로 좁혀졌고** 결과가 1건 이상일 때, 목록 상단 배너.
- **카피**: `다낭, 지금 최저 ₩214,300. 더 내려가면 알려드릴까요? [알림 받기] [×]`
- 목표 가격 기본값 = 현재 결과의 실제 최저가, `baseline`도 해당 항공권.
- **노출 제어**: 닫거나 등록하면 그 노선은 세션 동안 미노출 (`sessionStorage`).

### P3. 검색 결과 0건 빈 상태 ✅ 완료 (초안에서 설계 수정)

**초안의 오류**: 처음에는 "결과 0건 + 캐시에 같은 목적지 항공권 있음"을 조건으로 `지금은 다낭 특가가 없습니다`를 띄우도록 만들었다. 그런데 이 조건은 **항공권이 있는데 필터가 가린 상황**을 뜻하므로 문구가 사실과 반대였다. (예: `다낭` 검색 + 도착 지역 `일본` → 다낭 특가 19건이 멀쩡히 있는데 "없습니다"라고 안내)

브랜드 가치인 **투명성(No 낚시)** 에 정면으로 어긋나고, 사용자의 필터 실수를 바로잡아 줄 기회도 놓친다.

**수정한 설계** — 0건인 이유를 먼저 가려낸다 (`emptyDiagnosis`).

| 상황 | 화면 |
|------|------|
| 검색어에 맞는 항공권이 있는데 필터가 가림 | `다낭 항공권은 19건 있습니다` + 원인이 된 필터를 칩으로 표시 → 클릭 시 그 필터만 해제. **알림 CTA 없음** |
| 검색어에 맞는 항공권이 정말 하나도 없음 | `지금은 나가사키 특가가 없습니다. 나오면 알려드릴까요?` + 알림 CTA |
| 도시로 인식되지 않는 검색어 (오타·항공사명) | 기존 안내만. 알림 CTA 없음 |

- 원인 판정을 위해 필터 조건별 판정 함수(`matchesSearchTerm` / `matchesRegionFilter` / …)를 분리하고 `filteredFlights`도 이를 재사용하도록 정리했다.
- 진짜 0건인 경우엔 보여줄 항공권이 없으므로 `baseline` 없이 등록한다 (API가 선택 항목으로 허용 — `route.ts:268`). 목표 가격 기본값은 인터파크 월평균이 있으면 채우고, 없으면 직접 입력받는다.
- 도시명은 `CITY_TO_AIRPORT`로 검증해 오타·항공사명 입력으로는 등록되지 않게 했다.

**의도적 제한**: 도착 도시가 둘 이상으로 갈리면(예: "도쿄" → 나리타/하네다) 배너를 띄우지 않는다. 알림은 노선 단위라 한쪽만 등록되면 사용자 기대와 어긋나기 때문.

### P4. "내 알림" 빈 상태를 등록 유도로 전환 (미착수)

- **작업**: 빈 상태 문구("항공권 상세 화면에서 등록할 수 있어요")를, 현재 검색 중인 노선이 있으면 해당 노선 바로 등록 버튼으로 교체.
- **공수**: 1~2시간

### 보류 (하지 않기로 한 것)

- **카드마다 🔔 아이콘 추가**: 카드에 이미 즐겨찾기·공유 버튼이 있어 과밀. P2/P3 효과 측정 후 재검토.
- **첫 방문 즉시 알림 팝업**: 브랜드 보이스와 충돌(광고 냄새), 푸시 권한 차단률만 상승.

## 3. 성공 지표

| 지표 | 측정 방법 |
|------|----------|
| 알림 등록 수 (주간) | GA4 `alert_setup` 이벤트 |
| 진입점별 등록 비중 | `alert_setup`의 `entry_point` (`detail_modal` / `filter_banner` / `empty_state`) |
| 실제 발송 건수 | `send-alerts.ts` 로그의 발송 건수 — 정규화 버그 수정 전후 비교 |
| 등록 후 재방문율 | GA4 코호트 |

배포 후 1~2주 관찰 → 진입점별 비중으로 어느 CTA가 실제로 기여했는지 판단하고, 기여 없는 진입점은 정리한다.
