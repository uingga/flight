# 온라인투어 요청 형식·빈 목록 상태 수정

## 확인한 원인

- 2026-09-09 16:55 KST B 실행 `385828e9-c809-49d9-ad55-73b6569a976b`는 `unexpected_api_query`, 상품 요청 0회, 첫 페이지 미검증, 차단 감지 없음으로 실패했다. 상품 없음이 검증된 실행은 아니다.
- A는 이전 온라인투어 항공권이 0건일 때 `preservedSources`에 실패를 기록하지 않아, 같은 실패를 `B PC Chrome 수집 0건 완료`로 잘못 기록했다.
- B 공개 목록 문서를 두 번 진단했다. 첫 진단에서 새 항목의 이름을 발견했고, 두 번째에서 값과 DOM 정렬을 확인했다. 상품 API는 Fetch 가드로 전송 전에 모두 차단했고 전체 수집·운영 데이터 반영은 하지 않았다.
- 원본 페이지의 상품 요청: `order=LOW`, `searchStartDate=''`, `searchEndDate=''`, `useYn=N`. DOM의 `order`도 `LOW`. 이전 구현은 `LP`와 이전 키 목록만 허용했다. 요청의 인증 키 값은 저장·출력하지 않았다.
- 문서의 도시 선택은 4개이며 API를 차단한 상태의 빈 DOM은 상품 없음의 증거가 아니다. 현재 재고 유무는 아직 확정하지 않는다.

## 변경

- 구형 LP 및 확인된 LOW만 허용하고 응답 후 DOM 정렬과 같은지도 대조한다. 새 세 필드는 모두 함께 있을 때만 빈 시작일/종료일·N 값을 허용한다. 날짜 제한·다른 useYn·누락·중복·알 수 없는 정렬은 거부한다.
- 첫 지역 진입뿐 아니라 날짜/도시/후속 페이지 어댑터도 동일 형식을 처리한다. 요청을 조작하거나 상한·재시도·차단 회로를 변경하지 않는다.
- 수집 예외는 이전 표가 0건이어도 실패로 기록하고 이전 정상 갱신 시각을 유지한다. 일반 여행사에도 동일 원칙을 적용한다.
- 모든 계획 지역·월의 명시적 빈 목록과 도시 없음, 정상 종료·정리, 누락/오류 없음이 검증된 온라인투어만 정상 빈 결과로 승인한다. A도 해당 검증을 통과한 빈 결과만 수용하고 `전체 지역·월 확인 완료 — 판매 상품 없음(0건)`으로 기록한다. 단순 0건, 도시가 남은 불확실한 빈 응답, 미완료 월, 접근 제한은 성공으로 승격하지 않는다.
- 최초 실패 증거·과거 운영 로그는 수정하지 않는다. 사이트 변경 대응과 기록 버그 수정은 배포 후부터 적용한다.
