# 온라인투어 전체 범위·조회 규모 사전 점검

## 확인된 사실

- 저장된 실제 목록 DOM에는 지역 버튼 7개: 아시아·중국·일본·유럽·남태평양·미주·괌/사이판.
- 실제 자동 완주는 ICN/PQC/202609 한 범위, 2페이지/22개/상품 조회 2회다.
- inspect의 availableScopes는 현재 화면에서 한 번 클릭으로 이동 가능한 후보다. 전체 도시·월 목록도, 해당 월 상품 존재의 증거도 아니다.
- 기존 목록 adapter는 도시/월/더보기의 관측된 동작을 처리한다. 별도 `src/lib/onlinetour-region-discovery.ts`와 `scripts/discover-onlinetour-regions.ts`에 지역 버튼의 유한 탐색을 추가했다. 이는 전 도시·월 상품 순회기와 다르며 그 기능의 완료를 뜻하지 않는다.
- 이번 점검은 저장 자료와 코드만 분석했다. 추가 사이트 요청 0회.

## 전체량 산정의 경계

전체 도시 수·수집할 월 범위·범위별 페이지 수가 아직 없어 전체 조회 횟수/소요 시간은 미확정이다. 기본 maxRequests=100은 예상 전수 조회량이 아니다. 단일 푸꾸옥 표본의 시간도 모든 도시로 단순 곱하지 않는다.

정상 상품 조회량은 각 출발지/도시/월의 페이지 수 합계에 화면이 허용하는 끝 확인을 더한다. 최초 정상 페이지를 계획 수립과 수집에 재사용할 때 같은 페이지를 두 번 세거나 재요청하지 않는다. 지역 탐색이 발생시킨 상품 요청도 전체 부하에 포함한다. 정해진 5초 간격 외에 문서/API 대기와 허용된 10초 재시도 대기가 추가된다.

## 승인된 범위 발견 시험 — 구현·검증 진행

사용자가 `최대 6회 지역 탐색까지 진행`을 선택했다. 실행 계획은 `.local-crawler/verification/onlinetour_region_approved_plan.json`이며 구현·오프라인 검사·제한 탐색·결과 정리를 한 작업으로 진행한다.

현재 아시아 화면은 읽기만 하고, 나머지 6개 지역 버튼을 각 1회 이동한다. 문서 이동 최대 6회, 상품 전송 허용 최대 6회, 간격 5초, 재시도 없음. 정확한 목록 API 전송 전 cap을 유지한다. 도시/월별 목록 이동·더보기·상세 조회·운영 반영은 하지 않는다. 현재 화면이 달라졌거나 지역 버튼 계약이 달라졌으면 중단한다.

401/403/429/CAPTCHA/접근 제한/형식 오류/네트워크 오류/예산 소진에서 중단한다. 이 시험은 지역별 도시와 첫 화면의 월 선택 구조를 확인하는 범위다. 이것만으로 전 도시의 모든 월·페이지 수가 확정된다고 주장하지 않는다. 지역 연결부 구현·오프라인 검사·승인된 탐색·결과 집계를 한 묶음으로 처리한다.

기계 판독 증거: `.local-crawler/verification/onlinetour_scope_workload_inventory.json`.

## 재개 실행 결과 — 중국 화면 복구, 전 지역 탐색 미완료

사용자의 후속 `응 그래 그럼 규칙 정했으니 시작해봐`에 따라 중국 현재 탭의 명시적 복구 reload 1회와 남은 지역 5회 이동을 합쳐 최대 6문서/6상품 요청, 간격 5초, 자동 재시도 없음으로 재개했다. 이전 실패 상한을 재활용한 것이 아니다.

- `reloadStart: true` 명시 계획만 복구 reload를 수행한다. 현재 정확한 목록 URL의 지역이 일치해야 하며 첫 동작에서만 가능하다. 기존 전송 전 문서·상품 cap과 실패 latch를 그대로 공유한다. 일반 지역 탐색에서는 이 경로를 사용하지 않는다.
- 실행 계획: `.local-crawler/verification/onlinetour_region_resume_plan.json`.
- 실행: `.local-crawler/staging/7cf8908c-0b95-4758-9622-9170794dd967/summary.json`, exit 1, `failed / invalid_paused_request`, 실행 구간 68.168초.
- 이번 전송: 문서 1회 허용, 추가 문서 1회 전송 전 거부, 상품 0회. 과거 실패와 합쳐 문서 전송 허용 2회/상품 0회다. 최초 실패 이후 재시도/나머지 지역 이동은 없었다.
- 후속 읽기 전용 진단에서 CH 본문·목록 함수·지역 버튼이 존재하고 domInteractive가 양수임을 확인했다. 이전 로딩 중 prepare 오류와 구분한다.
- 별도 읽기 전용 staging `.local-crawler/staging/8434c75f-e607-4106-a816-52a1931f04cb/summary.json`에 중국 도시 MFM/SIA/DYG/TAO와 첫 출발일을 보존했다. 이 진단의 문서/상품 전송과 UI 동작은 0회다. 조회 상품을 받은 것은 아니며 실패한 자동 실행을 성공으로 바꾸지 않았다.
- 거부 요청의 원인은 미확정이다. 당시 `invalid_paused_request`가 여러 조건을 합친 오류였고 세부 플래그가 없었다. 현재 DOM/프레임/성능 기록에 iframe은 없으므로 광고 iframe 때문이라고 단정하지 않는다.
- 후속 로컬 보정은 최초 거부 요청의 main-frame 여부·network ID 존재 여부·redirect/response 단계·GET/POST 구분·본문 유무·list/API/other 분류만 저장한다. URL/쿼리/ID/헤더/본문 자체는 저장하지 않는다. 거부 조건이나 예산을 완화하지 않았다.
- 최종 관련 검사: adapter 40개, CLI 6개 통과. 프로젝트 타입 검사 오류 0. 보호 파일 불변, 연결 해제, 운영 반영 없음. 새로 추가한 복구·진단 코드는 직접 검사했으며 독립 재리뷰 완료라고 주장하지 않는다.
- 현재 확인 범위: 과거 AS/PQC와 별도 CH/4도시. JA/EU/HN/US/GS 미방문. 전 도시·월 조합 수 및 전수 조회량은 여전히 미확정이다.

## 거부 조건 확인 — CH → JA 단일 진단

후속 사용자 `그래 진행해` 뒤 CH에서 JA로 문서·상품 각각 최대 1회, 5초 대기, 재시도 0으로 실행했다.

- 실행 `e75d935a-0023-4dab-82d3-79e0e036e48f`: exit 1, `invalid_paused_request`, 문서 전송 허용 1회, 보조 문서 전송 전 거부 1회, 상품 전송 허용 0회, cleanupConfirmed=true.
- 최초 거부 플래그는 mainFrame=false, networkIdPresent=true, redirected=false, responseStage=false, method=GET, bodyPresent=false, urlKind=other, resourceKind=document. 따라서 코드의 합친 조건 중 직접 거부 원인은 **메인 프레임과 다른 frameId**임이 확인됐다. 다른 플래그는 이 오류를 발생시키지 않는다.
- 다만 그 요청의 주소·생성 주체·광고/인증 등 목적은 당시 저장하지 않아 미확정이다. 다른 프레임이라는 증거를 광고라는 증거로 바꾸지 않는다.
- 읽기 전용 진단 `02ed288e-776b-48d5-98d9-8321a3880d86`에서 JA 화면과 HND/KIX 두 도시를 확인하고 staging에 저장했다. 화면 이동/문서/상품 전송 0, cleanupConfirmed=true. 멈춘 화면 DOM의 iframe 및 frame 리소스는 없었고 광고 관련 스크립트의 존재만으로 거부 요청의 생성 주체를 특정할 수 없다.
- 읽기 전용 임시 진단의 첫 실행은 DOM 표현식 정규식 오류로 실패했다. 표현식을 수정한 두 번째 실행이 성공했으며 사이트 이동/상품 재시도는 아니다.
- 실패한 자동 지역 실행은 여전히 실패다. JA 상품 목록과 나머지 EU/HN/US/GS 탐색은 완료하지 않았다. 보호 파일 불변과 활성 수집기 없음을 검증했다.
- 정책 변경 미적용: 현재 모든 Document를 차단 검사하는 방식에서 지역 메인 문서·상품 요청과 보조 프레임을 분리하는 것은 요청 범위 변경이다. 보조 프레임을 무조건 통과시키거나 차단 실패를 무시하는 수정은 하지 않았다.
