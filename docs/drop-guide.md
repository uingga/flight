# 티키티킷 드롭 실행 가이드 (런북)

DROP 한 회차를 기획 → 원고 → 이미지 → 네이버 임시저장 → 배포까지 실행하는 절차.
**콘텐츠 기준**(문체·브랜드)은 `docs/marketing-strategy.md`, `docs/branding-guide.md`(Version 2)를 따르고,
이 문서는 **작업 순서와 도구**를 다룬다. DROP 02(2026-08) 실행 경험 기준.

## 0. 파일 맵

| 파일 | 역할 | Git |
|---|---|---|
| `data/marketing/current-drop.json` | 드롭 데이터 원본 (표 ID, 테마, 헤드라인). `/drop` 페이지와 이미지 생성이 모두 이걸 읽음 | 커밋 |
| `src/app/drop/page.tsx` | tikitikit.kr/drop 페이지. 빌드 시 current-drop.json + 항공권 캐시를 읽음 | 커밋 |
| `data/marketing/naver-blog-proposal-*.md` | 확정 원고 (사용자와 문장 단위 확정) | 로컬 전용 |
| `data/marketing/drop-00N-preview.html` | 네이버 입력용 HTML (원고 + 이미지 + 링크) | 로컬 전용 |
| `data/marketing/make-drop-images.mjs` | 썸네일 + 카드 이미지 생성기 | 로컬 전용 |
| `data/marketing/drop-00N-images/` | 생성·수집한 이미지 | 로컬 전용 |
| 네이버 자동화 스크립트 (`redraft-*`, `fix-*`, `verify-*`) | 임시저장 입력·보정·검증 | 로컬 전용 |

로컬 전용 파일은 `git add -A` 금지. 커밋은 `current-drop.json`과 사이트 코드만.

## 1. 표 선정 (데이터 검증이 절반이다)

`data/all-flights-cache.json`(약 800편)에서 후보를 추린다.

**추리는 기준**
- 출발일 리드타임: 발행일 기준 **최소 12일** (발행 지연 + 판매 종료 리스크). 8일짜리를 골랐다가 발행 전에 사라진 것이 DROP 02의 호치민 사고.
- 할인율(`discountRate`): **인터파크 그 달 최저가 대비**라서 양수면 진짜 특가. 음수여도 일정·출발지 등 다른 매력이 있으면 가능.
- 좌석 수: 적으면 희소성 소재, 많으면(20석+) 발행 후 생존율. 리드 티켓은 생존율도 고려.
- 구성: 세 장이 지역·출발 시간대·서사가 겹치지 않게 (예: 신규 노선 / 일본 소도시 / 지방 출발).

**반드시 교차 검증할 것 (캐시를 그대로 믿지 않는다)**

0. **먼저 감사 도구를 돌린다.**
   ```bash
   npx tsx scripts/audit-flight-consistency.ts
   ```
   판매처 간 항공사·시각·가격 불일치와 편명 불변식 위반을 뽑아준다.
   고른 표의 ID가 `high` 목록에 있으면 그 표는 쓰지 않는다. `--json`으로 기계용 출력,
   `--source ttang`으로 특정 판매처만 검사. high가 하나라도 있으면 종료 코드 1.
1. **같은 노선을 파는 다른 여행사 레코드와 시각·항공사 비교.** DROP 02에서 땡처리닷컴 레코드가 파라타항공 저녁편에 썬푸꾸옥 편명을 잘못 붙인 사례 발견. 여러 소스가 같은 시각을 보고하면 신뢰.
2. **공식 스케줄 확인**: aeroroutes.com, 항공사 보도자료, 인천공항 출발 시간표. 신규 취항 스토리를 쓸 땐 취항일도 확인.
3. **공유 페이지 생존 확인**: `https://www.tikitikit.kr/share/<id>`의 `<title>`이 노선명이면 정상, "지금 나온 땡처리 항공권"이면 배포된 캐시에 없는 것.
4. ttang 표는 표시가 + **발권수수료 20,000원** = 실결제가. 본문·썸네일은 실결제가 기준, 카드 캡션으로 차액 설명.

## 2. 원고

- 원고 확정본은 `naver-blog-proposal-*.md`에 보관. **확정 후 문장 임의 수정 금지.**
- 구조(참고용, 강제 아님): 꼭지마다 "왜 이 표가 나왔나 → 도시 이야기 → 일정 → 링크". 도시 이야기가 마지막에 오면 붙인 티가 난다.
- 금지: 인터파크·비교 서비스 언급, 크롤링 암시, 실데이터 없는 희소성 연출. 좌석 수·가격·시각은 캐시 실측값만.

### 문장 규칙

- **원고를 쓰기 전에 `docs/copy-feedback-log.md`를 읽는다.** 사용자의 문장 피드백이 회차별로 누적되는 파일이고, 맨 위 "증류된 규칙" 표가 초안 자체 검수 기준이다.
- **피드백을 받으면 그 라운드가 끝날 때마다 로그에 추가**하고, 새 유형이면 증류된 규칙 표도 갱신한다.
- 꼭지 간 반복 금지: 같은 구조(음식+가격, 당일치기 제안, "오전 비우기" 조언)가 두 꼭지에 나오면 한쪽만 남긴다.
- 링크 규칙:
  - 표: `/share/<id>?utm_source=naver_blog&utm_medium=content&utm_campaign=tikitikit_drop_00N&utm_content=drop_deal`
  - 알림 CTA: `/?dealAlert=1&...&utm_content=alert_cta` (dealAlert=1이 알림 설정 시트를 연다)
  - `/drop` 링크는 블로그에 넣지 않는다 (본문과 내용 중복).

## 3. 이미지

### 3-1. 썸네일 + 카드 (자동 생성)

```bash
node data/marketing/make-drop-images.mjs
```

- **썸네일**: current-drop.json 기반 1080×1080 티켓 모티프. 폰트는 **Pretendard 800**(jsDelivr CDN, DROP 02에서 확정 — Noto Sans KR은 폭이 좁아 압축돼 보임). 로딩 대기(`document.fonts.ready`)가 들어 있음.
- **카드**: 대시보드 실카드 캡처. `/api/flights`를 해당 표 1건으로 모킹해 tikitikit.kr 메인의 `.card`를 찍는다 (/drop 카드는 편집 텍스트가 많아 블로그 본문과 겹침).
- 좌석 수가 계속 줄므로 **발행 직전 재실행**해 최신화. 실행 전 current-drop.json의 표가 캐시에 있는지 확인 (없으면 카드가 빠진 채 생성됨).
- 표시가 ≠ 결제가인 표(ttang)는 카드 아래 캡션으로 설명: "카드에는 X원으로 표시되지만, 발권수수료를 포함한 실제 결제가는 Y원입니다."

### 3-2. 목적지 사진 (퍼오기)

- **Unsplash**에서 상업 사용 가능 사진 사용, 캡션에 `사진: 작가명 (Unsplash)` 표기.
- 다운로드: `?w=1600` 파라미터로 적정 해상도. 파일명 `drop0N-photo-<도시>-<내용>.jpg`.
- 사용자에게 후보를 보여줄 땐 **base64로 임베드한 HTML**(또는 아티팩트)로. 외부 핫링크 이미지는 사용자 화면에서 안 보인다. Read 도구 출력도 사용자에겐 안 보인다.

## 4. 네이버 블로그 임시저장 (Playwright 자동화)

세션은 `.naver-profile`(영구 프로필)에 저장. 기반 코드는 `scripts/draft-naver-blog.mjs`와
DROP 02의 `data/marketing/redraft-drop-002.mjs`(재입력) / `fix-drop-002.mjs`(보정·검증).

**입력 방식**: 입력용 HTML을 로컬 서버로 띄워 이미지 자리를 `이미지자리번호NNN끝` 마커 문단으로 바꿔
통째로 붙여넣고 → 마커 자리마다 사진 업로드 → 마커 제거 → 가운데 정렬 → 임시저장.

**함정과 대응 (DROP 02에서 전부 실제로 겪음)**
1. **계정 서식 오염**: 에디터에 볼드/취소선 등이 켜진 채 남아 있으면 붙여넣는 전체가 그 서식을 받는다. 붙여넣기 전에 글자 하나 쳐서 `b, strong, strike, u` 검사 후 토글 해제.
2. **DOM 삭제 ≠ 모델 삭제**: JS로 문단 텍스트를 지우면 화면에선 사라져도 저장본에 남는다. 마커 제거는 **키보드 입력**(클릭 → Home → Shift+End → Delete)으로.
3. **링크는 `<a>`가 아니다**: 에디터 안에서 링크는 `span.se-link[data-href]`. 검증 셀렉터는 `a[href], .se-link[data-href]` 둘 다.
4. **버튼 모양 CTA는 포기**: 에디터가 배경·패딩을 제거한다. 가운데 정렬된 일반 텍스트 링크로 (DROP 02 확정).
5. **임시저장 열기**: 정상 저장 후엔 "이어쓰기" 복구 팝업이 안 뜬다. 저장 버튼 옆 **숫자 버튼 → 저장 목록**에서 제목으로 찾아 연다. 복구 팝업이 뜨면 그건 미저장 상태의 복구다.
6. **자동저장 오염**: 작업 중간 상태가 자동저장될 수 있다. 마지막에 반드시 수동 저장하고, **저장 목록에서 다시 열어 최종 검증**: 마커 0개, 이미지 장수, 링크 4개(se-link), 볼드는 소제목만.
7. 빈 에디터의 회색 안내 문구는 placeholder다. 본문 텍스트 검증에서 제외할 것.
8. **발행 버튼은 절대 자동으로 누르지 않는다.** 임시저장까지만. 발행은 사용자.
9. **표 링크는 네이버 링크 카드(oglink)로** (DROP 02에서 확정): 일반 텍스트 링크는 목적지가
   안 보여 낚시처럼 보인다. 만들 땐 빈 문단에 URL을 키보드로 입력 후 Enter →
   `.se-component.se-oglink` 생성 대기. **주의 두 가지**: ① 카드가 생겨도 입력한 URL 텍스트가
   문단에 남는다 — 지우지 않으면 다음 검색에서 또 발견돼 카드가 중복 생성된다.
   ② 남은 URL 텍스트는 **여러 문단으로 조각나** 있을 수 있어 `^https://` 패턴만으로 못 찾는다.
   `utm_` 조각이 든 문단까지 검사해서 키보드로 제거할 것. 알림 CTA는 텍스트 링크 유지.
10. **카드 이미지는 폭 500px로**: 이미지의 실제 픽셀 폭이 곧 네이버 PC 본문 표시 폭이다
    (본문폭 약 693px). 원본 비율을 지키려면 2배율로 캡처한 뒤 파일만 축소한다 —
    `make-drop-images.mjs`에 구현돼 있음. 저해상도 캡처(뷰포트 축소)는 카드 비율이 바뀌므로 금지.

**본문 배치 순서** (DROP 02 기준): 대표 썸네일(1번, 정사각 — 대표 이미지로 선택됨) → 꼭지마다 [본문 → 목적지 사진+출처 캡션 → 본문 → 카드 이미지(+수수료 캡션) → 텍스트 링크] → 마무리 + 알림 CTA → 고지 문구. 성격이 바뀌는 지점마다 빈 문단.

## 5. 사이트 반영과 배포

1. `current-drop.json` 갱신 (헤드라인·표·테마) → 선택 스테이징으로 커밋 (다른 작업자의 미커밋 파일 주의).
2. `git pull --rebase --autostash` → `npm run build` → `npm run deploy:mark` → push. (`deploy:mark`는 미커밋 변경이 있으면 거부 — 작성자 구분 없음. 안 되면 수동 태그로 우회 가능, `docs/DEPLOY.md` 참고.)
3. 배포 후 `/share/<id>` 3건과 `/drop` 이 새 표를 보여주는지 확인.
4. 크롤링이 하루 7회 캐시를 갱신·재배포하므로, 발행 시점과 가까울수록 좋다.

## 6. 발행 전 최종 체크리스트

- [ ] 세 표 모두 공유 페이지 title이 노선명으로 나오는가
- [ ] 좌석 수·가격이 최신 캐시와 일치하는가 (`make-drop-images.mjs` 재실행 포함)
- [ ] 본문 숫자(좌석·시각·가격)와 카드 이미지가 서로 일치하는가
- [ ] 네이버 저장본: 마커 0, 이미지 전부 가운데 정렬, 링크 4개 클릭 가능, 볼드는 소제목만
- [ ] 대표 이미지 = 정사각 썸네일
- [ ] UTM 캠페인명이 회차와 일치 (`tikitikit_drop_00N`)
- [ ] 사용자의 명시적 발행 승인

발행 후: 어드민 GA4에서 `tikitikit_drop_00N` 캠페인 유입 모니터링.
