# 온라인투어 — 기존 프로필 복사본 기반 전용 Chrome

2026-09-07 사용자 요청으로 staging 수집기의 연결 방식을 변경했다.
B의 별도 검증 폴더에 전달하고 전용 Chrome 연결을 확인했다.
실상품 수집 성공이나 운영 연결을 뜻하지 않는다. 실제 시험 결과는 아래에 구분해 기록한다.

## 어떤 프로필인가

참고 저장소 https://github.com/chacha95/automation 의 `scripts/setup.py`는 개인 Chrome의
`User Data` 폴더를 처음 한 번 `~/tmp/chrome-debug`로 복사하고 이후에는 복사본을 재사용한다.
원본 프로필에 직접 붙거나 매 실행 다시 복사하는 방식이 아니며, 빈 프로필을 만드는 방식도 아니다.
복사 당시 정보가 남아 있을 수 있지만 원본의 이후 변경을 자동 동기화하지 않으며,
복사된 로그인·쿠키가 현재도 유효하다고 보장하지 않는다.

기존 땡처리용 실행기 `scripts/start-ttang-debug-chrome.mjs`가 쓰는 동일한 폴더와
`127.0.0.1:9222`의 headed Chrome을 재사용한다. 이번 수정은 프로필 내용/쿠키/로그인을
읽거나 복사·삭제하지 않고 개인 Chrome 설정을 변경하지 않는다. 별도 빈 프로필도 만들지 않는다.
참고 코드의 자동화 탐지 관련 플래그는 추가하지 않는다.

## 연결 경계

- 목록 CLI, 지역 CLI, 전체 순회 CLI, 단일 페이지 pilot 및 진단 모두 전용 연결만 사용한다.
- Windows에서 9222 리스너 소유 프로세스가 `chrome.exe`이고 정확한 전용 프로필 경로,
  loopback 주소, 고정 디버그 포트로 실행됐는지 확인한다. headless/guest/incognito는 거부한다.
- 개인 Chrome의 `DevToolsActivePort`는 읽지 않는다. 전용 Chrome이 없거나 확인이 안 되면
  실패하며 개인 Chrome으로 폴백, 브라우저 자동 실행, 프로필 자동 준비 또는 재시도를 하지 않는다.
- 소유 프로세스 검증 후 고정 loopback의 `/json/version`만 한 번 읽는다. 3초/8KB 상한,
  리디렉션 금지, 동일 loopback/포트의 browser UUID 경로 검증을 적용한다. 연결 전 소유자가
  바뀌지 않았는지 다시 확인한다. HTTP 탐색은 여행사 요청이 아니다.
- 연결 handshake는 최대 15초다. 이 방식은 일반 Chrome의 매 연결 허용 대화상자 경로를
  사용하지 않는다. 브라우저나 OS 보안 창을 자동 클릭하는 코드는 없다.
- 일반 진단·목록·지역·전체 순회에는 정확한 온라인투어 목록 탭이 이미 하나 열려 있어야 한다.
  Google 홈 탭이나 Google 로그인은 요구하지 않고, 계정 페이지·쿠키·storage를 읽지 않는다.
- 예외인 `probe-onlinetour-first-entry.ts`는 별도 승인된 첫 진입 시험 전용이다. 목록 탭이
  0개일 때만 `about:blank` 새 탭을 하나 만들고, 요청 가드를 먼저 켠 뒤 고정된 AS 목록을
  한 번 연다. 문서 1회·상품 1회 상한, 호스트 잠금, 최신 차단 상태 검사와 날짜별 1회 시도
  표식을 적용한다. 개인 탭 이동·탭 닫기·자동 재시도는 하지 않으며 표식을 자동 삭제하지 않는다.
- 사용자가 추가로 승인한 `--recheck-ad-frame-once`는 같은 날의 첫 진입이 광고 보조 문서에서
  중단됐고 상품 전송 0회·정리 성공이 기록된 경우만 기존 AS 목록을 1회 새로고침한다. 별도
  재검증 표식을 남겨 두 번째 실행을 거부하고 기존 첫 진입 표식·차단 회로를 삭제하지 않는다.
  이 추가 검증은 12:57 KST에 이미 사용됐다. 일반 재시도 옵션이 아니다.
- 지역/목록 adapter를 넘길 때 기존 CDP 연결을 정리하고 같은 Chrome에 재연결한다.
  브라우저 프로세스와 프로필은 유지하며 adapter/요청 상한을 동시에 중첩시키지 않는다.
- CLI의 `--consent-confirmed`는 승인된 실행 범위를 확인하는 플래그로 남는다.
  자동 운영 승인이나 요청 상한·차단 보호 해제를 뜻하지 않는다.

## 유지되는 수집 보호

명시된 지역·도시·월과 문서/상품 요청 상한, 요청 사이 간격, 실패/정리 중 접근 제한 판정,
불명확한 보조 프레임 거부, 입력/응답 검증, 부분 증거 보존 및 `productionReady=false`를 유지한다.
2026-09-07 시험에서 식별된 외부 `https://gum.criteo.com/syncframe`의 정상 GET 보조 문서만
전송 전에 차단하고 그 차단 자체는 상품 수집 실패로 취급하지 않도록 보정했다. 해당 프레임을
허용하는 것이 아니다. 메인 프레임·다른 경로/호스트·리디렉션·응답 단계는 예외가 아니고,
차단 명령이 실패하면 수집과 정리도 실패한다. 실제 사이트의 401·403·429·CAPTCHA 처리는 유지한다.
`suppressedAuxiliaryDocuments`는 `blockedRequests`에 포함된 비필수 차단 문서 수다.
전체 순회 실행기의 기존 cooldown 검사와 호스트별 잠금도 변경하지 않았다.
진단/pilot/지역/목록 단독 CLI는 기존처럼 운영 예약기가 아니므로 운영자의 실행 전 차단 회로와
동시 실행 점검이 필요하다. 전용 프로필 변경을 차단 뒤 재요청 허가로 사용하지 않는다.

실제 결과는 `.local-crawler/staging/<UUID>/`에만 저장한다. 기존 운영 스크래퍼, data/,
운영 캐시 병합, 일정 활성화, main 통합 및 배포는 변경하지 않았다.
