# TIKIT DROP 제품·콘텐츠 전략 v1

- 상태: 현재 기준
- 확정일: 2026-08-27
- 적용 범위: 메인, TIKIT DROP, TIKITIKIT CLUB, 인사이트바, Threads·블로그·알림, 실험 기능의 역할과 표현 강도
- 우선순위: 이 문서는 과거 `drop-guide.md`, `drop-article-template.md`, DROP 관련 과거 전략 문서보다 우선한다. 과거 문서는 사용 보류 상태를 유지한다.

## 1. 출발점

기존 항공권 서비스의 흐름은 보통 다음과 같다.

> 어디 갈지 정했다 → 날짜를 정했다 → 가장 좋은 항공권을 검색한다.

티키티킷은 반대 방향을 만든다.

> 아무 계획이 없었다 → 좋은 표를 발견했다 → 여행을 생각하기 시작했다.

티키티킷의 최종 형태는 단순한 땡처리 항공권 모음이 아니라 **여행 기회 탐지기**다. 검색(Search)은 기반 기능으로 유지하지만, 브랜드의 중심 경험은 발견(Discovery)에 둔다.

제품 전체를 판단하는 기준 문장은 다음과 같다.

> 좋은 표 하나가, 없던 여행 계획을 만듭니다.

사용자가 만들어야 할 습관은 “항공권을 사러 간다”보다 다음에 가깝다.

> 오늘 뭐 떴나 보러 간다.

## 2. 제품 구조

티키티킷다운 모든 아이디어를 DROP 안에 넣지 않는다. 아이디어는 담당하는 일에 따라 다섯 영역으로 나눈다.

### 2.1 메인 — 찾기

- 전체 땡처리 항공권을 검색하고 비교하는 곳
- 가격·일정·판매처 정보를 정제된 형태로 제공한다.
- 신뢰와 실용성이 가장 중요하다.
- 메인은 계속 ‘마트’ 역할을 맡는다.

### 2.2 TIKIT DROP — 발견하기

- 티키티킷이 볼 가치가 있다고 판단한 항공권을 보여주는 편집숍
- DROP은 상품 분류가 아니라 가격 사건이다.
- 각 DROP은 고유 번호와 영구 주소를 가진 독립 콘텐츠다.
- 가격·일정·희소성 등을 근거로 선정하며, 판매 종료 후에도 기록으로 남긴다.

### 2.3 TIKITIKIT CLUB — 관계 유지하기

- DROP의 하위 코너가 아니라 별도의 회원·관계 레이어
- 사용자가 앞으로 받고 싶은 여행 기회를 설정하고 기록하는 곳
- 별도 `/club` 페이지를 전제로 한다.
- DROP 상세에서는 CLUB 전체를 설명하지 않고 관련 CTA만 노출한다.

### 2.4 콘텐츠 — 이야기하기

- Threads, 네이버 블로그, 주간 시리즈, 알림 등
- 동일한 DROP 사건을 채널 성격에 맞게 번역한다.
- 사이트보다 유쾌함과 캐릭터의 비중이 크다.

### 2.5 실험 — 재미와 공유 만들기

- 사장님 몰래보기 모드 같은 선택형 이스터에그
- 핵심 정보 구조에 편입하지 않는다.
- 기본 화면을 방해하지 않으며, 사용자가 직접 켰을 때만 동작한다.

한 문장으로 정리하면 다음과 같다.

> 메인은 도구, DROP은 편집, CLUB은 관계, SNS는 캐릭터, 실험 기능은 이스터에그다.

## 3. DROP의 정의

항공권이 싸다고 모두 DROP은 아니다.

> 평소와 다른 가격이 발견되고, 티키티킷이 볼 가치가 있다고 판단한 순간 DROP이 발생한다.

일반 항공권은 상품이고, `DROP #041 후쿠오카 89,800원`은 사건이다.

### 3.1 기본 원칙

1. 공식 DROP은 하루 0~1개를 기본으로 한다.
2. 올릴 만한 표가 없으면 억지로 발행하지 않는다.
3. 정말 강한 사건이 여러 개 발생한 날만 예외적으로 추가 발행할 수 있다.
4. 메인의 ‘오늘의 DROP’에는 대표 1개만 노출한다.
5. 모든 DROP은 고유 번호와 `/drop/[번호]` 주소를 가진다.
6. 판매가 끝나도 상세 페이지를 삭제하지 않는다.
7. 일반 항공권 공유와 공식 DROP 발행은 구분한다.

### 3.2 생애주기

```text
항공권 관측
→ 이상한 가격 발견
→ DROP 후보
→ DROP 발행
→ 판매 중
→ 가격 변동 또는 소진
→ 판매 종료
→ 기록으로 보존
```

구현 상태 이름은 우선 다음 네 개를 사용한다.

```text
DRAFT → LIVE → PRICE_CHANGED → ENDED
```

- 같은 항공권의 가격이 바뀌면 기존 DROP의 상태와 기록을 갱신한다.
- 캐시에서 사라지거나 예약이 불가능해지면 ENDED로 전환한다.
- 종료 후 다시 발생한 별개의 기회는 새 DROP 번호를 받는다.
- 발행 당시 가격·조건은 덮어쓰지 않고 스냅숏으로 보존한다.

## 4. DROP 하나가 콘텐츠 원본이다

`/drop` 페이지보다 개별 DROP이 먼저다. 예를 들어 `DROP #041` 하나가 다음 채널의 원본이 된다.

```text
DROP #041
├─ 메인의 오늘의 DROP 카드
├─ /drop 아카이브
├─ /drop/041 상세 페이지
├─ Threads 게시물
├─ 네이버 블로그 글
├─ 카카오톡 OG 이미지
├─ 앱푸시·메일 알림
└─ 판매 종료 후 검색 가능한 기록
```

채널마다 항공권 정보를 따로 다시 작성하지 않는다. 한 DROP 원본에서 각 채널에 필요한 형식으로 출력한다.

### 4.1 채널별 역할

- 메인: 대표 DROP 1개를 짧고 정확하게 노출
- DROP 상세: 사건의 내용과 선정 근거를 함께 제공
- Threads: 친구에게 먼저 보내고 싶은 한 문장
- 블로그: 가격·일정·조건·대안을 더 자세히 설명
- 카카오톡: 짧은 문구, 짧은 링크, OG 이미지
- 알림: 발생 사실과 행동에 필요한 최소 정보
- 종료 페이지: 기록과 현재 가능한 대안

## 5. 아이디어 배치 기준

| 아이디어 | 주된 역할 | 기본 위치 | 메인 노출 |
|---|---|---|---|
| 오늘의 DROP | 공식 가격 사건 | `/drop/[번호]` | 대표 1개 |
| 가격 미친놈 지수 | DROP 판단을 설명하는 척도 | DROP 상세·허브 | 공식 DROP에만 제한적으로 |
| 이번 주 가장 망한 항공권 | 주간 편집 콘텐츠 | DROP 허브·Threads·블로그 | 기본 미노출 |
| 전설의 DROP 박물관 | 가격 기록·신뢰 | DROP 아카이브 | 미노출 |
| 연말 DROP AWARDS | 연간 편집 콘텐츠 | DROP·블로그·SNS | 행사 기간만 |
| 목적지 없는 버튼 | 핵심 Discovery 기능 | 메인 보조 진입·DROP 입구·종료 대안 | 조용한 보조 버튼 |
| 내일 출국 클럽 | D-0~D-3 발견 코너 | DROP 허브 또는 별도 발견 코너 | 필요할 때 작은 진입점 |
| TIKITIKIT CLUB | 회원·알림·기록 | 별도 `/club` | 작은 CTA |
| 티키티킷 여권 | 개인 기록 | CLUB·내 계정 | 미노출 |
| CATCH CARD | 구매 후 공유 | CLUB·공유 기능 | 미노출 |
| 사장님 몰래보기 모드 | 바이럴 실험 | 선택형 화면 모드 | 기본 미노출 |
| 비상!!·담당자가 미쳤어요 등 | 공유·배포 문구 | Threads·카카오·알림 | 메인 본문 미사용 |

### 5.1 아직 확정하지 않은 사항

- `내일 출국 클럽`은 `TIKITIKIT CLUB`과 이름이 충돌할 수 있다. 실제 제작 전에 `내일 출국`, `72시간 안에 출국` 등으로 이름을 다시 검토한다.
- 가격 미친놈 지수의 계산식과 공개 시점은 데이터 검증 후 확정한다.
- CLUB의 유료화 여부와 독점 DROP 혜택은 별도 기획으로 남긴다.

## 6. 메인의 표현 제한

메인은 계속 정제된 신뢰 영역이어야 한다. 표현이 강한 요소는 다음 세 가지로 제한한다.

1. 오늘의 DROP 대표 카드 1개
2. 검증된 숫자를 보여주는 인사이트바
3. 목적지 없는 버튼 같은 조용한 Discovery 진입점

주간 콘텐츠, CLUB 전체 설명, 이스터에그, 강한 SNS 문구를 메인에 한꺼번에 노출하지 않는다.

메인은 다음 인상을 유지한다.

> 실제 항공권이 많고, 비교할 수 있고, 정보가 믿을 만하다.

DROP에 들어갔을 때 다음 인상이 추가되게 한다.

> 그중 이상한 표를 꽤 잘 골라낸다.

## 7. 인사이트바의 역할

인사이트바는 캐릭터를 과시하는 곳이 아니라 현재 항공권을 빠르게 해석해주는 곳이다.

### 사용하기 좋은 내용

- 동일 노선 월평균 대비 `-31%`
- 최근 60일 중 가장 낮은 가격
- 비슷한 가격은 평균 8시간 안에 종료
- 금요일 20:40 출발
- 현재 4석 남음

### 사용하지 않을 내용

- 담당자가 미쳤어요
- 가격표 응급상황
- 이번 주 가장 망한 항공권
- 사장님 몰래보기

인사이트바의 문구는 반드시 실제 데이터로 입증할 수 있어야 한다.

## 8. 유쾌함의 강도

DROP과 CLUB은 이름에 맞게 메인보다 확실히 유쾌해야 한다. 별도 페이지로 분리하는 이유는 진지하게 만들기 위해서가 아니라, 메인의 신뢰를 해치지 않고 각자의 캐릭터를 더 강하게 보여주기 위해서다.

| 화면 | 정보·시스템 | 캐릭터 |
|---|---:|---:|
| 메인 | 90 | 10 |
| 인사이트바 | 85 | 15 |
| DROP 상세 상단 | 50 | 50 |
| DROP 상세 정보 영역 | 80 | 20 |
| DROP 허브 | 50 | 50 |
| CLUB 첫 화면 | 45 | 55 |
| CLUB 설정·결제 영역 | 85 | 15 |
| Threads·공유 문구 | 35 | 65 |
| 사장님 몰래보기 | 20 | 80 |

페이지 전체가 같은 말투일 필요는 없다.

> 상단에서 웃기고, 아래에서 증명한다.

### 8.1 티키티킷 유머의 원칙

1. 실제 숫자를 진지하게 보여준다.
2. 상황을 한 줄로 약간 이상하게 해석한다.
3. 호들갑은 짧게 끝낸다.
4. 말장난, 아재개그, 억지 비유를 피한다.
5. 유머가 가격 근거를 대신하지 않는다.

적합한 예:

```text
전원 정지.
후쿠오카 왕복 89,800원입니다.

월평균 168,400원
오늘 89,800원
설명은 여기까지 하겠습니다.
```

판매 종료 예:

```text
아, 조금 늦었네요.
이 가격은 46분 살았습니다.
```

부적합한 예:

- 도시 이름을 이용한 말장난
- 비행기·날다 등을 이용한 익숙한 아재개그
- 모든 버튼과 설명에 농담을 추가하는 방식

## 9. 개별 DROP 상세 페이지

개별 상세는 가격 사건 하나에 집중한다. 다른 콘텐츠를 한 화면에 모두 넣지 않는다.

### 9.1 상단 — 사건처럼 보여주기

- DROP 번호
- LIVE·ENDED 상태
- 발견·마지막 확인 시각
- 친구에게 먼저 보내고 싶은 구체적인 한 문장
- 노선·날짜·가격

일반적인 브랜드 선언보다 해당 항공권에 바로 반응하는 문장을 우선한다.

```text
전원 정지.
후쿠오카 왕복 89,800원입니다.
```

### 9.2 중단 — 숫자로 증명하기

- 이 표를 DROP으로 고른 이유
- 평균가 대비 차이
- 최근 가격 순위
- 일정 활용도
- 가격 미친놈 지수 또는 그 구성 근거
- 비행 일정
- 수하물·좌석·판매처·주의사항

### 9.3 행동

- 판매 중: 판매처 확인, 친구에게 공유
- 가격 변동: 기존 가격과 현재 가격을 함께 표시
- 판매 종료: 종료 시간, 생존 시간, 현재 대안

### 9.4 상세 페이지에 넣지 않을 것

- 이번 주 가장 망한 항공권 전체 콘텐츠
- 내일 출국 전체 목록
- CLUB 전체 혜택 설명
- 사장님 몰래보기의 기본 노출

페이지 마지막에 관련 콘텐츠나 CLUB CTA를 한 줄로 연결하는 것은 가능하다.

## 10. TIKITIKIT CLUB

CLUB은 DROP의 하위 메뉴가 아니라 별도 제품이다.

```text
/drop
오늘 어떤 표가 떨어졌는지 본다.

/club
앞으로 어떤 표를 먼저 받을지 정한다.
```

### 10.1 CLUB이 맡을 수 있는 기능

- Secret DROP 먼저 보기
- 역대급 가격 알림
- 관심 노선 가격 알림
- 목적지 없는 특가 알림
- 잡은 DROP 기록
- 지난 DROP 통계
- 독점 항공권
- 티키티킷 여권

### 10.2 CLUB의 말투

CLUB은 일반적인 회원 혜택 안내보다 ‘이상한 가격을 같이 기다리는 사람들’처럼 느껴져야 한다.

```text
이상한 가격을 먼저 보는 사람들.
TIKITIKIT CLUB

좋은 표가 뜨면
남들보다 조금 먼저 부릅니다.
```

다만 설정·결제·개인정보·알림 조건 영역은 명확하고 차분하게 작성한다.

## 11. 목적지 없는 버튼과 내일 출국

### 목적지 없는 버튼

DROP의 하위 콘텐츠가 아니라 티키티킷의 Discovery 철학을 직접 구현하는 핵심 기능이다.

```text
어디든 싸면 간다
→ 지금 가장 갈 만한 표 3개
```

클릭 후 다시 여러 필터를 요구하지 않고 바로 소수의 제안을 보여준다. 메인, DROP 입구, 검색 결과 없음, 공유 항공권 판매 종료 상태 등에 재사용할 수 있다.

### 내일 출국

- D-0~D-3 항공권 중 실제로 갈 만한 소수만 선정한다.
- 모든 임박 항공권을 나열하면 일반 필터가 되므로 3개 안팎의 제안을 우선한다.
- DROP 허브의 발견 코너 또는 별도 발견 페이지로 운영할 수 있다.
- 공식 DROP 선정 기준을 만족한 항공권만 별도의 DROP 번호를 받는다.

## 12. 실행 순서

1. 제품 역할과 표현 원칙 기록 — 이 문서
2. 개별 DROP 상세 미리보기
3. DROP 데이터 모델과 상태 생애주기
4. 실제 항공권·판매 종료·대안 연결
5. `/drop` 허브
6. 메인의 오늘의 DROP 연결
7. OG·Threads·블로그 출력 연결
8. 목적지 없는 버튼과 내일 출국
9. TIKITIKIT CLUB 별도 기획
10. 가격 미친놈 지수·주간 콘텐츠·실험 기능

새 상세 화면은 운영 `/drop`을 건드리지 않고 작업별 임시 미리보기에서 검토한다. 특정 미리보기 경로를 계속 운영하지 않으며, LIVE와 ENDED 상태를 함께 확인한 뒤 승인된 구조만 운영에 적용한다.

## 13. 다른 문서와의 관계

- DROP과 CLUB의 제품 역할, 정보 구조, 화면별 캐릭터 강도는 이 문서를 따른다.
- 웹사이트의 기존 TIKIT DROP 카드 문구와 입증 조건은 현재 `docs/tikit-drop-copy-library.md`를 따른다.
- 새 DROP 상세와 허브가 확정되면 카피 라이브러리의 적용 범위를 다시 정리한다.
- Threads 문장은 현재 Threads 운영 문서와 문장 참고본을 따른다.
- 과거 DROP 실행 가이드와 원고 템플릿은 계속 사용 보류 상태다.
