## 수정한 범위

1. **땡처리 20:30 저장 경로:** 회차·여행사별로 실제 체크포인트가 허용하는
   `.local-crawler/staging` 하위의 독립 폴더를 만든다. 경로 우회, 기존 폴더
   재사용 및 입력 덮어쓰기는 거절한다. 새 파일이 빠진 설치 패키지도 거절한다.
2. **저녁 성공분 전달:** 뒤 여행사가 실패해도 앞의 검증된 결과를 반환한다.
   실패한 하위 프로세스가 캐시를 지워도 앞의 결과를 오염시키지 못한다.
   A는 기존 검증·부분 병합·공통 writer 경로를 사용한다. 접근 제한이나 종료
   불명확 이후에 다른 여행사 요청을 계속 보내지는 않는다.
3. **PC/MRT 게시 대기:** 로컬 게시 서비스가 변경 전에 명시적으로 반환한
   `PUBLICATION_BUSY`만 최대 10분 기다린다. 요청 ID/본문은 동일하다.
   네트워크 불확실, 일반 409, 인증 오류, 429, 완료된 거절은 새 실행으로
   재시도하지 않는다. 기존 원격 영수증 확인과 불명확 상태 보존을 유지한다.
4. **네이버 중단 후 안전 마감:** 현재 설치본을 기준으로 별도 패치를 만들었다.
   A·C 브라우저 종료 및 결과 저장 증거가 있고 미결 요청·명시 차단이 없는
   일시 오류일 때만 검증된 성공분을 게시한다. 운영 재확인 후 중단 회차를
   마감하고 다음 정규 회차로 연결한다. 사용량·기존 키·실패 기록은 보존하며,
   추가 조회와 오늘의 표 선정은 하지 않는다.
   중단 기록에는 실제 확인한 수만 남기고 미확인 대기 건수를 0으로 만들지
   않는다. 기존 실행 기록이 있으면 중복 기록하지 않으며, 어드민의 필수
   여행사/실행기 필드도 유지한다.

네이버 운영본은 저장소보다 앞선 병렬 실행·복구 기능을 포함한다. 따라서
저장소의 오래된 실행본으로 통째로 덮지 않고
`scripts/runtime-patches/naver-safe-partial-20260926/`에 정확한 기준 해시와
별도 패치를 보존했다. A/C 운영 설치본은 아직 변경하지 않았다.
