# 배포와 되돌리기

tikitikit.kr은 `main` 브랜치에 푸시하면 Vercel이 자동으로 재배포한다.
배포한 코드에 문제가 생겼을 때 **되돌릴 수 있는 장치**를 마련해 두었다.

---

## 평소 배포 순서

```bash
git pull                    # 1. 최신 상태 받기 (자동 크롤링 데이터 포함)
npm run build               # 2. 빌드 통과 확인
npm run deploy:mark         # 3. ★ 되돌아갈 지점 표시
git add <이번 작업 파일들>  # 4. 이번 작업만 명시적으로 스테이징
git commit -m "..."
git push                    # 4. 배포
```

**3번을 빼먹으면 되돌릴 기준점이 없다.** 코드를 고친 뒤 푸시하기 전에 항상 실행한다.
`deploy:mark`는 현재 배포된 `HEAD`만 태그하며, 작업 중인 미커밋 변경은 안전 지점에
포함하지 않는다. 따라서 다른 미완료 작업이 작업 트리에 있어도 그대로 보존된다.

`git add -A`는 사용하지 않는다. 별도 작업 파일이나 `.env*`까지 섞일 수 있으므로
이번에 배포할 파일 경로만 `git add` 뒤에 하나씩 적는다.

## 문제가 생겼을 때

### 방법 1: Vercel 즉시 롤백 (가장 빠름 — 30초)

빌드를 새로 하지 않고 **직전에 잘 돌던 배포로 즉시 되돌린다.** 사이트가 완전히
망가진 응급 상황이면 이걸 먼저 한다.

1. https://vercel.com 접속 → `flight` 프로젝트
2. **Deployments** 탭
3. 문제 없던 배포의 `⋯` 메뉴 → **Promote to Production**

> ⚠️ 이건 **배포만** 되돌린다. 저장소 코드는 그대로 문제가 있는 상태다.
> 다음 크롤링(하루 7회)이 자동 커밋하면 문제 있는 코드가 다시 배포된다.
> 따라서 **반드시 아래 방법 2까지 해야 완전히 해결된다.**

### 방법 2: 코드 되돌리기 (근본 해결)

```bash
npm run deploy:list         # 되돌아갈 지점 확인
npm run deploy:rollback     # 가장 최근 안전 지점으로 되돌리기
git push                    # 되돌린 내용 배포
```

특정 지점을 지정하려면:

```bash
npm run deploy:rollback safe/20260811-1539
```

## 이 장치가 지키는 원칙

**1. 항공권 데이터는 되감지 않는다**

`data/` 폴더는 GitHub Actions가 하루 7회 자동 갱신한다. 코드를 되돌리면서
데이터까지 과거로 되돌리면 사이트에 옛날 항공권이 뜨게 된다.
그래서 롤백은 **코드만** 되돌리고 `data/`는 최신 상태로 둔다.

**2. 이력을 지우지 않는다 (그리고 되돌리기가 실패하지 않는다)**

`git reset --force`로 커밋을 없애지 않고, 되돌리는 커밋을 새로 하나 쌓는다.
안전 지점의 코드를 그대로 덮어쓰는 방식이라 중간에 쌓인 대용량 데이터
커밋과 **충돌 없이** 항상 되돌아간다 — 안전망 자체가 실패하면 안 되기 때문이다.
되돌리기도 커밋 하나이므로 다시 취소할 수 있다.

**3. 되돌리기도 취소할 수 있다**

`npm run deploy:rollback`은 로컬에만 커밋하고 푸시는 하지 않는다.
결과를 확인한 뒤 직접 `git push` 해야 배포된다. 마음이 바뀌면:

```bash
git reset --hard HEAD~1     # 되돌리기 취소 (푸시 전에만)
```

## 명령어 요약

| 명령어 | 하는 일 |
|---|---|
| `npm run deploy:mark` | 배포 전 안전 지점 표시 (태그 생성 + 푸시) |
| `npm run deploy:list` | 저장된 안전 지점 목록 |
| `npm run deploy:rollback` | 최근 안전 지점의 코드로 되돌리기 |
| `npm run deploy:rollback <태그>` | 지정한 안전 지점으로 되돌리기 |

안전 지점은 `safe/날짜-시각` 형식의 git 태그로 저장된다 (예: `safe/20260811-1539`).
