# 티키티킷 리디자인 메인 교체 체크리스트

새 디자인을 기존 `/` 메인으로 교체할 때 기능이 줄거나 검색 노출이 끊기지 않도록 확인하는 문서다.

## 교체 전 완료

- 6개 여행사 항공권 로드, 로딩·오류·빈 결과 화면
- 30분 자동 새로고침과 5분 이상 지난 화면 재진입 시 최신 데이터 확인
- 출발지·도착 지역·날짜·가격·여행사·항공사 필터
- 필터·검색·정렬·상세 항공권의 URL 상태 보존
- 현재 운영 추천순과 같은 비교가 구간, 품질 60%·순환 40%, 노선 분산
- 운영 `todayPickId`를 기본으로 쓰되 이후 더 파격적인 표가 들어오면 즉시 교체하는 TIKIT DROP 1개
- 상단 특가 경보가 보일 때 TIKIT DROP 카드와 반드시 같은 항공권을 가리킴
- 여행사별 정확한 예약 링크와 탑승 인원 반영
- 네이버 동일 일정 비교와 다공항 마이리얼트립 비교 안전장치
- 가격·예약 오류 신고, 항공권 공유, 내려간 공유 항공권의 목적지 대체 결과
- 비회원 찜, 로그인 후 기기 찜 전체 병합, 계정별 찜·최근 본 표·검색 조건 동기화
- 다른 탭에서 계정이 바뀌어도 이전 탭의 저장·삭제 요청이 새 계정에 적용되지 않음
- 전체 특가 알림, 노선 가격 알림, 알림 수정·해제·테스트
- 문의, 이용약관, 개인정보처리방침, 제휴·예약 주체 안내
- 모바일 320px·390px와 PC 1440px 자동 핵심 흐름 점검
- 320px에서 로고가 줄바꿈되지 않고 특가 알림·계정 버튼이 화면 밖으로 밀리지 않음
- 작은 날짜·시간·상태·버튼 글자가 흰 배경 및 브랜드 배경에서 충분히 읽힘
- 로그인·계정 화면의 강조색과 포커스 표시가 리디자인의 레드 계열 변수와 일치함
- 한 화면에 로고가 여러 번 있어도 SVG 그라데이션 `id`가 중복되지 않음
- 공개 가격 이력은 현재 노선의 최근 60일 최소 필드만 제공
- 정적 도시 페이지도 메인과 같은 만료·편도·고가 비교·중복 제거 기준 사용

## 배포 전 데이터베이스

코드보다 아래 Supabase 마이그레이션을 먼저 적용한다. 적용 전 코드를 배포하면 로그인
인증번호 검증과 조건형 알림 발송이 실패하도록 안전하게 막혀 있다.

1. `20260826_create_price_alerts.sql`
2. `20260826_harden_auth_verification_and_contact_rate_limits.sql`
3. `20260826_schedule_rate_limit_cleanup.sql` (선택적 pg_cron 정리 작업이며 실패해도 핵심 RPC와 분리됨)

적용 뒤 `claim_price_alert_delivery`, `tikitikit_take_rate_limit`,
`tikitikit_verify_auth_code` RPC가 PostgREST에서 호출되는지 확인한다. 마이그레이션이
스키마 캐시 갱신까지 요청하지만, 실제 REST 호출 확인 전에는 새 코드를 배포하지 않는다.

## 메인 교체 시

1. `src/app/page.tsx`에서 기존 `Dashboard` import를 `RedesignDashboard`로 교체한다. 현재는 아직 운영 메인을 바꾸지 않는다.
2. 페이지 구조는 아래처럼 **하나의 `main`만** 사용한다. `HomeCityLinks`를 리디자인 바깥의 형제 요소로 두면 푸터 뒤에 붙으므로 반드시 자식으로 전달한다.

   ```tsx
   <main>
       <RedesignDashboard>
           <HomeCityLinks />
       </RedesignDashboard>
   </main>
   ```

3. `RedesignDashboard`가 `rootAs="div"`와 `beforeFooter={children}`를 전달하는지 확인한다. 이 구조로 서버 렌더링 도시 링크가 리디자인 푸터 **바로 앞**에 들어간다.
4. 실제 DOM에서 `main`이 정확히 1개인지, `HomeCityLinks` 다음 요소가 서비스 푸터인지 확인한다. 도시 링크는 검색엔진과 AI가 현재 가격을 읽는 통로이므로 숨기거나 클라이언트 전용으로 바꾸지 않는다.
5. `/preview/mobile-redesign`은 최소 1주일 유지해 문제 비교와 되돌리기에 사용한다. 미리보기 경로는 기본 `main` 루트를 계속 사용한다.
6. `npm run test:redesign`, `npx tsc --noEmit`, `npm run build`를 통과시킨다.
7. `npm run deploy:mark`로 안전 지점을 남긴 뒤 이번 교체 파일만 커밋하고 `main`에 푸시한다.

## 배포 직후 실제 기기 확인

아래 항목은 실제 이메일·브라우저 알림 권한이 필요해 배포 뒤 한 번만 직접 확인한다.

- 이메일 인증번호 수신과 로그인 완료
- 휴대폰에서 특가 알림 등록 후 테스트 알림 수신
- 6개 여행사별 대표 항공권 1개씩 예약 페이지 착지
- 네이버 비교·여행사 예약·공유·알림 등록 이벤트가 GA4에 들어오는지 확인
- 320px 실제 기기 또는 개발자 도구에서 헤더 로고·버튼이 한 줄을 유지하는지 확인
- 계정·필터·상세·문의 화면을 열어 작은 보조 문구와 선택 버튼의 대비를 확인
- 페이지 소스에서 도시별 링크가 서비스 푸터보다 먼저 렌더링되는지 확인

문제가 있으면 `npm run deploy:rollback`으로 코드만 되돌리고 최신 항공권 데이터는 유지한다.
