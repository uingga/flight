# 티키티킷 리디자인 메인 교체 체크리스트

새 디자인을 기존 `/` 메인으로 교체할 때 기능이 줄거나 검색 노출이 끊기지 않도록 확인하는 문서다.

## 교체 전 완료

- 6개 여행사 항공권 로드, 로딩·오류·빈 결과 화면
- 5분 자동 새로고침과 화면 재진입 시 최신 데이터 확인
- 출발지·도착 지역·날짜·가격·여행사·항공사 필터
- 필터·검색·정렬·상세 항공권의 URL 상태 보존
- 현재 운영 추천순과 같은 비교가 구간, 품질 60%·순환 40%, 노선 분산
- 운영 `todayPickId`를 사용하는 TIKIT DROP 1개 고정
- 여행사별 정확한 예약 링크와 탑승 인원 반영
- 네이버 동일 일정 비교와 다공항 마이리얼트립 비교 안전장치
- 가격·예약 오류 신고, 항공권 공유, 내려간 공유 항공권의 목적지 대체 결과
- 비회원 찜, 로그인 후 찜·최근 본 표·검색 조건 동기화
- 전체 특가 알림, 노선 가격 알림, 알림 수정·해제·테스트
- 문의, 이용약관, 개인정보처리방침, 제휴·예약 주체 안내
- 모바일 390px·PC 1440px 자동 핵심 흐름 점검

## 메인 교체 시

1. `src/app/page.tsx`의 `Dashboard`를 `RedesignDashboard`로 바꾼다.
2. 서버에서 렌더링되는 `CityLinks`는 그대로 둔다. 검색엔진과 AI가 도시별 현재 가격을 읽는 통로다.
3. `/preview/mobile-redesign`은 최소 1주일 유지해 문제 비교와 되돌리기에 사용한다.
4. `npm run test:redesign`과 `npm run build`를 통과시킨다.
5. `npm run deploy:mark`로 안전 지점을 남긴 뒤 이번 교체 파일만 커밋하고 `main`에 푸시한다.

## 배포 직후 실제 기기 확인

아래 항목은 실제 이메일·브라우저 알림 권한이 필요해 배포 뒤 한 번만 직접 확인한다.

- 이메일 인증번호 수신과 로그인 완료
- 휴대폰에서 특가 알림 등록 후 테스트 알림 수신
- 6개 여행사별 대표 항공권 1개씩 예약 페이지 착지
- 네이버 비교·여행사 예약·공유·알림 등록 이벤트가 GA4에 들어오는지 확인

문제가 있으면 `npm run deploy:rollback`으로 코드만 되돌리고 최신 항공권 데이터는 유지한다.
