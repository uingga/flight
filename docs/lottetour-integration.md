# 롯데관광 할인항공권 연동

## 확인한 원본과 수집 계약

- 공개 목록: https://m.lottetour.com/discountAir
- 2026-09-21 HTML 1회, 공개 조회 API 3회만 확인했다. 예약·로그인·결제 요청은 하지 않았다.
- `disPriceList` → 각 `blockId`의 `disPriceLine` → 날짜별 `disPriceLow` 순서. 모두 페이지가 사용하는 조회용 POST이며 매개변수는 query string이다.
- 응답의 `result: true`와 내부 JSON 문자열을 검증한다. 목록의 최저가 대신 상세의 성인 총액(`priceAdt`)을 사용하고 항공료·유류·세금·수수료 합계와 대조한다.
- 왕복 일정은 `disSchedule`의 `arrvYn=N/Y`로 구분한다. 실제 응답은 귀국편이 먼저이며, 상세 `retnDt`는 비어 있었다. 여행 일수로 귀국일을 추정하지 않는다.
- 직항 왕복 2구간, 노선·공항·출도착 날짜·시간·편명·상품 식별자가 일치하는 결과만 수집한다. 미지원 형식이나 불완전 응답은 부분 반영하지 않는다.
- 확인 당시 부산–후쿠오카, 9월 23일–25일, ZE941/ZE944, 성인 왕복 380,000원, 잔여 10석. 이는 확인 시점의 표이며 현재 재고를 보장하지 않는다.
- 공개 요금 규정은 최소 성인 2명이다. `minPax=2`, 좌석 2개 미만 제외, 상세에 성인 조건과 출발 확정 확인 안내를 표시한다.

## 예약 이동

실제 예약 시작은 승객·요금 값이 담긴 POST 폼(`/disCountBooking/step01`)이다. GET 상품 주소를 임의로 만들지 않는다. 버튼은 공개 할인항공 목록과 해당 노선 앵커(`#tr__<blockId>`)로 연결하며, 이용자가 노선·출발일을 다시 선택한다. 앵커는 날짜 자동 선택이나 예약 확정 기능이 아니다.

## 기존 수집과 연결

- `scripts/crawl-all.ts`의 일반 소스 `lottetour`로 추가. 기존 일반 회차를 따르고 예약 시각·워크플로를 추가하지 않는다.
- 요청은 직렬, 요청 사이 1.5–2.5초, 20초 timeout, 회차 최대 80회, 재시도 없음. 401/403/429/CAPTCHA는 공통 소스 차단 회로에 전달된다.
- 0건·오류·부분 조회는 공통 기존 데이터 보존 규칙을 따른다. 오래된 가격은 기존 일반 소스 유효기간으로 감춘다.
- PC 대체 수집 대상은 추가하지 않았다. PC 실행기·스케줄러·승인 패키지·원장·네이버 할당량은 변경하지 않는다.
- 네이버 후보 소스 목록만 확장하며, 기존 차단·예산·회차 판단은 유지한다. 설치된 PC 프로그램은 이 저장소 변경만으로 갱신되지 않으므로 운영 반영 시 기존 유지보수 절차를 따른다.
- `lottetour-<evtCd>`로 안정된 ID를 만들고 공통 재등장 이력에 연결한다. 같은 가격으로 재등장하면 최초 발견일 유지, 실제 1만원 이상 새 최저가 하락 시 인사이트 이력을 남긴다.
- 여행사 필터, API 소스 집계, 관리자 수집/항공권 목록, 공유, 최근 본 표, 저장한 항공권, 신고 처리에 소스를 연결했다.

## 운영 적용 전

이 변경은 구현·오프라인 검증 준비본이다. 운영 캐시, DB, 설치된 수집 프로그램을 수정하지 않았으며 배포하지 않았다.

신고 기능의 source CHECK 허용값을 늘리는 `supabase/migrations/20260921_add_lottetour_source.sql`을 웹사이트 활성화 전에 적용해야 한다. 기존 행·RLS·권한은 바꾸지 않는다. 배포는 사용자 승인 후 `docs/DEPLOY.md`의 현재 보호된 진입점으로 진행한다.

## 검증

- `npm run test:lottetour`: 공개 응답 재생·금액/시간/좌석·부분 실패·차단·요청 상한·예약 주소·재등장·신선도 18개 통과. 실제 외부 요청 0회.
- 공통 재등장/가격하락 테스트에 롯데관광도 포함되어 통과.
- 운영 Next.js 빌드와 타입검사 통과.
- 네이버 정책/회차 테스트 30개 통과. 변경 전 HEAD에서도 실패하던 `upstream_pending` 테스트는 현재 06:17 KST 이전 시각으로 fixture를 정정했다. 운영 시각·정책은 바꾸지 않았다.
- 별도 수집 진입점(`crawl-all`)·롯데관광 테스트 타입검사 통과. 더 넓은 보조 스크립트 검사에서 예약 점검 스크립트의 `never.status`, 생애주기 기록의 `ended_estimated` 비교 타입 오류가 발견됐으나 해당 부분은 변경 전과 동일하며 이번 범위에서 고치지 않았다.
- 전체 크롤을 실제 실행하거나 추가 네이버 조회를 하지 않았다. 배포 후 첫 정규 회차의 실행·게시·API 노출 확인은 아직 남아 있다.
