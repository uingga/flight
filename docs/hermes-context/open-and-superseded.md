# Hermes 인수인계 — 열린 과제·보관 브랜치·폐기된 방향

> 기준 시점: 2026-09-04 KST
>
> 자동 실행 목록이 아니다. 새 작업을 시작할 때 중복 구현과 과거안 복원을 막기 위한 지도다.

## 가장 먼저 남아 있는 인수인계 작업

### 1. Hermes 실행 환경

- Hermes 프로젝트 `tikitikit`은 현재 저장소를 primary folder로 연결했고, 인수인계 문서 읽기 시험을 통과했다.
- 메인 PC에서 설치된 `hermes.exe` 런처는 점검 당시 `ModuleNotFoundError: hermes_cli`로 실행되지 않았다.
- 설치 소스와 venv를 통하면 CLI가 정상 동작했고, gateway도 별도 프로세스로 실행 중이었다.
- 따라서 런처 결함을 Hermes 프로젝트·gateway 전체 장애로 확대 해석하지 않는다.
- 설치를 임의로 덮어쓰기 전에 Desktop, gateway, CLI 각각의 상태와 공식 설치 경로를 구분해 진단한다.
- 티키티킷 전체 작업은 메인 Hermes가 맡고, 크롤러 PC 봇은 실행 전용으로 연결한다.

### 2. 땡처리 브라우저 수집 검증

- `codex/ttang-browser-runner`의 원격 실행자 코드는 작성·푸시됐다.
- 최신 코드로 크롤러 PC 파일럿을 한 번 성공시켜야 한다.
- `scheduleAct.do`의 `E001` 원인, `hanaFareId` 일치, 시간·좌석 반영, 정상 종료, staging 요약을 확인한다.
- 성공 전에는 `main` 병합이나 운영 자동화를 하지 않는다.

### 3. 다른 Codex 채팅 인수인계

기존 여섯 채팅의 원문을 모두 영구 문서로 만들지 않는다. 이번 문서들은 채팅별 임시 요약과 실제
코드·브랜치 대조를 통해 주제별로 합친 결과다. Hermes가 충분히 이해하는지 확인하기 전까지 기존
Codex 채팅을 삭제하거나 보관 해제하지 않는다. 1차 읽기 시험은 통과했으며, 실제 첫 제품 작업과
첫 원격 크롤러 지시까지 성공한 뒤 이전 채팅의 보관 여부를 판단한다.

## 현재 보류 또는 미완성

### 2026-09-04 아이디어 채널에서 나온 첫 화면 개선안 (기록만, 미실행)

배경: 첫 화면이 카드 나열뿐이라 상단에 새 지역·가격이 없으면 바로 이탈한다는 사용자 관찰.
이 중 5번(DROP 히어로)만 채택 → `current-product.md` "DROP 히어로" 참고. 나머지는 미결.

1. `지난 방문 이후` 요약 띠 — 마지막 방문 시각을 브라우저에 저장하고 "새 항공권 N · 더 싸진 M · 종료 K" 한 줄. 0이면 다음 수집 시각을 솔직히 표시.
2. `오늘 새로 나옴` 가로 레일 — 최근 수집에서 처음 등장한 노선만 상단 6~8장. 지금은 카드 사이 인사이트바에 묻혀 있음.
3. 카드별 2주 최저가 스파크라인 + `30일 중 최저` 배지 — `price-history.json`으로 가능. 장기 인사이트 보류와 별개의 짧은 노선 흐름.
4. 예산 슬라이더(20·30·50만원)로 갈 수 있는 도시가 켜지는 그리드/지도.
5. (채택) TIKIT DROP 히어로 — 최근 DROP 목록 없음, 빈 날 미표시, 미리보기 승인 후 반영.

- 공개 특가 알림: 구현은 남아 있지만 진입점은 숨김. 계정별 발송 이력과 기기 복구까지 검증 후 재개
- TIKIT DROP 영구 상세·아카이브·생애주기: 제품 전략은 있으나 구현 범위 미확정
- CLUB: 회원·관계 레이어라는 방향만 있고 현재 만들 제품으로 확정되지 않음
- `이 여행의 리듬`: 도시 분위기 영상 콘텐츠 실험, 구현하지 않음
- 기후 맥락 배지: 근거 데이터와 표시 방식 검증 전 아이디어
- 여행 취향 선택: `휴양 / 먹으러 가기 / 아이와 함께` 분류 근거 검증 전 아이디어
- 장기 가격 인사이트: 데이터 축적과 품질 확인 전 공개 판정 보류
- 낯선 도시 모바일 비주얼: 운영 반영 완료 (`WeeklyDiscoveryInsight`, 홈 `RedesignDashboard` 안에서 노출). WIP 브랜치는 폐기 대상

## 명시적으로 폐기·대체된 방향

- 메인 상단의 과한 롤링 경보·가격 붕괴 표현
- 인사이트바의 `공항 바꾸고 SAVE`, `가격 붕괴 감지`, `가격 좋음 · 시간 험함`
- 여행사 이름을 직접 내세운 평균가 비교 문구
- 알림을 계정 이력 없이 공개하는 방식
- 모두투어 중국 `전체` 한 번 수집
- 모두투어 실패 시 PC 자동 접속
- 네이버 20:30 폴백
- 네이버 비교가를 무조건 24시간 만료시키는 규칙
- 추천순의 무작위 재배열
- 비싼 항공권을 가격만으로 일괄 제거하는 규칙
- 인터파크 빠른 출발 가격을 월별 기준가에 다시 합치는 방식
- `이 여행의 리듬`을 항공편 출도착 시간의 좋고 나쁨을 평가하는 기능으로 만드는 방향
- 도시 콘텐츠를 항공권 상세 하단에 항상 연결하는 방식
- 모든 과거 채팅을 채팅별 영구 문서로 복제하는 방식
