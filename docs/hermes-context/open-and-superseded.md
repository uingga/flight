## 가장 먼저 남아 있는 인수인계 작업

### 1. Hermes 실행 환경

- Hermes 프로젝트 `tikitikit`은 현재 저장소를 primary folder로 연결했고, 인수인계 문서 읽기 시험을 통과했다.
- 메인 PC에서 설치된 `hermes.exe` 런처는 점검 당시 `ModuleNotFoundError: hermes_cli`로 실행되지 않았다.
- 설치 소스와 venv를 통하면 CLI가 정상 동작했고, gateway도 별도 프로세스로 실행 중이었다.
- 따라서 런처 결함을 Hermes 프로젝트·gateway 전체 장애로 확대 해석하지 않는다.
- 설치를 임의로 덮어쓰기 전에 Desktop, gateway, CLI 각각의 상태와 공식 설치 경로를 구분해 진단한다.
- 티키티킷 전체 작업은 메인 Hermes가 맡고, 크롤러 PC 봇은 실행 전용으로 연결한다.

### 2. 땡처리 브라우저 수집 검증

- `codex/ttang-browser-runner`의 원격 실행자 코드는 작성·푸시됐다.
- 최신 코드로 크롤러 PC 파일럿을 한 번 성공시켜야 한다.
- `scheduleAct.do`의 `E001` 원인, `hanaFareId` 일치, 시간·좌석 반영, 정상 종료, staging 요약을 확인한다.
- 성공 전에는 `main` 병합이나 운영 자동화를 하지 않는다.

### 3. 다른 Codex 채팅 인수인계

기존 여섯 채팅의 원문을 모두 영구 문서로 만들지 않는다. 이번 문서들은 채팅별 임시 요약과 실제
코드·브랜치 대조를 통해 주제별로 합친 결과다. Hermes가 충분히 이해하는지 확인하기 전까지 기존
Codex 채팅을 삭제하거나 보관 해제하지 않는다. 1차 읽기 시험은 통과했으며, 실제 첫 제품 작업과
첫 원격 크롤러 지시까지 성공한 뒤 이전 채팅의 보관 여부를 판단한다.

### 기후 맥락 배지

항공권에 이미 포함된 여행 날짜와 도시별 월간 기후 데이터를 대조해 카드에 계절 맥락을 자동으로 표시하는 아이디어를 보관한다.

```text
지금 건기 ☀️
우기 주의
```

단순한 날씨 정보가 아니라 `다낭 15만 원이 왜 이렇게 싸지?` 같은 사용자의 의문에 사이트가 먼저 답하게 하는 장치다. 기본 구현은 검증된 `도시 × 12개월` 기후 데이터와 항공권 일정 판정 함수로 구성한다.

- 월간 기후 분류는 일기예보처럼 표현하지 않고 계절적 경향으로만 설명한다.
- 여행 일정이 월 경계를 넘으면 전체 체류 날짜를 기준으로 판정한다.
- 도시별 근거가 충분한 경우에만 표시하고, 국가 단위 정보를 임의로 도시 전체에 적용하지 않는다.
- 기후 배지는 가격이 싼 원인으로 단정하지 않고 가격을 해석할 때 함께 볼 맥락으로 제공한다.

### 이 여행의 리듬

항공권의 출발일·귀국일과 출도착 시간을 실제 여행의 흐름으로 번역해 보여주는 콘텐츠 아이디어다. 같은 `4박 5일`이라도 늦은 도착, 온전히 사용할 수 있는 날, 귀국편 시간에 따라 여행 경험이 달라진다는 점을 설명한다.

대표 문구는 다음과 같다.

> 같은 4박 5일도, 여행의 리듬은 다르니까.

임의의 점수를 붙이기보다 확인된 날짜와 시간을 짧은 문장과 타임라인으로 보여주는 방향을 우선한다.

#### 같은 도시, 다른 리듬 매거진

같은 도시와 같은 여행 기간을 서로 다른 사람들이 완전히 다르게 보낸 실제 기록을 나란히 싣는 인터뷰·여행기 시리즈다.

```text
같은 도시, 다른 리듬
오사카 4박 5일을 세 사람이 보내는 세 가지 방식
```

한 사람은 먹는 일정, 한 사람은 느긋한 휴양, 한 사람은 아이와 함께한 일정처럼 각자의 하루 흐름과 선택을 비교한다. `같은 4박 5일도, 여행의 리듬은 다르니까.`라는 태그라인을 실제 사람의 기록으로 증명하며, 특정 항공권 판매와 직접 연결하지 않는 회차도 티키티킷의 발견 관점과 브랜드 자산으로 축적한다.

- 가상의 후기처럼 작성하지 않고 실제 인터뷰·제보·검증된 여행 기록만 사용한다.
- 누가 더 잘 여행했는지 평가하지 않고 서로 다른 리듬을 동등하게 보여준다.
- 날짜별 관광지 목록보다 왜 그렇게 시간을 썼는지와 그 사람의 선택을 중심으로 편집한다.
- 항공권 CTA는 콘텐츠의 필수 요소로 두지 않고, 현재 같은 도시의 항공권이 있을 때만 조용히 연결한다.

#### 도시별 리듬 플레이리스트

도시의 특정 시간대와 여행 장면을 음악으로 큐레이션하는 콘텐츠 시리즈다.

```text
방콕의 밤 리듬
후쿠오카의 아침 리듬
```

항공권을 당장 예약하지 않는 주에도 도시의 분위기를 느끼러 다시 방문할 이유를 만든다. 단순히 도시 이름을 붙인 음악 목록이 아니라 `새벽 시장으로 가는 시간`, `강변의 밤`, `문 연 가게를 찾아 걷는 아침`처럼 시간대와 장면이 분명한 편집을 우선한다.

- 플레이리스트 자체로 완결되는 콘텐츠로 만들고 항공권 구매를 전제로 하지 않는다.
- 현재 같은 도시의 항공권이 있을 때만 하단에 조용히 연결한다.
- 음악 파일을 직접 호스팅하지 않고 정식 스트리밍 서비스의 공개 플레이리스트·임베드·링크를 사용한다.
