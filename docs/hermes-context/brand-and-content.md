# Hermes 인수인계 — 브랜드·콘텐츠 현재 맥락

> 기준 시점: 2026-09-04 KST
>
> 문장을 고정하는 규칙집이 아니라 현재 사용자의 취향과 최근 결정을 설명하는 스냅숏이다.
> 실제 항공권과 최신 사용자 피드백에 맞춰 매번 새로 판단한다.

## 브랜드가 해야 하는 일

티키티킷은 ‘여행지를 검색하는 도구’에만 머무르지 않고 ‘오늘 무엇이 나왔는지 보러 오는 곳’을
지향한다. 그러나 이 철학을 비슷한 문장으로 계속 반복하면 사용자는 금방 익숙해지고 콘텐츠가
자기복제처럼 보인다.

브랜드 설명보다 다음을 먼저 보여준다.

- 실제로 발견한 항공권
- 정확한 가격·날짜·여행 기간·판매처
- 왜 지금 눈에 띄는지 보여주는 구체적인 숫자나 장면
- 티키티킷이 그 항공권을 보고 한 짧은 반응

## 사용자에게 보이는 용어

- 정보·설명·어드민에서는 `항공권`을 기본으로 쓴다.
- 짧고 가벼운 헤드라인이나 반응에서는 `티켓`을 쓸 수 있다.
- 사용자는 대화에서 자연스럽게 `표`라고 말하지만, 웹사이트와 공식 콘텐츠가 이를 기본 명칭으로 따라 쓰지 않는다.
- 다른 여행사 이름과 직접 비교하는 문구는 꼭 필요한 사실 설명이 아니면 전면에 내세우지 않는다.

## 문장과 유머의 온도

현재 가장 가까운 방향은 다음과 같다.

> 흥분은 하되 호들갑은 짧게. 설명은 숫자로.

- 회사 말투보다 사람이 발견하고 공유하는 말투를 선호한다.
- 억지 말장난과 익숙한 여행 광고 문구를 피한다.
- 모든 버튼과 설명에 농담을 넣지 않는다.
- 메인은 차분하고 신뢰할 만하게, DROP과 SNS는 더 유쾌하게 만들 수 있다.
- 강한 한 문장 뒤에는 가격·일정·좌석·비교 근거를 분명히 둔다.
- ‘가격이 먼저 여행을 만든다’는 철학을 매번 말만 바꿔 반복하지 않는다.
- 과거 후보 문구에서 도시와 가격만 바꿔 재사용하지 않는다.

## 채널별 역할

- 웹사이트 메인: 빠르게 비교하고 믿을 수 있는 정보
- TIKIT DROP 상세: 한 항공권 사건과 선정 근거
- Threads: 친구에게 먼저 보내고 싶은 첫 반응
- 네이버 블로그: 가격 흐름, 일정, 조건과 맥락을 필요한 만큼 설명
- 공유 카드: 전달받은 사람이 바로 이해할 최소 정보
- 알림: 지금 확인해야 하는 사실과 행동만 남김

같은 항공권을 여러 채널에서 다루더라도 사실만 공유하고 문장은 채널마다 새로 쓴다.

## Threads

- 예약 가능한 실제 항공권을 게시 직전에 다시 확인한다.
- 정해둔 문장을 순환 게시하지 않는다.
- 가격·도시만 바꾼 템플릿을 반복하지 않는다.
- 게시 빈도를 채우기 위해 가치가 약한 항공권을 억지로 올리지 않는다.
- 게시물만큼 댓글과 답글의 사람다운 반응도 중요하다.
- 판매 종료를 알리는 후속 글을 자동으로 만들 필요는 없다. 종료와 대안은 사이트가 우선 처리한다.

브랜딩 채팅에 다수의 후보 문장이 남아 있지만, 이들은 자동 발행 재고가 아니다. 실제 항공권과
상황이 맞을 때 표현의 리듬만 참고한다.

## 네이버 블로그와 발행 기록

2026-09-01 발행된 푸꾸옥 DROP 글의 실제 제목·본문·UTM·반응을 기록하는
`docs/content-publication-log.md` 초안이 `codex/content-drafts-wip-20260903`에 보존돼 있다.
이미지와 원고 초안도 같은 브랜치에 있다. 아직 `main`에 합쳐지지 않았으므로 전체 브랜치를
자동 병합하지 말고, 발행 기록 문서만 최신 사실을 다시 확인해 가져올지 결정한다.

발행 기록은 초안을 쌓는 곳이 아니라 실제 발행물과 성과를 연결하는 곳이어야 한다.

- 발행 시각·주소·원문·소개한 항공권
- 조회·공감·댓글 등 채널 반응과 확인 시각
- UTM 유입 → 상세 열람 → 예약 페이지 이동
- 판매 종료 뒤에도 콘텐츠가 대안 항공권 탐색으로 이어지는지

## `이 여행의 리듬` 실험

이 아이디어는 아직 운영 기능이 아니다. 최신 대화에서 사용자가 정정한 방향은 항공편 시간표를
평가하는 기능이 아니라 도시 분위기를 전달하는 독립 콘텐츠다.

- 고정 제목: `이 여행의 리듬`
- 도시·시간대·장면을 두 줄로 설명
- CTA 예: `▶ 방콕의 밤에 들어가기`
- 현재 항공권이 있으면 작은 보조 링크만 연결
- 항공권이 없어도 콘텐츠 자체는 유지
- 초기 후보: 방콕의 밤, 후쿠오카의 아침, 오사카의 늦은 오후
- Spotify 목록보다 약 1시간짜리 연속 YouTube 영상 방향이 더 적합하다는 논의가 있었다.

Suno 등 생성형 음악을 실제 상업 콘텐츠에 사용할 때는 제작 시점의 요금제·상업 이용·표시 의무를
다시 확인한다. 특정 아티스트의 스타일을 복제하지 않고, 여러 장면으로 편집한 고유 결과물을 만든다.

`codex/product-ideas-wip-20260903`의 전략 문서에는 이전 방향인 ‘항공편 시간표를 여행 리듬으로
번역’하는 내용이 포함돼 있다. 이 부분은 최신 결론이 아니므로 브랜치를 통째로 병합하지 않는다.

## 도시 콘텐츠 실험

- `이번 주 낯선 도시`는 실제로 갈 수 있지만 아직 익숙하지 않은 도시를 한 주에 한 곳 깊게 소개하는 방향이다.
- 메인 항공권과 억지로 연결하거나 관련 글을 상세 하단마다 붙이지 않는다.
- 도시 주제가 실제로 쓸 내용과 근거가 있는지 먼저 조사한 뒤 제작한다.
- 사용자가 요청하지 않은 도시 시리즈를 알아서 대량 제작하지 않는다.

## 성과를 볼 때

초기에는 숫자를 많이 만드는 것보다 콘텐츠가 실제 행동을 만들었는지 본다.

- 콘텐츠별 유입자
- 상세 열람률
- 예약 페이지 이동률
- 공유와 저장은 별도 행동으로 집계
- 평균 체류시간과 참여 유입률
- 7일·30일 재방문

항공권 노출 수가 많아서 관심이 커 보이는 것과 도시 자체에 대한 선호를 구분한다. 도시별 관심을
볼 때는 노출당 상세 열람·저장·공유·예약 이동을 함께 보고, 표본 수를 표시한다.

## 콘텐츠를 만들기 전에 확인할 것

1. 이 콘텐츠가 어느 채널용인지
2. 실제 항공권의 가격·일정·예약 가능 여부가 최신인지
3. 이미 했던 말의 순서만 바꾼 것은 아닌지
4. 사용자가 확정한 문구와 단순 후보를 구분했는지
5. 운영자가 혼자 감당할 수 있는 제작·측정 방식인지
