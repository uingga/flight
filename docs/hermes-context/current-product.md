# Hermes 인수인계 — 제품·UI 현재 맥락

> 기준 시점: 2026-09-04 KST
>
> 현재 상황을 설명하는 스냅숏이다. 사용자의 최신 지시와 실제 코드가 우선한다.

## 제품의 중심

티키티킷은 목적지와 날짜를 먼저 정해 검색하는 서비스만을 지향하지 않는다. 지금 나온 항공권을
둘러보다 여행을 발견하게 하는 서비스다. 다만 이 철학을 모든 화면과 문구에서 반복해서 설명하지
않는다. 메인에서는 실제 항공권이 많고, 비교하기 쉽고, 정보가 믿을 만하다는 인상이 먼저 와야 한다.

서비스 안내 페이지의 현재 확정 문구는 `docs/website-confirmed-copy.md`에 있다.

## 현재 운영 화면

- 운영 `/`는 `RedesignDashboard`를 사용한다.
- `/preview/mobile-redesign`은 실험 확인 경로이며 운영 메인으로 오해하지 않는다.
- 모바일과 PC는 같은 정보 구조를 공유하지만 상세 표시 방식과 레이아웃은 다르다.
- PC 항공권 상세는 오른쪽 비모달 패널이다. 목록을 계속 볼 수 있고 빈 영역을 누르면 닫힌다.
- 모바일 항공권 상세는 음영이 있는 바텀시트다.
- 패널·필터·버튼의 글자와 색상은 `docs/ui-design-system.md`를 기준으로 실제 화면에서 다시 검증한다.

## 추천순의 현재 구현

추천순은 단순 최저가순이나 무작위 배열이 아니다. 2026-09-04 코드 기준으로 다음 근거를 함께 본다.

1. 같은 날짜의 네이버 비교가
2. 인접 날짜의 네이버 가격 표본
3. 인터파크의 출발 권역·도착 도시·월별 최저가
4. 같은 노선의 최근 가격 기록
5. 실제 결제 가격과 가격 확인 신선도

주요 진열 규칙은 다음과 같다.

- 같은 출발권역·목적지에서는 실질 결제가가 더 싼 항공권을 먼저 둔다.
- TIKIT DROP은 첫 카드에 고정하고, 정확히 같은 항공권은 일반 목록에서 중복 제거한다.
- TIKIT DROP과 같은 목적지는 첫 9개에서 다시 노출하지 않고 그 뒤에 합친다.
- 첫 9개에는 인천·김포 출발 6개를 목표로 한다.
- 첫 9개 중 25만원 이하 항공권을 최소 6개 확보하려 한다.
- 30만~40만원, 40만~50만원, 50만원 이상 항공권은 가격 근거와 구간별 상한을 적용한다.
- 40만원 이상은 가격 근거가 충분할 때만 첫 화면에 드물게 허용한다.
- 같은 목적지의 반복과 A-B-A-B 반복을 줄이고, 비슷한 품질이면 아직 나오지 않은 목적지를 우선한다.
- 같은 품질·가격 구간에서는 새로 발견된 항공권을 앞세운다.

정확한 수치와 예외는 `src/lib/flight-recommendation.ts`, `src/lib/flight-diversity.ts`와 테스트가
최종 근거다. 과거 대화의 Top 9 조건을 코드보다 우선해서 적용하지 않는다.

## TIKIT DROP과 오늘의 항공권

- 현재 메인에서는 그날 유효한 TIKIT DROP 한 장을 첫 카드로 고정한다.
- 오늘의 TIKIT DROP은 Windows 네이버 비교가 운영에 반영된 뒤 하루 한 번 선정한다.
- 같은 목적지가 최근 7일에 선정됐더라도 그 기간의 최저 선정가보다 더 싸졌다면 다시 선정할 수 있다.
- 선정된 항공권이 사라지면 그날은 노출을 중단하며 다른 항공권으로 임의 복구하지 않는다.
- 일반 항공권 카드와 공식 TIKIT DROP 발행·기록은 같은 개념이 아니다.
- 웹사이트 카드의 문구는 `docs/tikit-drop-copy-library.md`의 위치·입증·재사용 조건을 지킨다.

### DROP 히어로 (2026-09-04 결정, 미리보기 승인 전 운영 반영 금지)

배경: 첫 화면이 카드 나열뿐이라 새 지역·가격이 상단에 없으면 바로 이탈한다는 사용자 판단.
현재 TIKIT DROP은 일반 카드에 띠 하나 붙은 모양이라 '오늘의 사건'으로 보이지 않는다.

- 카드 목록 위에 화면 폭 히어로 카드 1장. 도시 사진 배경(`이번 주 낯선 도시` 이미지 방식 재사용) + 작은 눈썹 `TIKIT DROP · M/D`.
- 큰 한 줄: 기존 `describeDropCard`가 만드는 근거 문장을 그대로 쓴다. 새 문구를 만들지 않는다.
- 작은 줄: 출발지·날짜·항공사·판매처. 버튼 하나(항공권 상세 열기).
- 최근 DROP 목록·칩은 넣지 않는다 (사용자 결정).
- 오늘 선정이 없거나 판매 종료된 날은 히어로를 아예 표시하지 않는다. 대체 항공권·최근 DROP으로 채우지 않는다.
- 히어로가 있을 때 첫 카드의 기존 DROP 띠는 중복이므로 제거하거나 목록에서 뺀다 (기존 중복 제거 규칙과 맞춘다).
- `이번 주 낯선 도시` 카드는 지금 자리 그대로 둔다.
- 순서: `/preview/drop-hero`(또는 Vercel 프리뷰 URL)로 먼저 보여주고 사용자가 승인한 뒤에만 운영 `/`에 반영한다.

## 인사이트 영역

최근 제품 UI 대화에서 확인된 운영·실험 항목은 다음과 같다.

- `오늘 새로 뜬 항공권`: 여러 일정이 있으면 일정 목록을 먼저 보여주고 선택한 뒤 상세로 들어간다.
- PC에서는 항공권 두 장, 모바일에서는 한 장을 보여주는 전환형 구성이 구현 논의의 최신 축이다.
- `이번 주 낯선 도시`: 한 주에 한 도시를 깊게 소개하는 발견 콘텐츠다.
- `주말이 아까운 사람에게`: 토·일이 일정에 들어간 항공권만 고르는 설명형 콘텐츠다.
- 상단 롤링 경보 띠와 과한 가격 붕괴 문구는 메인 결에 맞지 않아 제거했다.

이 항목들은 화면이 여러 번 수정됐으므로 디자인을 다시 손댈 때는 현재 운영 화면을 먼저 본다.
과거 스크린샷이나 보관 브랜치를 그대로 복원하지 않는다.

## 검색·필터·상세의 현재 원칙

- 검색은 목적지명과 항공사명이 우연히 겹쳐 엉뚱한 도시가 섞이지 않도록 필드별 의미를 구분한다.
- 필터 순서는 출발지 → 도착지 → 일정 → 가격을 기본으로 한다.
- 모바일 상세 조건은 바텀시트, PC 상세 조건은 상단 필터에서 여는 레이어다.
- 같은 역할의 오버레이는 공통 닫기·키보드·뒤로가기 동작을 공유한다.
- 포인터 클릭에는 브라우저 포커스 외곽선을 보이지 않고, 키보드 `Tab` 탐색의 `:focus-visible`에만 보인다.
- 공유는 OS 공유창만 강제로 띄우지 않는다. PC에서는 링크 복사 피드백을 눈에 띄게 보여준다.
- 모바일 상세 하단 CTA는 `공유`처럼 짧은 문구를 사용해 예약 확인 버튼 공간을 보존한다.

## 계정·저장·알림

- 찜과 내 여행은 계정과 연결하는 방향이다.
- 공개 특가 알림 진입점은 현재 코드에서 `PUBLIC_DEAL_ALERTS_ENABLED = false`로 가려져 있다.
- 이유는 계정별 발송 이력, 기기 복구, 어떤 알림을 받았는지 확인하는 경험이 완성되지 않았기 때문이다.
- 기존 알림 코드와 데이터가 있다는 이유로 공개 진입점을 다시 켜지 않는다.
- 다시 활성화하려면 등록 → 관리자 검수 → 본인 시험 발송 → 실제 수신 → 계정 내 발송 이력 확인을 한 흐름으로 검증한다.

## 어드민 제품 원칙

- 여행사별 수집 상태 막대는 회차 축을 공유하며 진행 중 회차 자리를 미리 표시한다.

- 운영자가 혼자 보므로 설명용 홍보 문장과 페이지 내 바로가기 목차를 과하게 넣지 않는다.
- 오늘·7일·30일의 방문 → 상세 열람 → 예약 페이지 이동을 한눈에 비교할 수 있어야 한다.
- 수집 상태는 현재 성공 여부와 실패 흐름이 먼저 보여야 하고, 여행사별 성공률 숫자를 크게 강조하지 않는다.
- `정상` 상태 색상은 여행사 브랜드색이 아니라 하나의 정상 색으로 통일한다.
- 원본 수집, 필터 후 노출, 추가·제거와 보존을 구분해서 표시한다.
- `수집 실행 상태`, 단순히 현재 가격이 낮은 항공권처럼 운영 판단에 도움이 적은 영역은 제거한 방향을 유지한다.

## UI를 바꿀 때 특히 피할 것

- 모바일에서 괜찮은 밀도를 PC에도 그대로 늘려 적용하기
- 모든 강조 요소에 브랜드 핑크를 반복하기
- 글로우, 불필요한 그라데이션, 선을 겹쳐 두껍게 만들기
- 일반 정보와 가격의 시각적 위계를 같게 만들기
- 카드, 인사이트, 필터, 상세창마다 서로 다른 오버레이 규칙을 만들기
- 이전 시안을 사용자가 승인한 최종안으로 간주하기

## 확인이 필요한 제품 항목

- 추천순 설명과 실제 50위 결과가 운영 데이터에서도 의도대로 나오는지 정기 표본 확인
- TIKIT DROP의 별도 생애주기와 영구 상세를 실제 제품으로 만들 범위
- 알림 기능 재공개 조건
- 인사이트바의 최종 콘텐츠 구성과 측정 기준
- 보관된 낯선 도시 모바일 시안의 재사용 여부
