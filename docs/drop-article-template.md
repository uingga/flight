# TIKITIKIT DROP 원고 템플릿

> **상태: 2026-08-26 사용 보류.** DROP을 새로 설계하기로 했으므로, 사용자가 다시 사용하라고 명시하기 전까지 새 DROP 원고에 복사하거나 참고하지 않는다. 내용은 이전 원고 형식 기록으로 보존한다.

네이버 블로그용 DROP 원고를 만들 때 복사해 쓰는 기준 문서다. 빈칸을 기계적으로 채우는 양식이 아니라,
항공권별로 무엇이 눈에 띄는지 판단하고도 글의 기본 품질과 배치를 놓치지 않기 위한 뼈대다.

## 0. 회차와 측정값

```text
공개 회차: DROP [01]
발행 예정일: [M/D]
UTM 캠페인: tikitikit_drop_[공개 회차 3자리, 예: 001]
소개할 항공권: [2~3개]
```

- **회차는 실제로 발행한 글만 센다.** 폐기한 초안과 내부 시안은 회차를 차지하지 않는다.
- 제목·대표 이미지·본문·UTM 캠페인·사이트 DROP 페이지의 회차가 모두 같은지 확인한다.
- 소개할 만한 표가 두 장뿐이면 세 장을 억지로 채우지 않는다.

## 1. 쓰기 전 사실 카드

각 항공권마다 먼저 아래 사실을 채운다. 이 단계에서는 멋있게 쓰지 않는다.

```text
[항공권 A]
- ID / 공유 URL:
- 출발지 ↔ 목적지:
- 항공사 / 여행사:
- 출발일·귀국일 / 몇 박 며칠:
- 출국편 출발·도착 시각:
- 귀국편 출발·도착 시각:
- 표시 가격 / 실제 결제 예상가:
- 발권수수료·수하물 등 확인할 비용:
- 네이버 비교가와 확인 시각(내부 판단용, 글에는 네이버를 쓰지 않음):
- 최근 노선 가격대(자료가 있을 때만):
- 일정에서 실제로 좋은 점:
- 숨기면 안 되는 불편:
- 목적지가 생소하다면 이해를 돕는 사실 한 가지:
- 공식 자료로 다시 확인해야 하는 주장:
- 이 표를 소개하는 가장 강한 이유 한 문장:
```

검증되지 않은 해석을 사실 카드에 섞지 않는다. 공식 운항 일정, 실제 가격, 수수료, 체류 시간부터 확인한 뒤
그 사실이 독자에게 어떤 의미인지 쓴다.

## 2. 제목

기본형:

```text
[M/D] [핵심 목적지] [가격대], [두 번째 목적지 또는 출발지 특징] [가격대] | TIKITIKIT DROP [공개 회차]
```

예시 구조:

```text
[8/19] 칭다오 17만원대, 부산발 괌 21만원대 | TIKITIKIT DROP 01
```

- 세 항공권을 모두 요약하지 않는다. 글을 열 이유가 되는 두 가지 정보만 남긴다.
- 가격은 `172,300원`보다 `17만원대`처럼 짧게 쓸 수 있다.
- `가볼 만할까?`, `어떤 곳일까?`, `실제로 가능할까?`처럼 흔한 AI형 질문 제목은 피한다.
- 제목의 회차와 대표 이미지의 회차를 발행 직전에 나란히 확인한다.

## 3. 대표 이미지

```text
[정사각형 대표 썸네일 1장]
```

- 1:1 비율 한 장만 사용한다.
- 발행일을 크게 표시한다.
- 이번 글의 중심 항공권 한 장만 티켓 모티프로 보여준다.
- `TIKITIKIT DROP [공개 회차]`를 제목과 동일하게 쓴다.
- 티키티킷 항공권 카드 캡처는 본문에 다시 넣지 않는다. 네이버 링크 카드와 정보가 겹친다.

## 4. 도입부

2~3문장으로 쓴다.

```text
[독자가 한 번쯤 겪어봤을 상황이나 이번 표들을 함께 볼 이유]

[이번 드롭에서 서로 다른 점 또는 계속 읽으면 알게 될 점]

[필요할 때만 한 문장 추가]
```

도입부에서 하지 않는 것:

- 세 도시와 가격을 다시 나열하기
- `세 장을 골랐습니다`처럼 제작 과정을 설명하기
- 뒤에서 할 이야기를 전부 요약하기
- 추상적인 브랜드 철학부터 설명하기

## 5. 목적지 꼭지

항공권 수만큼 반복하되, 본문 문장 구조까지 똑같이 반복하지 않는다.

```text


## [이 표의 매력이 바로 이해되는 소제목]

[목적지 사진 — 최대 4:5, 가운데 정렬]
[사진: 작가명 (Unsplash)]

**[출발지] ↔ [목적지]**
[항공사] · [M/D~M/D] · [N박 N일]
**왕복 [실제 결제 예상가]원**

[첫 문단: 출발·도착 시각과 현지에서 실제로 쓸 수 있는 시간을 자연스럽게 설명]

[둘째 문단: 이 표의 가장 큰 장점, 불편, 목적지 정보 중 필요한 내용을 연결]

[선택 문단: 독자가 판단하는 데 꼭 필요한 정보가 더 있을 때만 추가]

[네이버 링크 카드가 될 티키티킷 공유 URL]
위의 티켓을 누르면 항공권 페이지로 이동합니다.
```

### 소제목 판단

소제목은 시간표를 문장으로 옮기는 곳이 아니다. 도시·가격·출발지 중 필요한 정보와 이 일정이 주는 이득을 함께 보여준다.

```text
나쁨: 대구에서 목요일 밤에 떠나는 타이베이
좋음: 주말을 하루 일찍 시작하는 대구발 타이베이
```

단, 이득을 만들려고 사실을 비틀지 않는다. `첫날부터 쓴다`, `부드럽게 복귀한다`처럼 무엇을 뜻하는지 모호한 표현도 피한다.

### 본문 판단

- 출발·귀국 시각을 나열하고 끝내지 말고, 그 시간 때문에 가능한 일정이나 감수할 불편을 설명한다.
- 독자가 출발지 근처에 산다는 당연한 사실은 설명하지 않는다.
- 관광지 두 곳을 언급하려고 `둘러볼 수 있는 시간은 사흘`처럼 어색한 의미를 만들지 않는다.
- 목적지 정보는 항공권 선택을 이해하는 데 도움 될 때만 쓴다. 여행 가이드가 글의 주인공이 되지 않게 한다.
- 한 꼭지에서 끝낸 주제로 설명 없이 되돌아가지 않는다.
- 장점만 말하지 않는다. 이른 귀국, 밤 비행, 긴 공항 대기, 추가 비용처럼 판단에 필요한 불편을 숨기지 않는다.
- 표마다 분량이 완전히 같을 필요는 없다. 할 말이 적은 표를 억지로 늘리지 않는다.

## 6. 마무리와 특가 알림

아래 구조를 기본으로 사용한다.

```text


## 이번엔 떠날 만한 표가 없었나요?

다음 드롭은 예고 없이 옵니다.

출발지·지역·예산을 골라두세요.
조건에 맞는 표가 나와도 모두 알리지 않고, 가격과 일정이 좋은 표만 보내드립니다.
드롭에 실리지 않은 표도요.

[티키티킷에서 특가 알림 설정하기 →](https://www.tikitikit.kr/?dealAlert=1&utm_source=naver_blog&utm_medium=content&utm_campaign=tikitikit_drop_[공개회차3자리]&utm_content=alert_cta)
tikitikit.kr의 알림 설정 화면으로 이동합니다.
```

- CTA는 가운데 정렬하고 굵게 표시한다.
- 이동 안내는 CTA 바로 아래에 13px 정도의 옅은 글씨로 둔다. 안내 문구에는 링크를 걸지 않는다.
- 링크는 알림 목록이 아니라 `dealAlert=1`로 알림 설정 화면을 바로 연다.

## 7. 고지

```text
※ 가격과 좌석은 [YYYY년 M월 D일] 확인 시점 기준이며 판매처에서 달라질 수 있습니다. 결제 전 최종 금액, 수하물, 환불 규정을 확인하세요.
```

## 8. 이미지·여백 배치

- 모든 이미지와 링크 카드는 가운데 정렬한다.
- 대표 이미지 다음에 도입부를 둔다.
- 일반 문단과 문단 사이에는 빈 문단 하나를 둔다.
- 각 목적지 소제목 위에는 빈 문단 두 개를 둔다.
- 각 목적지 소제목과 바로 다음 목적지 사진 사이에는 빈 문단을 두지 않는다.
- 링크 카드와 `위의 티켓을…` 안내 문구 사이는 띄우지 않는다.
- `위의 티켓을…` 다음에는 빈 문단을 두고 다음 꼭지와 구분한다.
- 사진 출처는 사진 바로 아래에 둔다.
- 세로 사진은 최대 4:5로 크롭하되 사람·건물·해변 등 주요 피사체가 잘리지 않는지 눈으로 확인한다.

## 9. 발행 전 문장 검수

다음 질문에 하나라도 `아니오`면 고친 뒤 네이버 에디터로 옮긴다.

- [ ] 공개 회차가 실제 발행 순서와 맞는가
- [ ] 제목·대표 이미지·UTM의 회차가 같은가
- [ ] 제목이 글 내용을 다 소비하지 않으면서도 눌러볼 이유를 주는가
- [ ] 도입부가 세 표를 다시 나열하지 않는가
- [ ] 각 소제목이 단순한 사실 나열보다 이 표의 매력을 보여주는가
- [ ] 각 목적지 소제목 바로 아래에 빈 줄 없이 목적지 사진이 붙어 있는가
- [ ] 모든 가격·날짜·시각·수수료를 다시 확인했는가
- [ ] 사실과 해석이 구분되어 있는가
- [ ] 서로 상관없는 두 사실을 `대신`, `그래서`, `하지만`으로 억지 연결하지 않았는가
- [ ] 같은 뜻과 문장 구조를 세 꼭지에서 반복하지 않는가
- [ ] 불편한 조건도 독자가 예약 전에 알 수 있게 썼는가
- [ ] 생소한 목적지 정보가 항공권보다 더 길고 중요해지지 않았는가
- [ ] 읽지 않아도 되는 문장을 덜어냈는가

## 10. 네이버 입력 전 승인 원칙

1. 후보 선정과 사실 검증
2. Markdown 원고 작성
3. 로컬 HTML 미리보기와 이미지 배치
4. 사용자 문장 승인
5. 사용자 승인 후에만 네이버 임시저장 입력
6. 사용자가 직접 발행

사용자가 승인하기 전에는 네이버 에디터의 기존 글과 임시저장 글을 수정하지 않는다.
