# 모두투어 전용 Chrome 주 수집기

2026-09-07 사용자 승인으로 B PC 전용 Chrome을 주 수집으로 전환한다. GitHub 정규 모두투어 API 수집은 중복 방지를 위해 생략한다.

## 운영 연결

- A의 기존 `TikitikitBlockedSourceCrawl`이 08:17·11:12·14:23·17:31 KST에 해당 GitHub 회차 완료를 기다려 B에 전달한다.
- `modetour-remote-worker.ts`는 회차당 삭제하지 않는 표식과 온라인투어 공용 잠금을 사용한다. A에서도 PC 소스는 직렬 실행한다.
- 내일부터 한 달, 15구간 목록 GET 최대 15회, 자동 재시도 없음. 새 전용 프로필을 만들지 않는다.
- 사용자도 직접 확인한 타오위안(TPE)의 HTTP 500만 목적지 단위 부분 실패로 처리한다. 기존 TPE 항공권 객체를 그대로 보존하고 나머지 14구간을 반영한다. 다른 구간 오류나 접근 차단은 전체 새 결과를 반영하지 않는다.
- A는 B가 보낸 원본으로 항공권을 다시 산출해 대조한다. 원본 구간별 60% 급감, 누락, 가격 변조, 기간 불일치를 거부한다. 기존 최저가·만료·편도·인터파크 캐시 필터를 그대로 적용한다.
- `modetourPrimary`에 회차 시각·부분 성공·구간별 정상 원본 수·보존 이유를 저장한다. 어드민에는 PC 주 수집과 부분 성공을 표시한다.
- A/B PC와 B의 로그인된 전용 Chrome이 실행되어 있어야 한다. 연결 실패 시 기존 데이터 보존, 같은 회차 반복 실행이나 자동 GitHub 전환은 하지 않는다.
- 아래 `--stage` 명령은 운영 쓰기가 없는 진단 전용이며, 정규 운영은 `--scheduled` 원격 워커만 사용한다.

## 수집 방식

- 사용자가 로그인해 둔 기존 `~/tmp/chrome-debug` Chrome, loopback 9222에만 연결한다.
  온라인투어의 프로세스·프로필 검증기를 재사용한다. Chrome을 새로 실행하거나 프로필,
  쿠키, 계정 정보를 복사/읽지 않는다. 작업이 만든 탭만 닫고 연결을 해제한다.
- 웹사이트의 공개 검색 링크로 이동하고 **그 화면이 직접 요청한 GetList 응답**을 읽는다.
  Node에서 API를 재호출하거나 인증 헤더를 추출·재전송하지 않는다.
- 사용자 최종 지시대로 KST 내일부터 한 달까지 화면 기본 기간으로 검색한다. 중국은 기존에 확인한 10개 도시 각각,
  나머지 동남아·일본·남태평양·유럽·미주 5개 지역: 총 15개 구간이다.
  지역별 최대 한 번, 전체 목록 GET 최대 15회이며 3~5초 간격으로 직렬 실행한다.
  이는 목록 요청 수이며 HTML·이미지 등 모든 HTTP 요청 수가 15라는 뜻은 아니다.
- 검색 파라미터가 실제 요청에 적용되지 않거나 반복 GET이 발생하면 전송 전에 중단한다.
  2026-09-07 현장 확인에서 지역/도시와 500건 상한은 적용되며 날짜는 페이지 기본값을 사용하는 것을 확인했다.
- 세금 포함 요금, 출발/귀국 일정, 실제 공항 코드와 출발 시간을 검증한다. 귀국 직항 여부가
  없으면 가는편으로 추정하지 않는다. 품절/편도/기간 밖은 제외 수로 기록한다.
- 한 페이지 상한에 도달하거나 반환 개수와 전체 개수가 다르면 추가 조회를 임의로 늘리지 않고
  `pagination_requires_review`로 멈춘다. 15회는 최초 범위의 상한이지 전체 목록 완료 보장이 아니다.

## 안전 및 출력

- 명시적 차단, 기존 구간의 60% 미만 급감, 전체 0건이면 24시간 중단 기록을 남긴다.
  활성 GitHub/PC 회로를 무시하거나 닫지 않는다. 당일 실행 표식은 실패해도 유지한다.
  단, 페이지 생성 전 Chrome 소유자/연결 탐색만 실패한 증거가 있으면 1회만 연결을 재개할 수 있다.
  최초 표식과 실패 기록은 보존하며 별도 재개 표식을 생성한다. 사이트 요청 이후 실패에는 적용하지 않는다.
- 온라인투어와 동일한 호스트 잠금을 사용한다. A 공통 실행기는 땡처리를 포함한 PC 소스를 직렬 실행한다.
- `.local-crawler/modetour/<runId>`에 공개 목록과 후보만 저장한다. 중간 실패도 이미 읽은 구간을
  보존하되 성공으로 표시하지 않는다. 운영 캐시·네이버 결과·오늘의 표·스케줄에는 쓰지 않는다.
- 사용자가 이어서 실행하도록 지시한 HTTP 500 중단은 `--continue-unqueried <runId>`로 한 번만
  이어갈 수 있다. 동일 기간/계획, 앞선 순차 GET/응답 기록, 체크포인트를 검증한다. 이미 성공한
  구간은 로컬 재사용하고 실패한 구간도 재요청하지 않는다. 기존 요청 수를 차감한 잔여 상한만
  브라우저에 부여한다. 타오위안의 HTTP 500만 별도 실패로 남기고 다음으로 가되, 차단 문구와
  401/403/429·구조 오류·급감은 즉시 중단한다. 실패 구간이 남으면 `status=incomplete`로 저장한다.
- staging의 `productionReady=false`는 원본 자체가 곧 운영 캐시가 아니라는 뜻이다. 별도 운영 검증기가
  구간 완전성·원본 가격·날짜·세금·링크를 재계산해 통과시킨 뒤 기존 필터와 어드민/운영 병합으로 연결한다.
