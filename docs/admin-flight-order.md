## 사용 방법

어드민의 **노출 순서** 탭에서 **노출 순서 관리** 패널을 연다.
네이버 비교 링크 위에는 같은 일정으로 저장된 `naverLowest`를 표시한다. 가격의 툴팁에는 확인 시각을 표시하며, 값이 없으면 **가격 미확인**과 비교 링크를 보여준다.
같은 화면에서 다른 어드민 탭에 다녀와도 편집 중인 순서는 유지한다. 새로고침하면 마지막으로 적용한 순서를 다시 읽는다.
PC에서는 카드의 점 손잡이 쪽을 끌어 원하는 카드 위치에 놓는다.
모바일과 키보드에서는 **맨 위로 / 위로 / 아래로**를 사용한다.
검색은 편집할 카드를 찾는 용도이며, 표시 번호는 전체 일반 목록에서의 위치다.

편집 중에는 저장하지 않는다. **미리보기 → 적용**으로 저장한다.
**자동 배치**는 해당 카드만 수동 배치에서 해제한다.
**자동 추천순으로 복원**도 자동순 미리보기를 먼저 보여주며 **적용**해야 저장된다.
저장 실패나 다른 탭과의 충돌은 오류로 알리고 초안은 남긴다.
**편집 취소·새로고침**은 초안을 버리고 최신 목록과 저장된 설정을 다시 읽는다.

## 정렬 규칙

1. 기존 노출 필터와 중복 제거를 먼저 적용한다. 종료·만료·신고 숨김·오래된 가격·네이버 비교 제외 등 기존 판단을 바꾸지 않는다.
2. 기존 추천 점수·목적지 다양화 결과를 자동순으로 사용한다.
3. 현재 기본 화면의 TIKIT DROP은 맨 앞을 유지한다. 직접 배치 번호는 DROP을 제외한 일반 목록에서 1부터 센다.
4. 직접 옮긴 최대 30장만 지정 위치에 넣고 나머지 항공권은 기존 자동순의 상대 순서를 유지한다. 수동 배치가 목적지 다양화보다 우선하지만 DROP의 맨 앞 자리는 바꾸지 않는다.
5. 현재 필터에 없는 표는 추가하지 않는다. 지정 위치보다 검색 결과가 적으면 가능한 마지막 위치로 당긴다. 남은 자리는 자동순이 채운다.
6. 추천순에만 적용한다. 가격순·출발일순·명시적으로 공유한 항공권 목록은 기존 정렬을 유지한다.
7. 전체 표시 목록을 결정한 **뒤에** 기존 `visibleCount`로 자른다. 더 보기마다 재배치하지 않아 페이지 중복/누락이 없다. 현재 API는 페이지로 나누지 않고 전체 적격 항공권을 제공하므로 새 서버 페이지네이션을 도입하지 않았다.

수동 지정 상품이 잠시 목록에서 빠져도 저장 설정은 삭제하지 않는다.
크롤링 실패로 보존된 캐시를 새 판매 종료로 판정하지 않는다.
나중에 같은 상품·일정이 다시 정상 노출 대상이 되면 기존 위치를 재사용한다.
같은 키에 여러 후보가 남아 있는 애매한 경우에는 이동하지 않는다.

## 상품 식별과 최신값

`scripts/lib/flight-lifecycle.ts`의 기존 `buildLifecycleIdentity()`를 서버에서 재사용한다.
`v1:<offerKey>:<itineraryKey>`를 `manualOrderKey`로 내려준다.
노랑풍선·하나투어의 가격 의존 해시 ID, 마이리얼트립의 가격 접미사 ID를 그대로 고정하지 않는다.
일정 키도 포함해 같은 상품 번호가 다른 날짜에 재사용될 때 설정이 잘못 붙지 않게 한다.
크롤러의 식별자 생성 로직은 변경하지 않는다.

시간·편명 등 기존 식별 근거 자체가 달라져 새 키가 만들어지면 자동순으로 남긴다.
추측으로 다른 일정에 재연결하지 않는다.

저장 항목은 `{ key, position }`뿐이다. 가격, 좌석, 링크, 항공권 객체를 저장하지 않는다.
표시할 때 항상 현재 적격 항공권 객체를 사용한다.

## 저장과 인증

- 운영: 전용 Supabase `flight_display_order` 테이블의 `main` 한 행.
- 정수 `revision`을 사용하는 RPC compare-and-swap으로 동시 편집 덮어쓰기를 막는다.
- 브라우저 DB 역할의 권한은 없고 서버 service role만 읽기/갱신한다.
- 관리자 GET/PUT 모두 서버에서 기존 `ADMIN_KEY`를 확인한다. PUT은 Origin도 확인한다.
- 응답은 no-store다. 공개 항공권 API에는 식별 키와 배치 설정만 포함하며 관리자 키는 없다.
- 저장소 장애 시 공개 목록은 자동순으로 폴백한다. 저장된 설정을 삭제하지 않으며 관리자 저장은 실패로 알린다.
- 기본값은 비활성이다. 준비가 끝난 뒤에만 `FLIGHT_ORDER_ENABLED=1`을 설정한다.
